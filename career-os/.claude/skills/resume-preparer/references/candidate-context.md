# 이력서 작성 중 개인 맥락 조회

이 파일은 `resume-preparer`가 이력서 작성 중 필요한 개인 맥락을 언제 조회하고, 새로 확인한 내용을 어디로 보낼지 정한다.
개인 작성 취향은 [resume-taste.md](resume-taste.md)가 관리하고, 이 파일은 현재 경력, 역할 선호와 경험 경계처럼 실행 시점에 확인할 사실을 다룬다.

## 조회 시점

지원 작업본을 준비한 뒤 대표 사례 사실 확인 단계에서 후보자 맥락 문서를 조회한다.

```bash
bun career-os/scripts/candidate-context/manage_candidate_context.ts get --key career-status
```

조회 대상은 현재 경력, 역할 선호, 경험 경계와 제출 문장의 사실 범위를 판단하는 데 필요한 개인 맥락이다.
회사 지식, 사내 시스템 지식과 Dooray 업무 지식은 후보자 맥락 문서가 아니라 `nbrain` 대상이므로 이 흐름에서 조회하지 않는다.

원고 작성 중 추가 사실이 필요하거나 사용자 정정이 생기면 관련 질문만 다시 조회한다.
같은 편집 흐름에서 이미 확인한 정보는 재사용한다.
제출 문장을 바꾸는 불확실성이 없으면 조회를 반복하지 않는다.

## 조회 결과 적용

조회 결과에는 출처로 문서 키와 version 을 붙인다.
출처의 시점과 현재 사용자 확인이 충돌하면 현재 문구는 최신 사용자 확인에 맞춰 수정하고, 차이는 작업 기록이나 확인 항목에 남긴다.
문서 본문의 개인 내용을 공개 문맥에 그대로 옮기지 않는다.

제출 문장은 확인된 주어, 업무 대상, 수행한 행동, 본인 역할과 결과의 범위 안에서 작성한다.
결과는 현재 근거로 확인된 변화나 검증 범위에 맞춘다.
현재 사용자가 역할 범위를 정정하면 그 정정을 현재 문구에 반영하고, 다른 지원에서도 재사용할 개인 사실 후보로 구분한다.

조회 결과가 없으면 후보자 맥락 문서에서 찾지 못한 사실임을 밝히고 현재 대화와 후보자 확인으로 보완한다.
Backend 연결이 실패하면 실패 사실을 밝히고 현재 확인된 근거 범위에서 편집을 계속한다.
사실을 확정할 근거가 부족한 제출 문장만 후보자 확인 대상으로 남긴다.

## 환원 분기

사용자와 새로 합의한 내용은 성격에 따라 나눈다.

| 성격 | 관리 위치 |
| --- | --- |
| 개인 작성 취향 | [resume-taste.md](resume-taste.md) |
| 재사용할 개인 사실이나 결정 | 후보자 맥락 문서의 변경 전후 미리보기와 승인 뒤 `put` |
| 지원별 표현과 수치 | 작업 중인 지원 건의 `candidate-interview.md` |

작성 취향 합의는 원고 표현 기준에만 적용한다.
재사용할 개인 사실이나 결정은 변경 전후를 미리 보여 주고 사용자 승인을 받은 뒤에만 `put` 으로 저장한다.
저장할 때는 조회한 version 을 `--expected-version` 으로 넘기고, `--note` 에 날짜와 내용을 남긴다.
`resume-preparer`는 저장을 자동 승인하지 않는다.
