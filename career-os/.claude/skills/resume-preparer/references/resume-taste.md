# 이력서 작성 취향

이 파일은 회사에 관계없이 재사용하는 개인 이력서 취향을 관리한다.
공고의 공식 작성 안내와 회사별 기준이 있으면 먼저 따르고, 이 파일은 그 범위 안에서 경력과 일하는 방식을 어떻게 보여줄지 정한다.
일반 표현 검증은 [resume-writing-style.md](resume-writing-style.md)를, HTML과 PDF 배치 검증은 [resume-design.md](resume-design.md)를 함께 적용한다.

## 목표

이력서는 경력과 일하는 방식을 지원 직무에서 만들 수 있는 기여로 연결한다.
목표는 제출 문서가 다음 전형으로 넘어갈 이유를 빠르게 보여 주어 서류 합격 가능성을 최대한 높이는 것이다.

첫 화면에서는 현재 역할, 다루는 문제와 지원 직무에 연결되는 대표 근거가 보여야 한다.
뒤쪽에서는 경력 흐름, 프로젝트, 기술 범위와 검증 가능한 결과를 확인할 수 있어야 한다.

## 표현

프로필은 현재 소속과 역할, 업무의 대상과 목적, 관심을 보여주는 실제 행동을 짧게 연결해 쓴다.
소개에서 연차를 말할 때는 실제 재직 기간으로 계산하고 `N년 차`로 표현한다.
회사명, 기간과 기술 목록은 이 파일에 예시 값으로 고정하지 않는다.

개발과 유지보수는 실제 역할에 맞춰 쓴다.
수식어는 실제 동작의 주체를 가리켜야 하며, 팀이 만든 결과와 본인이 맡은 작업을 구분한다.
같은 내용은 가장 적절한 위치에서 한 번 설명하고 다른 섹션에서는 반복하지 않는다.

도구와 프로젝트는 목적을 담은 제목으로 시작한다.
프로젝트 제목은 전체 담당 범위를 간결하게 보여주고, 개별 개선 사례는 본문에 둔다.
그 아래에는 소속 팀, 실제 참여 기간, 핵심 행동과 결과를 짧은 항목으로 둔다.
수치를 쓰면 집계 기간과 확인 시점을 함께 표시한다.
전후 비교는 [resume-writing-style.md](resume-writing-style.md)의 측정 대상과 조건 기준을 따른다.

기술 목록은 사용 범위와 판단을 설명할 수 있는 항목으로 선별한다.
테스트 경험은 독립된 기술 나열보다 관련 프로젝트에서 어떤 검증을 했는지로 설명한다.

## 정보 구조

연락처는 이름과 값을 함께 표시한다.
회사명과 팀 재직 기간 아래에는 해당 회사에서 수행한 프로젝트를 제목 계층으로 묶는다.
각 프로젝트에는 소속 팀과 실제 참여 기간을 연결하고, 팀 재직 기간과 프로젝트 참여 기간은 구분한다.
학력과 자격증은 독립 섹션으로 둔다.

학력은 재학 기간과 평점을 한 줄로 묶고, 전공과 부전공을 별도 한 줄로 묶는다.
회사와 학교는 실제 로고를 사용한다.
로고를 사용할 근거가 불명확하면 텍스트 표기로 대체하고 확인 대상으로 남긴다.

공식 브랜드 강조색은 지원별로 선택한다.
색상값은 이 파일에 고정하지 않고, 제목, 아이콘과 구분선에 제한해 적용한다.
분량과 페이지 수는 제출처 제한, 근거의 양, 중복과 읽기 편의성으로 정한다.

## 함께 수정하는 방식

사용자와 합의한 문구는 Markdown 원고에 먼저 반영한다.
사용자가 PDF 갱신을 요청하면 렌더링을 다시 실행하고 실제 배치를 확인한다.
글자 겹침, 잘림, 링크, 대비와 페이지 넘침은 [resume-design.md](resume-design.md)의 검증 기준으로 확인한다.

작성 취향 합의와 개인 사실 정정의 분리는 [brain-context.md](brain-context.md)의 「환원 분기」를 따른다.
