# 이력서 작성 취향

이 파일은 회사와 관계없이 재사용하는 개인 이력서 취향을 관리한다.
공고의 공식 안내와 회사별 기준을 먼저 따르고,
사실성과 화면 품질은 [공통 작성 기준](resume-writing-style.md)과 [디자인 계약](resume-design.md)으로 검증한다.

## 목표

이력서는 경력과 일하는 방식을 지원 직무에서 만들 수 있는 기여로 연결한다.
첫 화면에는 현재 역할, 다루는 문제와 대표 근거를 배치하고,
뒤쪽에는 경력 흐름, 프로젝트, 기술 범위와 검증 가능한 결과를 배치한다.

## 프로젝트 구성

프로젝트는 문제를 만난 시점부터 판단, 조치와 결과까지 시간 순서로 쓴다.
상위 항목만 읽어도 흐름이 보이게 하고 제약과 구현 상세는 하위 항목에 둔다.

- 문제와 결과는 같은 대상을 가리킨다.
- 원인을 찾은 과정과 직접 내린 판단을 구체적으로 쓴다.
- 전체 담당 범위는 프로젝트 제목에, 개별 개선 사례는 본문에 둔다.
- 검증 가능한 결과를 프로젝트마다 하나 이상 남긴다.
- 세부 자원 조건, 기각한 대안과 남은 한계는 면접 자료로 분리한다.

프로젝트 항목은 개조식으로 끝내고 프로필과 소개는 존댓말 문장으로 쓴다.
인사담당자도 문제와 판단을 이해할 수 있도록 내부 이름과 기술 나열보다 실제 대상과 동작을 먼저 설명한다.

## 정보 선택

기술 목록은 사용 범위와 판단을 설명할 수 있는 항목으로 선별한다.
프로젝트별 기술에는 실제 사용 버전을 적을 수 있지만,
문서 끝의 요약 목록에는 이름만 적는다.

수치는 업무의 규모, 변화나 검증 결과를 설명할 때 사용한다.
집계 기간과 비교 조건을 함께 밝히고,
문제 해결과 무관한 분량이나 개수는 강조하지 않는다.

면접에서 설명할 여지는 남기되,
서류 심사자가 판단하는 데 필요한 문제, 역할과 검증 결과는 문서에 포함한다.
분량을 줄이며 제외한 사실은 해당 지원 건의 후보자 확인 기록으로 옮긴다.

## 정보 구조

- 연락처는 이름과 값을 함께 표시한다.
- 회사 재직 기간은 회사명과 같은 줄에 두고 회사별 형식을 맞춘다.
- 회사명 아래에 프로젝트를 묶고 소속 팀, 팀 재직 기간과 프로젝트 참여 기간을 구분한다.
- 학력과 자격증은 독립된 섹션으로 둔다.
- 회사와 학교 로고는 사용 근거를 확인할 수 있을 때만 사용한다.
- 공식 브랜드 강조색은 지원별로 선택하고 제목, 아이콘과 구분선에 제한해 적용한다.

## 함께 수정하는 방식

사용자와 합의한 문구는 Markdown 원고에 먼저 반영한다.
PDF를 갱신하면 실제 화면에서 배치와 페이지 구분을 확인한다.

회사와 공고에 관계없이 재사용할 표현 취향만 이 파일에 반영한다.
경력 사실과 역할 선호는 [개인 맥락 조회 기준](brain-context.md)의 환원 분기에 따라 별도로 관리한다.
