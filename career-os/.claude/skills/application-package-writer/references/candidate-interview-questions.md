# 후보자 인터뷰

지원동기와 경력 서사는 후보자가 먼저 말하고 에이전트가 구조와 근거를 보강한다.
질문을 모두 기계적으로 묻지 말고, 기존 대화와 `candidate-interview.md`에 없는 내용만 묻는다.
서로 독립적으로 답할 수 있고 같은 제출 판단을 보완하는 질문은 최대 6개까지 한 번에 묶는다.
한 답이 다음 질문을 바꾸거나 민감한 사실 하나만 확정해야 하면 한 질문만 묻는다.

## AI와 후보자의 책임

에이전트는 공고와 근거를 찾고, 경험을 구조화하며, 예상 후속 질문과 표현 경계를 준비한다.
후보자는 문서만으로 확정할 수 없는 동기, 당시 제약, 본인 판단, 기각한 대안, 책임 범위와 배운 점을 직접 확인한다.

후보자 확인이 필요한 질문에는 다음 정보를 함께 제시한다.

- 이 답이 필요한 이유
- 이미 코드와 문서에서 확인한 사실
- 답에 따라 달라지는 이력서 문장이나 지원 판단
- 답변할 때 사용할 문제, 제약, 판단, 결과의 순서
- 면접에서 이어질 가능성이 높은 후속 질문
- 확인하지 못한 내용을 과장하지 않을 경계

에이전트가 완성 답변을 먼저 쓰지 않는다.
후보자가 키워드나 생각 조각으로 답하면 원문과 정리한 핵심을 나누어 기록한다.

## 제품과 지원동기

- 이 회사와 제품에서 개인적으로 끌리는 구체적인 지점은 무엇인가?
- 이 제품의 어떤 사용자를 직접 돕고 싶은가?
- 지금보다 이 포지션에서 더 넓게 해결하고 싶은 문제는 무엇인가?

## 기여 시나리오

- 입사 후 3개월에서 6개월 안에 어떤 사용자 문제를 먼저 풀고 싶은가?
- 현재 경험으로 바로 시작할 수 있는 설계, 구현 또는 운영 영역은 무엇인가?
- 그 기여가 잘됐는지 어떤 지표나 테스트로 확인할 수 있는가?

## 근거와 역할

- 가장 가까운 실제 경험에서 문제, 제약, 본인 판단과 결과는 무엇이었는가?
- 팀 결과와 본인이 직접 책임진 부분은 각각 어디까지인가?
- 당시 검토했지만 선택하지 않은 대안은 무엇이며 왜 제외했는가?
- 결과를 무엇으로 확인했으며 확인하지 못한 범위는 무엇인가?
- 다시 한다면 어떤 결정을 다르게 내리겠는가?

## 설명 준비

제출에 사용할 대표 사례마다 다음 두 수준을 준비한다.

- 30초 설명: 해결한 문제, 본인 판단과 확인된 결과를 한 번에 말한다.
- 2분 설명: 문제의 중요성, 제약, 대안, 선택 이유, 실행, 검증과 남은 한계를 설명한다.

후보자가 먼저 말한 뒤 다음 내용을 점검한다.

- 기술 이름을 빼도 판단과 결과가 남는가?
- 팀 결과와 본인 책임을 구분했는가?
- 수치의 비교 조건과 출처를 설명할 수 있는가?
- 확인하지 못한 결과를 솔직하게 구분하는가?
- 다시 한다면 바꿀 판단을 말할 수 있는가?

설명이 막히면 이력서 문장을 강하게 다듬지 않는다.
근거를 더 확인하거나 표현을 낮추고 `interview-questions.json`에 근거 방어 질문을 남긴다.

## 기술 경험 깊이

코드와 Git 이력만으로 숙련도나 운영 경험을 확정할 수 없을 때만 묻는다.
같은 기술의 사용 범위, 운영 문제와 주력 역량 여부는 한 묶음으로 질문할 수 있다.
답변이 없거나 구체적인 사례가 없다는 답도 그대로 기록한다.

- 이 기술로 직접 개발한 기능은 무엇이며 실제 사용 기간은 어느 정도인가?
- 이 기술 때문에 발생한 장애, 성능, 배포 또는 디버깅 문제를 직접 해결한 사례가 있는가?
- 그 문제에서 후보자가 직접 판단한 원인, 선택한 조치와 결과는 무엇인가?
- 다른 프로젝트에서도 다시 적용할 수 있다고 느낀 노하우가 있는가?
- 이 기술을 본인의 주력 역량으로 소개하는 데 동의하는가?

코드 기여는 있지만 기술 고유 문제를 설명할 근거가 없으면 특정 프로젝트의 사용 경험으로만 정리한다.
후보자가 주력 역량이 아니라고 답하면 기술 목록과 첫 소개에서 제외한다.

## 공백과 학습

- 공고에서 가장 약한 경험은 무엇인가?
- 그 공백을 숨기지 않으면서 어떤 인접 경험으로 설명할 수 있는가?
- 입사 전과 입사 후에 무엇을 학습하거나 검증할 것인가?

## 회사 문화와 의사결정

회사 공식 문화 기준 중 포지션과 직접 관련된 항목만 고른다.
각 항목에 대해 실제 행동 사례를 하나씩 확인한다.

- 중요한 한 가지 문제에 집중한 사례가 있는가?
- 기존 가정을 의심하고 더 나은 기준을 만든 사례가 있는가?
- 불완전한 상황에서 빠르게 실행하고 피드백으로 개선한 사례가 있는가?
- 모르는 영역을 인정하고 주도적으로 학습한 사례가 있는가?
- 불편한 피드백을 요청하거나 받아 결과를 바꾼 사례가 있는가?

## 내부 의사결정

다음 답변은 지원 문구에 직접 쓰지 않고 지원 여부와 역질문에만 사용한다.

- 이 포지션과 회사에서 걱정되는 점은 무엇인가?
- 성장, 보상, 안정성, 제품 영향 중 포기할 수 없는 조건은 무엇인가?

## 기록 형식

`candidate-interview.md`에 질문, 후보자 원문, 에이전트가 정리한 핵심, 제출 반영 여부를 구분한다.
후보자 원문에 없던 동기나 성과를 정리된 핵심에 추가하지 않는다.
사용자의 경험 수준 정정은 기존 이력 문서보다 우선하며, 정정 전 문구를 근거로 재사용하지 않는다.
