# GPT-5.6 Guidance

OpenAI API를 사용하는 career-os 구성의 모델 선택과 마이그레이션을 다룬다.

공식 기준은 [OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model)다.

## 적용 범위

먼저 활성 OpenAI 호출, 환경 변수, 배포 설정, 프롬프트를 찾는다.

- 실제 실행 경로의 모델 기본값과 직접 연결된 프롬프트만 변경한다.
- 과거 task, ADR, 예시, fixture, 비용표, provider 비교, 저비용 fallback은 사용자가 명시하지 않으면 변경하지 않는다.
- 활성 호출이 없으면 모델 문자열이나 환경 변수를 추측해 추가하지 않는다.
  발견 결과와 필요한 대상 저장소 또는 실행 경로를 보고하고 멈춘다.

## 모델 선택

작업의 품질·비용·처리량 요구에 맞는 모델을 선택한다.

| 작업 성격 | 모델 |
|---|---|
| 복잡한 분석, 중요한 코드·문서 검토 | `gpt-5.6` 또는 `gpt-5.6-sol` |
| 일반적인 운영 작업, 품질과 비용 균형 | `gpt-5.6-terra` |
| 대량 분류, 단순 변환, 비용 민감 처리 | `gpt-5.6-luna` |

`gpt-5.6`은 `gpt-5.6-sol`을 가리키는 alias다.

reasoning, 도구 호출, 다중 턴 작업에서는 Responses API를 우선 검토한다.
기존 `reasoning.effort`가 있으면 첫 비교에서는 보존한다.
같은 대표 작업으로 한 단계 낮은 effort도 비교한다.
`max`와 `reasoning.mode: "pro"`는 어려운 품질 우선 작업에서만 측정 후 채택한다.

## 프롬프트 점검

작업 완료에 필요한 지시만 남긴다.

- 목표, 관련 맥락, 제약, 필요한 근거, 성공 기준, 출력 형식을 명확히 쓴다.
- "Be concise", "Keep it short", "Use minimal text" 같은 일반적인 축약 지시는 제거한다.
- 결과의 우선순위를 지정해야 하면 결론, 필수 근거, 중요한 주의사항, 다음 행동을 남기도록 쓴다.
- 중복된 금지·승인 문구와 과도한 예시는 제거한다.
- 도구는 현재 작업에 필요한 것만 노출하고, 설명에는 입력·출력·오류 계약만 둔다.

## 실행 절차

1. 공식 가이드에서 현재 모델 alias, 기능, 마이그레이션 주의사항을 확인한다.
2. 활성 API 호출과 모델·reasoning·프롬프트 설정을 분류한다.
3. 작업 성격에 맞는 GPT-5.6 모델을 선택한다.
4. 기존 reasoning 설정과 한 단계 낮은 설정을 대표 작업에서 비교한다.
5. 필요한 경우에만 프롬프트를 축약한다.
6. 개인 사용자 요청이면 안정적이고 개인정보를 직접 드러내지 않는 `safety_identifier`를 추가한다.
7. 아래 검증 기준을 만족할 때만 기본값을 전환한다.

## 검증 기준

동일한 대표 작업군에서 이전 설정과 후보 설정을 비교한다.

- task 성공 여부
- 최종 결과의 완결성
- 필요한 근거와 형식 충족 여부
- 총 토큰
- 지연 시간
- 비용

토큰·호출 수·응답 길이가 줄어도 사용자 결과의 품질 기준을 충족하지 못하면 개선으로 판단하지 않는다.

## 경계

Programmatic Tool Calling, persisted reasoning, explicit prompt caching, pro mode는 모델 이름 변경만으로 도입하지 않는다.
각 기능이 필요한 작업 형태와 API 처리 변경을 확인한 뒤 별도 범위로 구현한다.
외부 전송, 실제 지원, 공개 발행, 인증 정보 변경은 기존 career-os 승인 경계를 유지한다.
