# 포지션 추천을 ChatGPT 채용 브리핑과 같은 기준으로: AI·Agent 직무, 다섯 축 점수, 웹 근거 보상 비교, 매일 대시보드

확인: 2026-11-21

## 목표

position-recommender 가 사용자가 ChatGPT 예약 작업 「매일 AI·Agent 채용 브리핑」 에서 쓰는 기준과 같은 기준으로 공고를 고르고,
매일 3~5개 우선순위를 추천 이유와 보상 비교가 보이는 대시보드 표로 대화 답에 보여 준다.

지금은 두 쪽의 결과가 다르다. 2026-11-21 가족 비서 실행 1614 는 활성 113건 가운데 20건을 분석했고,
1위가 티맵모빌리티(사용자가 「IT 회사가 아니라 매력도가 떨어진다」 고 한 곳)였으며, 토스 계열 5건이 순위에 들었다.
회사 19곳 가운데 18곳은 세 축 모두 근거 없음이었고, 리포트에는 점수와 이유가 없었다.
같은 날 ChatGPT 의 1위는 당근 Content & User Understanding, 2위는 크래프톤 AI Native Full Stack 이었다.

차이의 원인은 다섯 가지다.

- 직무 필터가 SRE, DevOps, 인프라, 일반 백엔드까지 통과시킨다(`scripts/position-recommender/live-postings/policy/role.ts`, `keywords.ts`).
- 공고 점수가 역할 적합도 40, 역할 범위 25, 회사 기회 20, 제약 15 의 네 항목이다(`services/career-backend/src/positions/schema.ts` 의 `scoreBreakdownSchema`, `plugin/skills/position-recommender/references/judgment.md`).
- 회사 근거가 수집기가 모은 OpenDART 와 Blind 평점뿐이고, 모델은 저장된 근거 밖을 찾지 않는다(원본 SKILL.md 「실행」).
- 토스 계열 제외가 등록돼 있지 않다.
- HTML 은 공개 경계 때문에 추천 이유, 점수, 보상 비교를 넣지 않는다(원본 SKILL.md 「결과와 공개 경계」).

## 범위

이 기능은 저장 위치와 무관한 기준만 정한다(DECISION10).
기준은 직무 필터, 다섯 축 점수, 회사 평가 네 칸, 웹 근거, 판단 기준 문서(`judgment.md`), 대시보드 형식과 우선순위 고르기다.
원본(`plugin/skills/position-recommender/`)과 비서용 사본(`plugin/agent-skills/position-recommender/`)에 같은 기준을 둔다(DECISION11).

PR 은 세 개로 나눈다(DECISION14).

| PR | 담는 것 | 시작 조건 |
| --- | --- | --- |
| PR 1 | 직무 필터(REQ1) | 지금. 수집 스크립트 안의 규칙이라 저장 위치와 무관하다 |
| PR 2 | 다섯 축 점수, 회사 네 칸, 웹 근거(REQ3~REQ5) | 「커리어 데이터를 비서로 옮기기」 기능이 머지된 뒤. 그 기능이 정한 자리 위에서 칸을 바꾼다 |
| PR 3 | 우선순위 고르기와 대시보드(REQ6~REQ8) | PR 2 뒤 |

확인(REQ10)은 PR 3 머지 뒤 가족 비서 예약 작업으로 한다.

범위 밖:

- 커리어 데이터 저장 위치를 가족 비서로 옮기는 일. 별도 기능 「커리어 데이터를 비서로 옮기기」 가 fos-assistant 에서 정한다(DECISION10).
  그 기능이 정할 것: 공고 분석을 다음 날까지 남길지, 후보자 기준·지원 상태·토스 계열 제외 목록·직전 대시보드 결과를 어디에 두는지.
- 커리어 Backend 에 새 데이터나 칸을 쓰는 일(DECISION9).
- 수집 회사 넓히기(42dot, 현대오토에버, LG). 다음 기능이다(DECISION8).
- ChatGPT 예약 작업을 끄는 일. 사용자가 REQ10 이 통과한 뒤 직접 끈다(DECISION11).
- 지원서 작성과 제출. `application-package-writer` 가 맡는다.
- 사용자 개인 값(현재 연봉, 거주지, 지원 이력)을 저장소에 쓰는 일. 이 값은 후보자 기준 문서에만 두고, 실행 중 모델이 읽는다.
