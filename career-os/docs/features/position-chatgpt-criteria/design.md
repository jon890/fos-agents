## 책임과 경계

`live-postings/policy/role.ts`가 채용 공고의 직무를 판단하고 `keywords.ts`가 직무 표현을 관리한다. `validator.ts`는 마감과 고용 형태를 확인한 뒤 직무 필터를 실행한다. 소스 어댑터의 사전 검색은 상세 본문을 확보할 후보를 고른다. 상세 조회 상한이 있는 소스는 기존 목록 검색 범위 안에서 공통 필터를 적용한다.
원본과 비서용 사본의 `judgment.md`에 `RULE-ROLE-FILTER`를 기록한다.

PR 2의 다섯 축 점수, 회사 평가 네 칸, 웹 근거는 fos-assistant의 「커리어 데이터를 비서로 옮기기」가 저장 위치를 정하고 머지된 뒤 설계한다. PR 3의 우선순위와 대시보드는 PR 2 뒤에 설계한다. 토스 계열 제외 목록의 위치와 등록은 데이터 이전 기능이 결정한다.

## 인터페이스와 데이터

공고의 기존 `title`과 `mainTasks`를 사용한다. 직무가 맞지 않으면 수집 진단에 `not_target_role`을 기록한다. 커리어 Backend의 API, 저장 구조와 데이터에는 변경이 없다.

## 실패와 일관성

주요 업무 칸에 원문이 통째로 들어온 경우 알려진 자격·우대 제목 앞까지만 읽는다. 소개 문단에 있는 업무도 근거로 쓴다. 제목과 업무에서 근거를 확인하기 어려운 공고는 수집 후보에서 제외한다.

## 검증 전략

공통 검증과 후보풀에서 REQ1의 포함·제외 공고를 합성 자료로 검사한다. 당근과 토스 어댑터를 거치는 사례로 본문에서만 확인되는 업무와 자격·우대 제목 경계도 검증한다.
