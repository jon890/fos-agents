# 비서 웹에서 원티드·LinkedIn 프로필 반영: fos-career 도구가 「내 브라우저」 로 칸을 넣고 다시 읽는다

확인: 2026-11-20

## 목표

가족 비서 웹의 대화에서 「원티드 프로필 최신화해 줘」 라고 하면,
비서가 사이트의 지금 값과 프로필 원고를 비교한 변경 전후 표를 보여 주고, 사이트마다 한 번 승인받은 뒤
fos-career 도구가 사용자의 「내 브라우저」 에서 칸을 하나씩 넣고 다시 읽어 저장됐는지 확인한다.

지금은 원티드·LinkedIn 반영이 노트북 Claude Code 의 `sync-profile` 스킬(로컬 `browser-driver` 와 zsh 스크립트)에서만 된다.
비서 웹의 `career-connector` 는 원고 저장과 GitHub 프로필 갱신까지만 하고, 원티드와 LinkedIn 반영에는 쓰지 않는다고 적혀 있다.
2026-11 현재 사용자의 프로필이 10월 이후 갱신되지 않아 낡아 있다.

## 범위

기능은 PR 두 개로 나눈다(DECISION3).

| PR | 사이트 | 다루는 칸 |
| --- | --- | --- |
| 첫 PR | 원티드 | 이력서의 간단 소개, 경력 프로젝트의 제목·본문·시작월·종료월. 이미 있는 칸만 고친다 |
| 두 번째 PR | LinkedIn | 헤드라인, 소개, 프로젝트. 이 스펙의 결정을 그대로 따르고, LinkedIn 에만 있는 결정은 그 PR 의 계획 전에 이 스펙에 더해 다시 확인받는다 |

요구사항 표는 첫 PR 의 원티드 기준으로 쓴다. 두 번째 PR 은 같은 요구사항을 LinkedIn 칸에 적용한다.
LinkedIn 작업은 원티드 PR 의 머지와 실제 계정 확인을 마친 뒤 시작한다(DECISION3, DECISION9).

범위 밖:

- 원티드의 새 항목 추가(경력, 프로젝트). 사용자가 원티드 화면에서 빈 항목을 추가하면 그 빈 칸은 「이미 있는 칸」 으로 다룬다.
- 원티드의 기술, 링크, AI 활용 경험. 비서는 바꿀 내용만 알리고 사용자가 화면에서 직접 고친다(REQ9).
- Claude·Codex 사용량 수집. 노트북 Claude Code 에 그대로 둔다(사용자 2026-11-20).
- 원고 저장과 GitHub 프로필 갱신의 동작. `career-connector` 가 이미 비서 웹에서 하며, 이 기능은 원고 저장 도구를 반영 뒤에 부르기만 한다.
- 노트북 `sync-profile` 스킬의 로컬 스크립트 경로. 이번 기능은 그 경로를 바꾸지 않는다.
- 자동 로그인과 자격 증명 입력. 로그인은 사용자가 「내 브라우저」 에서 직접 한다.
- fos-assistant 의 변경. 「내 브라우저」 중계(`owner_browser_env`)와 화면 넘기기 카드(fos-assistant ADR-20261111 / connector-handoff)를 있는 그대로 쓴다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 비서는 승인 없이 사용자의 「내 브라우저」 에서 원티드 이력서의 대상 칸 지금 값을 읽는다. 칸마다 사람이 알아볼 이름(예: 「경력 2 / 프로젝트 1 / 본문」), 값, 값의 지문(해시)을 받는다 | 가짜 원티드 화면 fixture 에서 읽기 도구가 소개와 프로젝트의 제목·본문·시작월·종료월을 칸 이름, 값, 지문과 함께 돌려준다. 승인 카드가 생기지 않는다 |
| REQ2 | 비서는 지금 값과 원고(`wanted`)를 비교해 다른 칸만 변경 전후 표로 보인다. 사용자가 대화에서 칸의 문장을 고치면 표를 다시 보인다 | 실제 계정 확인에서 비서가 다른 칸만 표로 보이고, 대화로 고친 문장이 다시 보인 표와 승인 카드에 그대로 들어간다 |
| REQ3 | 반영은 사이트마다 승인 카드 한 번이다. 카드에는 바꿀 칸 이름, 넣을 값, 각 칸의 변경 전 지문만 담는다. 인자가 16KB 를 넘으면 카드를 나눠 차례로 승인받는다 | 쓰기 도구가 `WRITE`, `approval: required`, 상시 허락과 대화 허락 없음으로 선언된다. 16KB 를 넘는 변경은 칸을 나눈 두 번 이상의 호출이 되고, 각 호출은 16KB 이하다 |
| REQ4 | 승인한 실행은 칸을 하나씩 넣고, 넣은 직후 원티드 서버 API 로 다시 읽어 넣으려던 값과 글자 단위로 같은지 확인한다. 같을 때만 다음 칸으로 간다 | fixture 에서 결과가 칸마다 「넣음」 과 되읽은 값의 일치를 보인다. 화면에만 값이 들어가고 서버에 저장되지 않는 fixture 는 「실패」 가 된다 |
| REQ5 | 넣기나 되읽기가 실패하거나, 넣기 직전 칸의 지금 값 지문이 카드의 변경 전 지문과 다르면 그 칸에서 멈춘다. 이미 넣은 칸은 그대로 두고 남은 칸은 넣지 않는다. 결과는 칸마다 「넣음 / 실패 / 넣지 않음」 이고, 넣지 않은 칸에는 이유(앞 칸에서 멈춤, 다른 곳에서 바뀜)를 붙인다. 다시 하려면 새로 읽고 새로 승인받는다 | fixture 의 세 칸 중 둘째 칸 실패에서 결과가 「넣음, 실패, 넣지 않음」 이다. 둘째 칸 값을 승인 뒤 바꾼 fixture 에서는 그 칸을 덮어쓰지 않고 멈춘다. 비서는 같은 인자로 다시 부르지 않는다 |
| REQ6 | 읽기 중 원티드가 로그인이나 보안 확인 화면을 보이면 화면 넘기기 결과를 돌려준다. 비서는 「내 브라우저」 에서 로그인한 뒤 「다 했어요」 를 눌러 달라고 알린다. 승인한 실행 중에 그런 화면이 나오면 남은 칸을 넣지 않고 칸별 결과(이유 「로그인 필요」)를 돌려준다. 비서는 멈췄다고 알린 뒤 다시 읽기를 불러 넘기기 카드를 띄우고, 로그인 뒤 남은 칸만 표로 보여 새로 승인받는다(DECISION24) | 로그인 화면 fixture 에서 읽기 결과가 `isError` 없는 `{"status": "HUMAN_ACTION_REQUIRED", "handoff": {"need": "login", ...}}` 모양이고, 실행 결과는 넘기기 모양이 아닌 `status: "stopped"` 와 칸별 결과다. 실제 계정 확인에서 다시 읽기 때 대화에 넘기기 카드가 뜬다 |
| REQ7 | 칸을 찾지 못하는 등 화면이 예상과 다르면 어느 칸에서 멈췄는지와 대안(노트북 `sync-profile` 로 반영하거나 화면에서 직접 고치기)을 알린다 | 칸 구조를 바꾼 fixture 에서 결과가 멈춘 칸과 「화면이 예상과 다름」 오류 코드를 낸다. 지침이나 도구 설명에 대안 안내가 있다 |
| REQ8 | 반영이 끝나면 비서는 실제로 넣은 값으로 `wanted` 원고를 고친 저장안을 보이고 `save_profile_document` 로 따로 승인받는다. 폼 제약으로 원고와 다르게 넣은 것(진행 중 프로젝트의 종료월 등)은 그 사실을 원고에 함께 적는다. 일부만 넣었으면 넣은 칸만 원고에 반영한다 | 실제 계정 확인에서 반영 뒤 원고 저장 승인 카드가 따로 뜨고, 저장된 원고가 사이트의 값과 같다 |
| REQ9 | 범위 밖 칸(기술, 링크, AI 활용 경험)이 원고와 다르면 비서는 바꿀 내용을 알리고 사용자가 화면에서 직접 고치라고 안내한다. 도구는 그 칸을 쓰지 않는다 | 쓰기 도구의 인자가 범위 밖 칸을 받지 않는다(입력 검사에서 거절). 지침이나 도구 설명에 안내가 있다 |
| REQ10 | 비서 웹의 연결용 지침이 원티드 반영을 안내한다. `career-connector` 의 「원티드와 LinkedIn 사이트 반영에는 사용하지 않는다」 를 원티드에 대해 고치고, 연결용 지침 전체 8,000자 상한을 지킨다 | `plugin/scripts/connector-config.test.ts` 의 상한 테스트와 「모든 도구 이름이 지침에 있다」 테스트가 통과한다 |
| REQ11 | 「내 브라우저」 중계가 꺼졌거나 브라우저에 닿지 못하면 읽기와 실행 모두 칸을 건드리지 않고 「브라우저에 닿지 못함」 으로 끝난다 | 중계 주소가 빈 값인 테스트에서 도구가 칸을 읽거나 쓰지 않고 정한 오류 코드로 끝난다 |
| REQ12 | 표에는 원고 문장과 사용자가 대화에서 준 문장만 올린다. 비서가 다듬거나 새로 쓴 문장은 「비서 제안」 으로 표시하고, 사내 수치나 조직명이 새로 들어가면 표 위에서 공개 여부를 따로 묻는다(DECISION22) | 지침이나 도구 설명에 이 규칙이 있다. 실제 계정 확인에서 비서가 다듬은 문장이 「비서 제안」 표시로 보인다 |
| REQ13 | 원티드 이력서가 하나면 그것을 쓰고, 여럿이면 제목과 고친 날짜 목록을 보여 사용자가 고르게 한다. 승인 카드에 고른 이력서 이름이 나온다(DECISION23) | 이력서 두 개인 fixture 에서 읽기 도구가 목록을 돌려주고, 쓰기 도구 인자에 이력서 식별자와 이름이 들어간다. 다른 이력서는 바뀌지 않는다 |

| DECISION12 | 원고 항목과 사이트 칸의 짝 | 회사 이름과 프로젝트 제목으로 짝짓는다. 짝이 없거나 제목 자체를 바꾸는 변경이면 비서가 어느 사이트 항목에 넣을지 사용자에게 묻는다. 화면 순서로 짝짓지 않는다 | 작성자 | 빈 항목을 더하면 아래 칸 순서가 밀린다(`plugin/skills/sync-profile/references/wanted.md`). 순서로 짝지으면 표 전체가 어긋난다 |
| DECISION13 | 「다르다」·「같다」 판정 | 줄바꿈 모양(CRLF·LF)과 앞뒤 공백만 맞춘 뒤 글자 단위로 비교한다. 기간은 연·월 숫자로 비교한다. 그 밖의 정리는 하지 않는다 | 작성자 | `sync-profile` 의 「긴 본문은 글자 단위로 대조한다」. 표기만 다른 기간이 표에 오르지 않게 한다 |
| DECISION14 | 진행 중 프로젝트의 종료월 | 원고에 진행 중으로 적힌 프로젝트는 반영하는 달을 종료월로 넣는 행을 표에 넣는다. 본문 첫 줄에 현재 담당 중이라고 적는 규칙도 따른다 | 작성자 | 원티드 폼은 진행 중 옵션 없이 종료월을 요구하고, `sync-profile` 이 이 규칙을 이미 쓴다(`references/wanted.md` 「폼이 강제하는 것」) |
| DECISION15 | 범위 밖 칸의 읽기 | 읽기 도구가 기술, 링크, AI 활용 경험의 지금 값도 돌려준다. 비서는 원고와 실제로 다른 것만 「화면에서 직접 고쳐 주세요」 로 알린다 | 작성자 | 같은 이력서 API 응답에 들어 있어 추가 비용이 없다(`references/wanted.md` 「저장 확인」) |
| DECISION16 | 지문 대조에 쓰는 값 | 넣기 직전 원티드 서버에서 새로 받은 값의 지문을 대조한다. 글 칸은 이력서 API 로, 기간 칸은 편집 화면을 새로 열어 서버가 그린 값으로 읽는다. 실행 시작 때 열어 둔 화면 값은 쓰지 않는다 | 작성자 | DECISION5 의 「다른 곳에서 고친 내용을 덮지 않는다」. 원티드 API 의 기간 키 이름은 공개 근거가 없다(design DECISION2) |
| DECISION17 | 지문이 달라 멈춘 칸의 결과 | 「넣지 않음」 으로 적고 이유 「다른 곳에서 바뀜」 을 붙인다 | 작성자 | 칸을 건드리지 않았으므로 「실패」 가 아니다. 사용자가 이유를 보고 다시 읽기를 고른다 |
| DECISION18 | 실행 중 사람이 해야 할 화면의 결과 | 넘기기 모양으로 내지 않고 `status: "stopped"` 와 칸마다의 「넣음 / 넣지 않음」 을 낸다. 비서는 넣은 칸만으로 원고 저장안을 내고, 다시 읽은 표에서는 이미 넣은 칸이 빠진다 | 작성자 | 승인한 실행의 넘기기 결과는 fos-assistant 가 카드 없이 실패로 끝내고 결과를 버린다(DECISION24). REQ5 의 칸별 결과와 REQ8 의 「넣은 칸만 원고에 반영」 을 지킨다 |
| DECISION19 | 사람이 「내 브라우저」 를 쥐고 있을 때 | 읽기 도구는 fos-assistant 계약대로 `human_browser` 넘기기를 낸다. 승인한 실행 중이면 DECISION18 처럼 멈춘 결과를 내고, 넣던 칸은 저장됐을 수 있어 「실패」 와 이유 「브라우저를 사람이 가져감」 으로 적는다. 「브라우저에 닿지 못함」 으로 끝내지 않는다 | 작성자 | fos-assistant `docs/features/user-browser.md` 「사람 잠금」 과 `hermes/connectors/README.md` 의 사람 잠금 신호 |
| DECISION20 | 카드를 나눌 때의 순서 | 앞 카드의 결과가 모두 「넣음」 일 때만 다음 카드를 낸다. 하나라도 아니면 남은 카드를 내지 않고 새로 읽는다 | 작성자 | DECISION5 의 「그 칸에서 멈춘다」 를 카드 사이에도 적용한다 |
| DECISION21 | 화면이 예상과 다를 때의 넘기기 | 넘기기 카드(`unexpected_page`)를 띄우지 않고 멈춘 칸과 대안만 알린다 | 사용자 2026-11-20 | DECISION7. 폼 구조 변화는 사람이 그 탭에서 풀 수 있는 문제가 아니다 |
| DECISION22 | 표에 올릴 문장과 공개 범위 확인 | 원고의 문장과 사용자가 대화에서 준 문장만 올린다. 비서가 다듬거나 새로 쓴 문장은 표에 「비서 제안」 으로 표시한다. 사내 수치나 조직명이 새로 들어가면 표 위에서 공개 여부를 따로 묻는다 | 사용자 2026-11-20 | 비서 웹은 코드와 커밋으로 근거를 확인할 수 없다. 원고 문장은 `sync-profile` 3·4단계를 이미 거쳤다 |
| DECISION23 | 원티드 이력서가 여럿일 때 | 하나면 바로 쓴다. 여럿이면 제목과 고친 날짜 목록을 보이고 사용자가 고른다. 승인 카드에 이력서 이름이 나온다 | 사용자 2026-11-20 | `sync-profile` 은 목록의 첫 이력서를 열어 잘못 고를 수 있다 |
| DECISION24 | 승인한 실행 중 로그인이 풀렸을 때 | 실행은 멈춰서 칸별 결과만 돌려주고, 넘기기 카드는 비서가 다시 읽을 때 띄운다. 로그인 뒤 남은 칸만 표로 보여 새로 승인받는다. fos-assistant 는 고치지 않는다 | 사용자 2026-11-20 (설계 리뷰 뒤) | 넘기기 카드는 승인 없이 도는 호출에서만 뜨고, 승인한 실행의 넘기기 결과는 카드 없이 실패가 된다(fos-assistant `docs/features/browser-cowork/design.md` 「PR4 이어 가기」) |
