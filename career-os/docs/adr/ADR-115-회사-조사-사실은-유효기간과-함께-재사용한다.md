# ADR-115 회사 조사 사실은 유효기간과 함께 재사용한다

- Status: Accepted
- Date: 2026-09-14

## 맥락

포지션 추천은 회사의 사업 규모, 성장 여력, 보상과 복지를 실행마다 다시 찾았다.
고정된 네 축과 판정값을 모든 추천에 요구하면서 근거가 부족한 칸에도 비슷한 문장이 반복됐다.
이 구조는 모델의 조사를 돕기보다 형식을 채우게 했고 다음 실행의 조사 비용도 줄이지 못했다.

회사에 대한 공개 사실과 현재 직장 대비 최종 판정은 수명이 다르다.
공식 실적, 보상 자료와 복지 제도는 여러 실행에서 재사용할 수 있지만,
최종 추천 판단은 현재 역할, 이직 우선순위와 대상 공고가 바뀌면 다시 계산해야 한다.

## 결정

최종 추천 판단을 저장하지 않는다는 부분은 [ADR-117](ADR-117-포지션-분석은-우선순위-큐와-버전-이력으로-재사용한다.md)이 대체한다.
회사 사실과 근거 기반 추론을 유효기간과 함께 재사용하는 결정은 유지한다.

- 공개 회사 사실을 `state/company-research/<companyKey>.json`에 회사별로 저장하고 비공개 작업 release로 동기화한다.
- 실행 중 갱신 입력은 여러 회사를 한 번에 전달할 수 있게 유지하고, 저장 단계에서 회사별 파일로 나눈다.
- 기존 `state/company-research.json`은 처음 갱신할 때 읽은 뒤 회사별 파일로 자동 이전한다.
- 사실은 회사 식별자, 주제, 적용 범위, 출처, 확인 시각과 유효기간을 갖는다.
- 사실에서 도출한 재사용 가능한 추론은 근거 사실, 가정, 신뢰도와 유효기간을 함께 저장한다.
- 찾지 못한 주제는 `researchGaps`에 질문과 재시도 날짜로 저장한다.
- 추천 실행은 유효한 사실을 재사용하고 만료됐거나 재시도 날짜가 된 주제만 조사한다.
- 현재 역할, 개인 우선순위와 최종 추천 순위는 회사 조사 데이터에 저장하지 않는다.
- 추천 스키마는 고정 평가 축, 티어와 순위를 요구하지 않는다. 추천 배열의 순서와 모델이 자유롭게 정한 라벨을 사용한다.
- 추천 이유와 후보 식별 정보만 필수로 두고, 상세 근거와 다음 행동은 도움이 될 때만 기록한다.
- 추천하지 않은 후보에는 보류 사유를 만들도록 요구하지 않는다.
- HTML은 결정에 영향을 주는 근거와 질문을 표시하며, 자료가 없다는 칸을 만들기 위해 문장을 강제하지 않는다.

## 결과

같은 회사가 다시 후보에 들어오면 이미 확인한 규모, 성장, 보상과 복지 및 근거 기반 추론을 바로 활용할 수 있다.
출처가 오래되면 자동으로 다시 조사할 대상을 찾을 수 있고, 공개 자료가 없는 항목을 매일 반복 검색하지 않는다.
리포트는 확인된 판단과 사용자가 할 행동에 집중한다.

## 기각한 대안

- 최종 추천 방향을 회사별로 저장하는 방식은 사용자 기준과 대상 공고가 바뀌어도 과거 판정을 재사용하게 된다.
- 모든 후보 회사를 매번 조사하는 방식은 추천 가능성이 낮은 공고에도 같은 비용을 쓴다.
- 미확인 문구를 HTML에 계속 표시하는 방식은 조사 상태를 보여주지만 선택에 필요한 새 정보는 주지 않는다.
