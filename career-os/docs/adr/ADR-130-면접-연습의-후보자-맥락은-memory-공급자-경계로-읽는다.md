## ADR-130: 면접 연습의 후보자 맥락은 memory 공급자 경계로 읽는다

- **status**: `accepted`
- **결정**:
  - `interview-practice` 가 쓰는 후보자 맥락을 필드가 정해진 계약 하나로 정의한다. 현재 지원 대상, 현재 역할과 경력 수준, 경험 경계 셋이다.
  - 계약을 채우는 공급자는 둘이다. `brain` 은 스킬이 `brain-search` 로 계약의 필드를 채운다. `file` 은 사용자가 템플릿을 복사해 채운 JSON 을 스크립트가 zod 로 검사해 낸다.
  - 어느 공급자를 쓸지는 `CAREER_MEMORY` 환경값(`brain` 또는 `file`)으로 명시한다. 값이 없으면 명령이 실패한다.
  - 스크립트는 brain 을 조회하지 않는다. `brain` 공급자일 때 스크립트는 채울 필드 목록만 내고, 조회는 스킬 안에서 모델이 한다.
- **맥락**:
  - 스킬이 개인 스킬인 `brain-search` 와 개인 지식 기반의 entity 이름을 직접 가리켰다. 다른 사람은 그 스킬도 entity 도 없어 `interview-practice` 를 쓸 수 없었다.
  - 스킬이 brain 에서 읽는 값은 현재 지원 대상, 현재 직장과 경력 수준, 직접 경험의 경계로 셋뿐이었다. 계약으로 고정할 수 있는 크기다.
  - [ADR-102](ADR-102-별도-웹-대시보드보다-파일-기반-피드백-루프를-사용한다.md) 는 실행 스크립트가 private brain 을 직접 조회하지 않는다고 정했다. 이 경계는 유지한다.
  - [ADR-129](ADR-129-면접-연습-기록과-개인-질문은-backend가-소유한다.md) 가 저장소를 `CAREER_STORE` 로 고르게 했다. 후보자 맥락도 같은 방식이어야 다른 사람이 환경값 두 개와 파일 하나로 스킬을 쓸 수 있다.
- **대안 기각**:
  - 스크립트가 brain 저장소를 직접 읽는 공급자는 기각했다. ADR-102 의 경계를 깨고, brain 의 파일 구조가 스크립트 계약이 된다.
  - 후보자 맥락을 Markdown 의 고정 제목 아래 자유롭게 쓰게 하는 안은 기각했다. 채우기는 쉽지만 누락과 형식을 검사할 수 없고 모델이 본문을 해석해야 한다.
  - YAML 은 기각했다. 사람이 쓰기 편하지만 파서 의존이 하나 늘고, JSON 템플릿으로도 채울 값이 적다.
  - `brain-search` 가 있으면 brain, 없으면 file 을 쓰는 자동 선택은 기각했다. ADR-129 의 자동 선택 기각과 같은 이유로, 설정이 빠진 환경에서 다른 맥락으로 조용히 연습하게 된다.
- **결과**:
  - 얻는 것: 다른 사람이 템플릿을 채우고 `CAREER_MEMORY=file` 로 같은 스킬을 쓴다. 스킬 문서가 개인 스킬과 entity 이름을 한 곳(`brain` 공급자 절)에서만 가리킨다.
  - 감당할 것: `brain` 공급자는 모델이 조회해 채우므로 스크립트가 값을 검사하지 못한다. 계약에 필드를 더하면 템플릿, zod 스키마, `brain` 공급자의 조회 목록을 함께 고쳐야 한다. 포지션 추천 같은 다른 스킬은 아직 brain 을 직접 가리킨다.
- **적용 범위**: `scripts/interview-drill/memory.ts`, `.claude/skills/interview-practice/`, `docs/data-schema.md`. 다른 career-os 스킬에 같은 경계를 둘지는 별도 결정으로 다룬다.
