## ADR-103 — 지원 준비는 단일 사용자 진입점과 내부 검증으로 제공한다

- Status: Accepted
- Date: 2026-08-25

### 맥락

지원 패키지 생성, Markdown 검토, 이력서 근거 감사와 HTML 평가가 각각 사용자 스킬로 드러나면 사용자가 어떤 문서를 읽고 어떤 순서로 실행해야 하는지 다시 판단해야 한다. 반면 자동 상태 전이는 생성 결과와 독립된 검토 판정이 필요하다.

### 결정

- 사용자는 `application-package-writer` 하나로 지원 준비를 시작한다.
- `application-package.md`를 지원 판단, 공고·회사 기준, 후보자 근거, 승부처, 공백과 다음 행동을 설명하는 중심 원본으로 사용한다.
- 사용자 검토 화면은 `application-package.html` 하나로 제공하며 후보자 인터뷰, 지원 판단과 이력서 초안을 함께 보여준다.
- 기본 원본은 `candidate-interview.md`, `application-package.md`, `resume-draft.md`만 유지한다.
- 별도 지원 문항은 채용 사이트가 요구할 때만 `application-answers.md`로 만들고, 최종 제출 단계에서 `resume.html`과 `resume.pdf`를 파생한다.
- 후보자 인터뷰는 기존 답변을 보존하고 비어 있는 질문만 한 번에 하나씩 확인한다.
- `application-reviewer`는 자동 상태 전이 또는 명시적인 독립 검토에서만 내부 검사로 사용한다.
- `resume-evidence-auditor`와 `resume-evaluator`는 각각 사실 근거와 최종 HTML 품질이라는 별도 책임을 유지하되 사용자 진입점 안에서 순서대로 연결한다.

`fit-analysis.md`, `cover-letter.md`, `submission-checklist.md`를 모든 지원 건에 만드는 대안은 같은 내용을 여러 파일에서 반복하게 하므로 기각한다.
직접 reviewer와 HTML evaluator를 합치는 대안은 실행 시점과 입력 산출물이 달라 조건 분기가 늘어나므로 기각한다.
독립 reviewer를 삭제하는 대안은 기존 application agent의 상태 전이 안전성을 약화하므로 기각한다.

### 결과

사용자는 한 화면과 최종 제출물만 중심으로 검토하고, 자동화는 기존 독립 판정을 유지할 수 있다.
준비 상태는 합격 보장이 아니라 현재 근거와 사용자 확인이 충분한지를 나타낸다.
