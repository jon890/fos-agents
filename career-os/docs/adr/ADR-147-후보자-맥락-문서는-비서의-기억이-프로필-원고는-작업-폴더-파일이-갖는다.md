## ADR-147: 후보자 맥락 문서는 비서의 기억이, 프로필 원고는 작업 폴더 파일이 갖고 MCP 서버는 밖의 사이트에 닿는 도구만 갖는다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `data, operations`
- **현재 규칙의 원본**: [`docs/data-schema.md`](../data-schema.md#후보자-맥락-문서) 의 「후보자 맥락 문서」, 「커리어 작업 폴더」, 「fos-career 커넥터」. 스펙과 설계는 fos-assistant `docs/features/career-migrate/` 다(사용자 확인 2026-11-21)
- **결정**:
  - **후보자 맥락 문서 넷의 원본은 커리어 에이전트 주인의 기억이다.** 제목은 「커리어: 현재 경력」, 「커리어: 역할 선호」, 「커리어: 지원 상태」, 「커리어: 학습 관심사」 로 고정한다. 스킬이 기억 도구로 읽고, 실행기가 필요로 하는 문서는 본문 그대로 작업 폴더 `context/<문서 키>.md` 에 옮겨 쓴다(스펙 DECISION5).
  - **에이전트가 맥락 문서를 고칠 때는 본문 전체를 기억에 남기고, 바로 저장할지 제안으로 둘지는 비서의 기억 규칙을 따른다.** 제안이면 사람이 받아들이기 전까지 다음 실행은 옛 문서를 쓴다(스펙 DECISION23).
  - **프로필 원고 셋(원티드, LinkedIn, GitHub)의 원본은 작업 폴더 `library/profiles/<이름>.md` 다.** 에이전트가 파일 도구로 고치고 승인 카드가 없다. 원고는 기억에 한 번에 남길 수 있는 2000자보다 길다.
  - **커리어 MCP 서버는 밖의 사이트에 닿는 도구만 갖는다.** 연결 확인, GitHub 프로필 읽기와 갱신, 원티드 이력서 읽기와 반영이다. 커리어 Backend 를 부르던 도구는 지우고 그 일은 스킬과 로컬 실행기가 한다(스펙 DECISION6). MCP 서버는 작업 폴더에 닿지 못한다.
  - **플러그인 선언에서 Backend token 칸과 Backend 주소를 지운다.** 필수 입력 칸이 없고, 확인 도구는 GitHub 만 확인하며 GitHub 연결이 없어도 성공한다. GitHub 단추 연결(`oauth`, `CAREER_GITHUB_TOKEN_URL`)은 그대로 둔다.
  - **GitHub 프로필 갱신은 README 한 파일만 쓴다.** 에이전트 사용량 차트와 Tokens 배지는 프로필에서 뺀다(스펙 DECISION25). 사용량 기록이 노트북 파일로 가 더 갱신되지 않기 때문이다.
  - **면접 연습 기록은 승인 카드 없이 실행기가 작업 폴더 SQLite 에 쓴다.** 저장 자리와 규칙은 [ADR-146](ADR-146-커리어-표-데이터는-에이전트-작업-폴더의-sqlite-가-갖는다.md)이 갖는다.
  - **대화용 스킬 디렉터리(`connector-skills/`)를 없앤다.** 면접 연습과 문서·프로필 관리 스킬은 `agent-skills/` 가 원본이고 셸 실행 공간에서 돈다. 대화용 공부 추천 스킬은 지우고 `study-collection` 이 맡는다(설계 DECISION12).
  - **공고 제외 판정은 실행기 명령 `position check-exclusions` 가 한다.** 판정 코드는 [ADR-142](ADR-142-먼저-살펴보기의-공고-제외-판정은-수집기와-같은-코드가-하고-식별-불가는-보류한다.md)의 것 그대로다. 규칙과 회사 선호가 한 파일에 있어 「한쪽만 읽지 못함」(`constraints-hold`)은 없어진다.
- **대체하는 결정**:

  | ADR | 바뀌는 조항 |
  | --- | --- |
  | ADR-129 | 면접 기록의 저장소 경계와 Backend 소유. 저장 자리는 ADR-146 이 갖고 JSON 파일 저장소와 `CAREER_STORE` 는 없다 |
  | ADR-130 | memory 공급자의 `backend`. 작업 폴더 `context/` 를 읽는 `context` 로 바꾼다. 비서용 스킬은 기억을 직접 읽는다 |
  | ADR-131 | 후보자 맥락 문서의 자리(Backend 문서) |
  | ADR-133 | 프로필 원고의 자리(Backend `profile` 모듈). 사용량 기록 조항은 다음 단계가 바꾼다 |
  | ADR-135 | 커넥터가 Backend 를 감싸는 것과 차트·배지 숫자를 기록에서 읽는 것 |
  | ADR-137 | 「MCP 서버는 데이터 접근만 맡는다」 와 실행기 저장소가 늘 Backend 라는 조항 |
  | ADR-139 | 대화용 스킬과 Claude Code 전용 스킬을 디렉터리로 나누는 것 |
  | ADR-142 | 판정을 MCP 도구가 하는 것과 `constraints-hold`. 판정 규칙은 그대로다 |
  | ADR-143, ADR-144 | MCP 서버가 Backend 에 Cloudflare Access 머리말을 보내는 것. 서버가 Backend 를 부르지 않는다 |
- **맥락**:
  - 커리어 Backend 와 그 데이터베이스를 내리는 것이 목적이다. 1단계에서 공고 추천과 공부 추천이 작업 폴더 SQLite 로 옮겨 갔고, 남은 Backend 호출이 MCP 도구와 면접 실행기였다.
  - MCP 서버는 에이전트 주인의 작업 폴더를 마운트하지 않는다. 작업 폴더에 있는 데이터를 MCP 도구로 다루려면 서버에 저장소를 따로 둬야 한다.
  - 노트북 Claude Code 의 커리어 스킬은 더 쓰지 않는다(스펙 DECISION2). 실행 환경이 비서 하나라 대화용과 노트북용을 나눌 이유가 없다.
- **대안 기각**:
  - **맥락 문서도 작업 폴더 파일로 두기**: 사람이 기억 화면에서 고칠 수 없고, 비서의 다른 대화가 그 맥락을 쓰지 못한다.
  - **프로필 원고도 기억으로 두기**: 기억에 한 번에 남길 수 있는 본문이 2000자라 원고(원티드 원고는 7천 자가 넘는다)가 들어가지 않는다.
  - **Backend 도구를 남기고 저장만 바꾸기**: MCP 서버가 작업 폴더에 닿지 못해 서버 쪽에 새 저장소가 필요하다.
  - **사용량 차트를 멈춘 값으로 남기기**: 갱신되지 않는 숫자가 최신처럼 보인다.
- **결과**:
  - 면접 기록과 원고 저장에서 승인 카드가 사라진다. 누구나 보는 프로필을 바꾸는 두 도구만 호출마다 승인받는다.
  - 커리어 에이전트는 맥락 문서가 든 기억 영역을 받아야 한다. 운영 확인 항목이다.
  - Claude Code 전용 스킬(`plugin/skills/`)은 지운 도구를 가리킨 채로 남아 돌지 않는다. 다음 단계가 지원 준비 스킬을 비서용으로 옮기고 이 디렉터리를 지운다.
  - 운영의 `operator_env` 값(`CAREER_BACKEND_URL`)과 실행 공간 env 의 Backend 값은 운영 단계에서 지운다. 플러그인이 더 요구하지 않으므로 남아 있어도 동작에 영향이 없다.
