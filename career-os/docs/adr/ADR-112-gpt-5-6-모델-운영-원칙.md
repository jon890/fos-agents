## ADR-112 — GPT-5.6 모델 운영 원칙

## 상태

Accepted

## 맥락

GPT-5.6은 `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`로 역할을 나눈다.
`gpt-5.6` alias는 `gpt-5.6-sol`을 가리킨다.

모델 문자열만 바꾸면 reasoning 설정, 프롬프트 길이, 품질·비용의 실제 변화를 확인하지 못한다.
현재 career-os에는 활성 OpenAI API 호출이 없다.
따라서 미사용 환경 변수나 provider 설정을 추가하면 실행 경계가 불명확해진다.

## 결정

활성 OpenAI API 호출이 발견되거나 새로 도입될 때만 GPT-5.6 운영 원칙을 적용한다.

- 복잡하고 품질이 중요한 작업은 `gpt-5.6` 또는 `gpt-5.6-sol`을 기본 후보로 둔다.
- 품질과 비용 균형 작업은 `gpt-5.6-terra`를 기본 후보로 둔다.
- 대량·비용 민감 작업은 `gpt-5.6-luna`를 기본 후보로 둔다.
- reasoning, 도구 호출, 다중 턴 작업은 Responses API를 우선 검토한다.
- 기존 reasoning 설정을 기준값으로 유지한다.
  같은 대표 작업에서 한 단계 낮은 설정도 비교한다.
- 프롬프트는 목표, 맥락, 제약, 필요한 근거, 성공 기준, 출력 형식에 집중한다.
  일반적인 축약 지시와 중복 지시는 제거한다.
- 전환 전후에는 task 성공, 결과 완결성, 근거 충족, 토큰, 지연 시간, 비용을 비교한다.

## 대안

### 모든 작업을 `gpt-5.6-sol`로 고정

단순하고 대량인 작업에 과도한 비용과 지연 시간을 만든다.

### 모델 문자열만 일괄 교체

reasoning·프롬프트·품질 차이를 검증하지 못한다.

### 활성 호출이 없어도 OpenAI 환경 변수를 미리 추가

실행되지 않는 설정을 정본처럼 남겨 향후 호출 경계를 흐린다.

## 결과

미래의 OpenAI API 도입 또는 변경은 모델 선택과 검증 기준을 일관되게 따른다.
현재 career-os 실행 경로와 비밀 설정은 변경하지 않는다.
