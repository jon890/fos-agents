## ADR-127: 공부 추천은 고르지 않은 후보의 판정을 재사용한다

- **status**: `accepted`
- **결정**: 모델이 고르지 않은 후보마다 한 줄 이유를 남기고, 서버가 그 판정을 후보자 기준 버전과 30일 유효기간과 함께 `study_material_verdicts` 에 저장한다. 후보 조회는 이미 추천한 자료와, 지금 기준 버전에서 유효기간이 남은 판정이 있는 자료를 뺀다. 관심사가 바뀌면 사람이 `study_recommendation_control.candidate_context_version` 을 올리고, 그러면 예전 판정이 모두 조회에서 빠진다.
- **대체된 부분**: [ADR-013](ADR-013-외부-읽을거리는-전체-수집-후-모델이-선별한다.md)의 「최종 주제 적합도와 추천 이유는 현재 모델이 이전 추천을 제외한 전체 후보 풀을 보고 판단한다」 를 대체한다. 모델은 전체 후보가 아니라 새 후보와 판정이 만료된 후보만 본다. 수집 단계에서 후보를 자르지 않는다는 ADR-013 의 나머지는 그대로다.
- **맥락**: 후보는 하루 최대 100건이고 모델에게는 제목과 짧은 발췌가 간다. 모델은 그중 5건 안팎을 고른다. 고른 자료는 누적 이력에 들어가 다시 나오지 않지만, 고르지 않은 95건 안팎은 다음 날 또 판단 대상이 된다. 같은 자료를 같은 기준으로 매일 다시 판단하는 것이 반복 비용이다. 포지션 추천은 이미 `position_analyses` 를 `content_hash` 와 `valid_until` 로 재사용하고, 후보자 기준은 `candidate_context_version` 이라는 사람이 올리는 값으로 둔다. 같은 구조를 쓴다.
- **대안 기각**:
  - 판정을 저장하지 않는 안은 기각했다. 비용이 크지는 않지만 사용자가 처음 요구한 것이 「이미 분석한 것을 캐시처럼 써서 토큰을 아낀다」 였다.
  - 유효기간 없이 기준 버전만 두는 안은 기각했다. 사람이 버전을 올리는 것을 잊으면 한 번 제외된 자료가 영영 나오지 않는다. ADR-013 이 걱정한 「잘린 후보를 다시 평가할 수 없다」 가 그대로 생긴다.
  - 판정을 자료 내용의 hash 로 무효화하는 안은 기각했다. 기술 블로그 글은 게시 뒤 거의 바뀌지 않고, 바뀌는 경우의 대부분은 발췌의 공백이나 추적 query 다. 판정을 흔들 뿐 다시 판단할 이유가 되지 않는다.
- **결과**:
  - 얻는 것: 모델이 매일 보는 후보가 새로 수집된 자료와 만료된 판정으로 줄어든다. 기준이 바뀌면 버전 하나로 전부 다시 평가한다.
  - 감당할 것: 모델이 고르지 않은 후보마다 이유를 내야 한다. 이유 없이 빠진 후보는 판정이 없으므로 다음 날 다시 나온다. 30일 안에는 관심사가 조금 바뀌어도 사람이 버전을 올리지 않으면 예전 판정이 유지된다. 판정은 지우지 않고 쌓이지만, 자료 하나에 기준 버전마다 한 행이라 행 수는 자료 수에 비례한다.
