## ADR-102 별도 웹 대시보드보다 파일 기반 피드백 루프를 사용한다

- Status: Accepted
- Date: 2026-07-03

### 맥락

별도 웹 대시보드와 MySQL로 공고, 지원 후보, 면접 준비, 작업 큐를 통합하는 방안을 검토했다.
하지만 서버와 데이터베이스 운영 비용이 개인 커리어 피드백 루프의 가치보다 컸다.

### 결정

career-os의 파일과 skill 산출물로 상태와 피드백을 관리한다.
외부 데이터베이스, 요청 큐, outbox worker를 필수 구성 요소로 두지 않는다.

현재 지원 대상과 회사별 지원 판단은 여러 실행 환경에서 함께 조회할 수 있는 private brain에 둔다.
skill은 brain 검색 결과를 저장소의 `applications/<company>/<position>/` 경로로 해석해 실행 코드에 명시적으로 전달한다.
실행 스크립트가 private brain을 직접 조회하거나 현재 대상을 별도 상태 파일에 복제하지 않는다.

### 거절한 대안

- 웹 대시보드는 조회 화면을 제공하지만 별도 배포와 운영이 필요하다.
- MySQL은 질의를 쉽게 하지만 현재 데이터 규모와 개인 사용 흐름에는 과하다.

### 결과

수집, 판단, 문서 생성, 면접 연습을 저장소 안에서 직접 연결한다.
현재 대상은 환경마다 복제한 로컬 파일 없이 private brain에서 같은 기준으로 복원한다.
필요한 화면은 정적 HTML 리포트로 제공하고 외부 공유가 필요할 때만 게시한다.
