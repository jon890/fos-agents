## ADR-148: 지원 준비는 비서의 셸 실행 공간에서 하고 작업본 동기화와 노트북 전용 스킬을 두지 않는다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `data, operations`
- **현재 규칙의 원본**: [`docs/flow.md`](../flow.md#지원-자료의-자리) 의 「지원 자료의 자리」, 「지원서 공통 프로필」, 「사용량 수집」 과 [`docs/data-schema.md`](../data-schema.md#커리어-작업-폴더) 의 「커리어 작업 폴더」, 「사용량 파일」. 스펙과 설계는 fos-assistant `docs/features/career-migrate/` 다(사용자 확인 2026-11-21)
- **결정**:
  - **스킬은 모두 `plugin/agent-skills/` 가 원본이고 fos-assistant 에이전트의 셸 실행 공간에서 돈다.** 지원 준비 스킬 넷(`application-package-writer`, `resume-preparer`, `resume-review`, `interview-question-prep`)을 옮기고 `plugin/skills/` 를 지운다. 사본 생성기는 다른 실행 환경 전용 표현을 찾는 검사기로 바꾼다(스펙 DECISION2, DECISION7, 설계 DECISION9).
  - **지원 자료는 커리어 작업 폴더에만 있다.** `applications/<회사>/<직무>/`, `library/`, `state/verified-claims/` 를 실행기와 파일 도구로 읽고 쓴다. 기기 사이에 작업본을 주고받던 동기화(`scripts/career-workspace/`, 실행기의 `workspace begin|finish`)를 지운다. `workspace paths` 만 남고 모든 실행기가 같은 작업 폴더 기본값을 쓴다.
  - **지원서 공통 프로필은 기억에서 읽는다.** 제목은 「커리어: 지원서 공통 프로필」 로 고정한다. 에이전트가 지원서 입력을 만들 때만 읽어 작업 폴더 `context/application-profile.md` 로 옮기고, 쓰고 나서 지운다. 서비스 토큰으로 fos-assistant 에 묻던 client 와 실행기(`application-profile`)를 지운다.
  - **사용자에게 줄 결과는 실행기가 사본으로 만들고 에이전트가 「내 파일」 에 넣는다.** `package report` 가 `reports/` 에 날짜가 든 이름으로 복사하고 넣을 경로를 한 줄로 알린다(스펙 DECISION22).
  - **이력서 PDF 는 실행 공간에 Chrome 이 있을 때만 만든다.** 없으면 `resume export` 가 실패하지 않고 HTML 만 만들며, 제출 묶음은 만들지 않는다(스펙 DECISION12).
  - **다른 스킬의 기준 문서는 링크가 아니라 스킬 이름과 경로로 가리킨다.** 에이전트가 `skill_view` 로 읽는다. 설치된 자리에서 상대 경로가 유지된다는 보장이 없다.
  - **에이전트 사용량은 세션 기록이 있는 기기의 파일 하나에 쌓는다.** 수집기가 커리어 Backend 를 부르지 않고, 이미 기록한 달은 사유 없이 바꾸지 않는다. 번들 실행기에서 `usage` 를 뺀다(스펙 DECISION8).
  - **세 프로필 사이트를 한 기기의 브라우저로 직접 조작하던 `sync-profile` 스킬을 지운다.** 원티드와 GitHub 은 `career-connector` 가 MCP 도구로 반영하고 LinkedIn 은 원고만 고친다.
- **대체하는 결정**:

  | ADR | 바뀌는 조항 |
  | --- | --- |
  | ADR-108 | 비공개 작업 release 를 S3 collection 에 보관하는 것. 주고받을 작업본이 없다 |
  | ADR-133 | 사용량 기록의 자리(Backend `profile` 모듈). 기기의 파일이 갖는다 |
  | ADR-136 | 공통 프로필을 서비스 토큰으로 읽는 것. 원본이 fos-assistant Memory 라는 것은 그대로다 |
  | ADR-138 | 작업본 위치의 기본값(홈 아래)과 동기화 설정. 실행기가 `scripts/` 원본을 번들해 부르는 것은 그대로다 |
  | ADR-141 | 실행기 스킬을 `skills/` 원본의 사본으로 두는 것. 모두 `agent-skills/` 가 원본이다 |
- **맥락**:
  - 커리어 일을 비서 대화 하나로 모으고 운영하는 서비스와 저장 공간을 줄이는 것이 목적이다(스펙 DECISION2). 실행 환경이 하나면 작업본을 맞출 상대가 없다.
  - 2단계에서 MCP 도구가 사라져, 지운 도구를 가리키는 노트북 전용 스킬 넷은 이미 돌지 않았다.
  - 실행 공간은 기억에 닿지 못한다. 맥락 문서와 같은 방식으로 에이전트가 읽어 넘긴다.
  - 실행 공간 이미지에는 Chrome 이 없을 수 있고, 이력서 PDF 는 지원할 때만 드물게 필요하다.
- **대안 기각**:
  - **사본 생성을 유지하고 원본을 따로 두기**: 원본을 읽는 실행 환경이 없다. 사본 규칙만 남아 원본과 사본이 어긋날 자리가 된다.
  - **작업본 동기화를 남겨 두 환경에서 쓰기**: 운영할 저장 공간과 잠금, 충돌 복구가 남는다. 쓰는 사람이 한 명이고 실행 환경이 하나다.
  - **공통 프로필 사본을 작업 폴더에 계속 두기**: 연락처가 든 파일이 남고 기억과 어긋난 것을 알 수 없다.
  - **Chrome 이 없으면 실패하기**: HTML 로도 검토와 전달을 할 수 있는데 지원 준비 전체가 멈춘다.
  - **결과 사본을 에이전트가 직접 복사하기**: 공고 추천에서 에이전트가 넣기를 건너뛴 적이 있다. 실행기가 넣을 파일을 알리게 한다.
- **결과**:
  - 지원 준비 넷이 비서 대화에서 돌고 결과가 작업 폴더와 「내 파일」 에 남는다. 공고별 면접 질문 연습은 HTML 결과가 없고 연습 기록이 SQLite 에 남는다.
  - 기억에 「커리어: 지원서 공통 프로필」 문서가 있어야 지원서 입력을 준비한다. 앞서 다른 제목으로 둔 문서는 사용자가 이 제목으로 옮긴다. 운영 확인 항목이다.
  - 검토를 맡길 별도 검토자가 실행 공간에 없다. 쓴 대화에서 한 검토는 `독립성 미확인` 으로 기록한다.
  - Backend 에 있던 지난 달 사용량 기록은 옮기지 않는다. 파일은 수집기가 처음 돈 달부터 쌓인다.
  - 운영의 작업본 release 와 그 저장 공간은 운영 단계에서 지운다. 코드가 더 읽지 않으므로 남아 있어도 동작에 영향이 없다.
  - `scripts/candidate-context/`, `scripts/profile/` 과 `services/career-backend` 는 Backend 를 내린 뒤 지운다.
