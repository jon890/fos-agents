## ADR-035 — TypeScript 실행 코드는 책임별 모듈로 분리한다

- Status: 결정됨
- Date: 2026-05-19
- Updated: 2026-08-12

### 맥락

`career-os/scripts/<skill>/` 아래 ts 헬퍼들이 외부 API fetch, 필터·정규화, markdown 렌더링, CLI 파싱, 파일 IO를 한 파일에 모두 응집한 god-script 구조였다.
새 source 추가 시 한 파일 전체를 수정해야 하고, 순수 함수가 IO와 섞여 단위 테스트 진입점이 없는 문제가 있었다.

### 결정

TypeScript 실행 코드를 다음 책임으로 분리한다.

- `source/`는 외부 응답 수집과 소스별 어댑터를 맡는다.
- `transform/`은 선별, 정규화, 중복 탐지, 점수 계산을 맡는다.
- `persistence/`는 실행 이력과 상태 파일 입출력을 맡는다.
- `render/`는 Markdown과 HTML 파생을 맡는다.
- `reading_contracts.ts`는 읽을거리 타입과 허용 상수를 맡는다.
- `cli.ts`는 각 단계를 조립하고 최종 상태를 기록한다.

공개 실행 경로는 `refresh_topic_inventory.ts`다.
이 파일은 `cli.ts`의 `main`을 호출하는 호환 진입점으로 유지한다.

거절한 대안:
- 한 파일 안에서 함수 그룹화(분리 없음): 확장 시 같은 파일이 계속 비대해지고 오차(drift) 위험이 영구화된다.
- 저장소 공용 영역으로 승격하면 워크스페이스 한정 도메인 로직의 책임이 흐려진다.

### 결과

- 새 수집 방식은 어댑터와 레지스트리에 추가한다.
- 타입과 허용값은 계약 모듈에서 찾을 수 있다.
- 순수 선별 로직과 런타임 경계 검증을 독립적으로 테스트할 수 있다.
- 파일 수는 늘지만 변경 영향 범위와 테스트 진입점이 명확해진다.
