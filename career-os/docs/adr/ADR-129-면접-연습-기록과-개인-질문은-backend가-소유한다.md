## ADR-129: 면접 연습 기록과 개인 질문은 저장소 경계 뒤에 두고 운영은 Backend가 소유한다

- **status**: `accepted`
- **결정**:
  - `interview-practice` 의 주제별 복습 상태, 연습 기록과 개인 질문을 `scripts/interview-drill/store/` 의 저장소 interface 뒤에 둔다. 구현은 커리어 Backend(`/api/interview/v1`, `fos_career`)와 로컬 파일 둘이다.
  - 어느 구현을 쓸지는 `CAREER_STORE` 환경값(`backend` 또는 `file`)으로 명시한다. 값이 없으면 명령이 실패한다. 실행 중에 구현을 바꾸지 않는다.
  - 운영(hermes)은 `backend` 를 쓴다. Backend 가 없는 사용자는 `file` 로 같은 스킬을 쓴다.
  - 복습일 규칙은 한 모듈이 소유하고 두 구현이 함께 쓴다. Backend 구현에서는 연습 기록 추가와 같은 transaction 안에서 계산한다.
  - 공개 질문 은행, 공고별 질문과 질문 출처 config 는 파일로 남는다.
- **맥락**:
  - 면접 연습은 hermes 의 `career` profile 에서 여러 대화에 걸쳐 진행한다. 복습 상태가 container 안 작업본의 `state/drill-progress.json` 에 있으면 작업본을 다시 준비하거나 다른 실행 환경에서 연습할 때 기록이 이어지지 않는다.
  - 스킬은 결과를 기록하라고 지시했지만 엔진 CLI 에는 기록 명령이 없었다. 모델은 즉석 스크립트로만 기록할 수 있었고, hermes 는 그런 명령을 막는다. 2026-09-27 에 노트북, 홈서버와 hermes 어디에도 연습 기록 파일이 없었다.
  - 개인 질문은 비공개 작업본 release 로 동기화했다. 대화 중에 더한 질문은 release 를 다시 발행해야 다음 대화에 보인다.
  - 커리어 Backend 는 이미 hermes 와 같은 Docker network 에 있고 hermes 는 연결값을 가지고 있다.
  - career-os 스킬을 Backend 없이 쓰려는 사람도 있다. 저장 방식이 코드 곳곳에 박혀 있으면 한쪽을 고를 때마다 스킬 코드를 고쳐야 한다.
- **대체된 부분**: [ADR-102](ADR-102-별도-웹-대시보드보다-파일-기반-피드백-루프를-사용한다.md) 가 면접 자료에 파일 기반 상태를 적용한 부분 중 연습 기록과 개인 질문을 이 ADR 이 대체한다. 지원 문서와 공고별 질문에는 ADR-102 가 그대로 적용된다.
- **대안 기각**:
  - 파일을 유지하고 기록 명령만 더하는 안은 기각했다. 기록 누락은 고치지만 실행 환경마다 복습 상태가 따로 쌓이는 문제가 남는다.
  - Backend 만 두고 파일 구현을 없애는 안은 기각했다. 운영에는 충분하지만 Backend 를 띄우지 않는 사용자가 스킬을 쓸 수 없다.
  - Backend 에 닿지 못할 때 파일에 쌓았다가 다시 보내는 자동 대체는 기각했다. 원본이 둘이 되고 재전송 코드와 파일 상태가 다시 생긴다. `backend` 를 고른 실행은 Backend 에 닿지 못하면 실패하고 모델이 기록되지 않았다고 알린다.
  - `CAREER_BACKEND_URL` 이 있으면 Backend, 없으면 파일을 쓰는 자동 선택은 기각했다. 설정이 하나 줄지만, hermes 에서 URL 이 빠지면 오류 없이 파일에 쌓이기 시작해 이 ADR 이 풀려는 문제가 다시 생긴다.
  - 질문 출처 config 까지 옮기는 안은 기각했다. [ADR-126](ADR-126-읽을거리-소스-목록은-backend가-원본을-가진다.md) 이 읽을거리 출처를 옮긴 이유는 매일 도는 cron 에서 실패하는 출처를 커밋 없이 꺼야 한다는 것과, 출처를 가리키는 DB 행이 있다는 것이었다. 면접 질문 출처에는 둘 다 없다.
  - 개인 질문의 `answerSignals` 와 `followUps` 를 자식 table 로 나누는 안은 기각했다. 이 목록은 따로 조회하거나 집계하지 않고 질문 전체가 한 번에 모델에게 전달된다. 조회에 쓰는 칸만 컬럼으로 두고 나머지는 쓰기 전에 검사한 JSON 으로 둔다.
- **결과**:
  - 얻는 것: hermes 의 어느 대화에서 연습해도 같은 복습 상태로 질문을 고른다. 대화 중에 더한 개인 질문이 다음 연습에 바로 쓰인다. 기록 재시도는 `attemptId` 로 한 번만 반영된다. Backend 가 없는 사용자도 `CAREER_STORE=file` 하나로 같은 스킬을 쓴다.
  - 감당할 것: 저장소 구현이 둘이라 계약 테스트를 두 구현에 모두 돌려야 한다. 파일 구현은 한 사람이 한 곳에서 쓰는 것을 전제로 하고 동시 기록을 보장하지 않는다. `backend` 를 고르면 Backend 가 멈춘 동안 연습 질문을 고를 수도 기록할 수도 없다. 모든 실행 환경에 `CAREER_STORE` 를 설정해야 한다. 개인 질문 JSON 의 형식은 DB 제약이 아니라 zod 검사가 지킨다.
- **적용 범위**: `services/career-backend/src/interview/`, `scripts/interview-drill/`, `.claude/skills/interview-practice/`, `docs/data-schema.md`, `docs/flow.md`. 포지션 추천과 공부 추천에 같은 경계를 둘지는 별도 결정으로 다룬다.
