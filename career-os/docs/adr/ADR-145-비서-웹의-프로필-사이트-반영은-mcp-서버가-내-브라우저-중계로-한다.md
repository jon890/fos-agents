## ADR-145: 비서 웹의 프로필 사이트 반영은 MCP 서버가 「내 브라우저」 중계로 한다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `security, operations`
- **현재 규칙의 원본**: [`docs/features/profile-browser-sync/design.md`](../features/profile-browser-sync/design.md), 스펙 [`spec.md`](../features/profile-browser-sync/spec.md)(사용자 확인 2026-11-20)
- **결정**:
  - **비서 웹에서 원티드 프로필을 고치는 일은 fos-career MCP 서버의 도구가 한다.** 도구는 fos-assistant 가 `owner_browser_env`(`CAREER_BROWSER_URL`)로 넘겨 준 중계 주소로 사용자의 「내 브라우저」 에 CDP 로 붙어, 칸을 하나씩 넣고 원티드 서버에서 다시 읽어 확인한다.
  - [ADR-137](ADR-137-스킬과-mcp를-plugin-하나로-묶고-세-단계로-옮긴다.md) 의 「MCP 서버는 데이터 접근만 맡는다」, 「브라우저 조작은 Claude Code 에서만 돈다」 를, 「내 브라우저」 중계를 받는 도구에 한해 이 결정으로 바꾼다. 다른 브라우저 조작(노트북 `sync-profile` 의 LinkedIn 반영 등)은 지금처럼 Claude Code 에서만 돈다.
  - 노트북 `sync-profile` 의 원티드 스크립트는 그대로 둔다. 같은 원티드 화면 지식이 노트북 스크립트와 `plugin/src/wanted/` 두 곳에 있다.
  - 쓰기 도구는 승인한 실행으로 돌므로 사람이 해야 하는 화면을 만나도 화면 넘기기를 내지 않고 칸별 결과와 함께 멈춘다. 넘기기 카드는 승인 없이 도는 읽기 도구만 띄운다.
- **맥락**:
  - 사용자가 비서 웹에서도 원티드·LinkedIn 을 반영하기를 골랐다(2026-11-20). 프로필이 10월 이후 갱신되지 않아 낡아 있었다.
  - 비서 웹의 연결용 에이전트에는 셸과 파일 도구가 없고 MCP 도구만 부른다. 노트북 스크립트는 zsh 와 로컬 `browser-driver` 를 쓴다.
  - fos-assistant 는 「내 브라우저」 와 플러그인용 중계(`owner_browser_env`), 화면 넘기기 카드를 이미 갖고 있고 네이버 블로그 플러그인이 같은 방식으로 돈다.
  - fos-assistant 의 화면 넘기기 카드는 승인 없이 도는 호출에서만 뜬다. 승인한 실행의 넘기기 결과는 카드 없이 실패가 되고 결과가 버려진다.
- **대안 기각**:
  - 노트북 스크립트를 비서 웹에서 다시 쓴다: 비서 웹에는 셸이 없어 부를 수 없다.
  - fos-assistant 에 범용 브라우저 조작 도구를 둔다: 원티드 화면 지식이 fos-assistant 로 옮겨 가 커리어 판단과 원고가 있는 fos-career 와 떨어진다. 플러그인이 사이트를 모르게 하는 fos-assistant 의 원칙과도 어긋난다.
  - 네이버 블로그처럼 분리 작업 프로세스와 상태 조회 도구를 둔다: 칸 몇 개는 승인한 호출의 60초 안에 끝난다. 작업 파일과 조회 도구가 늘어나는 비용이 크다. 대신 실행에 45초 제한을 두고 남은 칸은 다시 승인받는다.
  - 실행 중 넘기기 카드를 위해 fos-assistant 에 쓰기 승인의 이어 가기를 더한다: 결제 승인에만 있는 장치를 새로 만드는 일이라 이번 범위를 크게 넘는다(사용자 2026-11-20).
- **결과**:
  - 얻는 것: 비서 웹 대화에서 원티드 프로필을 변경 전후 표, 승인 한 번, 칸별 확인으로 고친다. fos-assistant 는 고치지 않는다.
  - 감당할 것:
    - 원티드 화면이 바뀌면 노트북 스크립트와 `plugin/src/wanted/page.ts` 를 함께 고쳐야 한다.
    - 원티드 API 의 기간·회사 이름 키와 목록 화면 모양은 공개 근거가 없어 배포 뒤 실제 계정으로 확인한다.
    - 승인한 실행 중 로그인이 풀리면 카드가 바로 뜨지 않고, 비서가 다시 읽을 때 뜬다.
    - MCP 서버가 사용자의 로그인된 브라우저를 조작하므로, 쓰기 도구는 상시 허락과 대화 허락 없이 호출마다 승인받는다.
