## ADR-116: 검증한 주장은 근거 해시와 함께 state에서 재사용한다

- **status**: `accepted`
- **결정**: 모든 주장이 안전하고 현재 제출 HTML과 일치하는 공고별 근거 원장에서 주장과 근거 파일 해시를 `state/verified-claims/`에 반영한다. 다음 지원에서는 문구와 근거가 같은 판정만 재사용하고 달라진 항목만 다시 감사한다.
- **맥락**: 공고별 원장은 현재 제출 문서 전체를 증명하지만, 다음 지원은 같은 경력 근거를 다시 읽고 판정했다. `library/resume-baselines/`에는 사람이 관리하는 프로필 원고와 과거 검토 산출물도 섞여 있어 현재 자료와 낡은 결과를 경로만으로 구분하기 어려웠다.
- **대안 기각**:
  - 공고별 원장 전체를 그대로 재사용하면 제출 문구 해시가 달라졌을 때 어느 주장만 유효한지 구분할 수 없다.
  - 검증 결과를 `sources/fos-study/task/`에 쓰면 읽기 전용 학습 이력과 파생 판정의 책임이 섞인다.
  - 검증 결과를 `library/`에 두면 사람이 관리하는 원고와 도구가 갱신하는 상태를 다시 섞게 된다.
  - 별도 데이터베이스나 검색 서비스를 두면 현재 파일 release만으로 동작하는 지원 흐름에 새 운영 의존성이 생긴다.
- **결과**:
  - 얻는 것: 모델에 전달하기 전에 재사용 가능 여부와 다시 읽을 근거를 코드로 정해 반복 검증의 입력과 비용을 줄일 수 있다. JSON 본문과 검색 CLI로 주장과 근거를 찾을 수 있다.
  - 감당할 것: 근거 파일의 내용이 바뀌면 해당 주장을 다시 감사해야 한다. URL 근거는 자동 재사용하지 않으며 공고별 완결 원장은 계속 유지해야 한다.
- **적용 범위**: `resume-preparer`, `state/verified-claims/`, `library/profiles/`와 공고별 `review/claim-ledger.json`
