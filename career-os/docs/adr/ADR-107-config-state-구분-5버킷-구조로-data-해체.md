## ADR-107 — config/state를 분리하고 자산을 5개 버킷으로 관리한다

- Status: Accepted
- Date: 2026-07-08

### 맥락

`data/`에 지원 원장, 리포트, runtime 상태, cache, 수집 원문이 섞이면 경로만으로 파일의 책임을 판단하기 어렵다.
config와 state는 작성 주체가 아니라 변경 트리거로 나눠야 한다.

### 결정

- `config/`는 사용자의 의도, 정책, 사실, override를 담는다.
- `state/`는 실행과 이벤트로 갱신되는 상태를 담는다.
- `applications/`는 지원 건별 작업 문서를 담는다.
- `reports/`는 사람이 읽는 생성 산출물을 담는다.
- `cache/`는 재생성 가능한 수집 결과와 임시 파일을 담는다.
- `data/`를 신규 정본 경로로 사용하지 않는다.

### 거절한 대안

- config/data 두 분류를 유지하면 생성물의 retention과 추적 정책을 파일별 예외로 관리해야 한다.
- 파일을 누가 작성했는지로 나누면 LLM과 사용자가 함께 관리하는 설정을 분류할 수 없다.

### 결과

경로만으로 자산의 변경 트리거, 소유권, retention 성격을 판단할 수 있다.
현재 파일별 스키마는 `docs/data-schema.md`를 따른다.
