## ADR-135: fos-assistant 커넥터는 Backend 를 감싸고 숫자는 기록에서 직접 읽는다

- **status**: `accepted`
- **결정**:
  - fos-assistant 에 연결하는 커리어 커넥터 `fos-career` 를 `career-os/plugin/` 에 둔다. 가계부 커넥터와 같은 구성(stdio MCP 서버, `connector.json`, 커밋하는 단일 번들)이다.
  - 커넥터는 커리어 Backend 의 HTTP API 와 GitHub API 만 부른다. 파일을 읽거나 쓰지 않고 `.env` 를 탐색하지 않는다.
  - 읽기 도구는 승인 없이 돈다. 쓰기 도구는 셋이고 모두 승인이 필요하다. 후보자 맥락 문서 저장, 프로필 원고 저장, GitHub 프로필 갱신이다.
  - **GitHub 프로필을 갱신할 때 모델은 README 본문만 넘긴다.** 차트는 커넥터가 Backend 의 사용량 기록으로 그린다. README 의 Tokens 배지 값이 기록의 합계와 다르면 도구가 거절한다.
  - 원티드와 LinkedIn 의 반영은 커넥터가 하지 않는다. 로그인된 브라우저가 있는 기기의 `sync-profile` 이 한다.
- **맥락**:
  - 프로필 갱신의 원칙은 「무엇을 어떻게 바꿀지 보여주고 확인받은 뒤에 넣는다」 다. fos-assistant 의 승인은 사용자가 승인한 정확한 인자로 한 번만 실행한다.
  - 커넥터 에이전트는 셸과 파일 도구를 열 수 없고 Memory 를 받지 않는다. 브라우저 조작과 세션 기록 측정은 커넥터로 옮길 수 없다.
  - 사용량 수치는 프로필에 그대로 공개된다. 모델이 수치를 옮겨 적으면 틀려도 승인 카드에서 알아보기 어렵다.
  - Backend 의 token 은 서버 하나의 공유 token 이다. fos-assistant 는 운영자가 주는 비밀 칸을 아직 받지 않는다.
- **대안 기각**:
  - 모델이 차트의 숫자나 SVG 를 인자로 넘긴다: 도구가 단순하다. 그러나 틀린 숫자가 공개 프로필에 올라가도 막을 자리가 없다.
  - GitHub 갱신만 하는 작은 커넥터로 둔다: 만들 것이 적다. 그러나 원고와 후보자 맥락을 대화에서 읽고 고치려면 같은 Backend 를 다시 감싸야 한다.
  - 커넥터용 token 을 Backend 에 따로 둔다: 커넥터가 닿는 API 를 제한할 수 있다. 그러나 Backend 인증을 고쳐야 하고 지금은 연결하는 사람이 주인 하나다. 연결하는 사람이 늘 때 정한다.
  - 계정 소개(bio)도 갱신한다: 사용자 범위의 token 권한이 필요하다. 저장소 하나의 쓰기 권한으로 끝내려고 뺀다.
- **결과**:
  - 얻는 것: 대화에서 프로필 갱신을 시작하고 승인 카드로 끝낸다. 차트와 배지의 숫자가 기록과 같다는 것을 도구가 보장한다.
  - 감당할 것: 연결할 때 Backend 의 공유 token 을 직접 넣는다. 그 token 은 Backend 의 모든 API 에 닿는다. 차트를 그리는 코드는 커넥터 쪽 TypeScript 하나만 둔다. 예약 실행이 없어 매달 사람이 대화에서 시작한다.
