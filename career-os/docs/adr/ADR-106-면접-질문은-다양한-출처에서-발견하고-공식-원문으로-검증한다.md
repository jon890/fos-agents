## ADR-106: 면접 질문은 다양한 출처에서 발견하고 공식 원문으로 검증한다

- Status: Accepted
- Date: 2026-08-27

## 맥락

공식 문서만 보면 기술 사실은 정확하지만 실제 장애, 제약과 조직 판단을 묻는 질문이 부족해진다.
반대로 기술 블로그, 발표 영상과 면접 가이드를 정답으로 사용하면 특정 사례를 보편화하거나 오래된 설명과 저작권이 있는 문답을 그대로 받아들일 위험이 있다.

## 결정

기술 블로그와 공개 발표는 실무 사례 발견에 사용하고, GitHub 면접 가이드는 질문 범위의 공백을 찾는 데만 사용한다.
최종 질문의 답변 신호와 기술 사실은 공식 문서, 표준 또는 프로젝트 문서로 다시 검증한다.
현재 직장과 경력 수준은 private brain에서 실행 시 읽고 공개 질문에는 능력 기준인 `bar`만 기록한다.

별도 질문 추천 스킬은 만들지 않는다.
질문 후보 수집, 공개 질문 보강과 답변 연습을 `interview-practice`의 서로 다른 실행 모드로 유지한다.

## 기각한 대안

- 면접 가이드의 질문과 답안을 바로 적재하는 방식은 정확성, 중복과 저작권 경계를 통제하기 어려워 기각했다.
- 공부 주제 추천 결과를 그대로 질문으로 바꾸는 방식은 읽을 가치와 면접 검증 가치가 다르므로 기각했다.
- 회사 이름으로 질문 수준을 고정하는 방식은 같은 회사 안에서도 역할과 책임이 다르므로 기각했다.

## 결과

다양한 실제 사례를 계속 수집하면서도 공개 질문 은행의 정답 기준과 개인 정보 경계를 유지할 수 있다.
후보 수집 실패는 기존 질문 연습을 막지 않으며, 공식 근거를 확인하지 못한 후보는 질문으로 승격하지 않는다.
