## ADR-131: 후보자 맥락은 Backend 문서로 두고 공부 추천 기준 버전을 문서 버전에서 계산한다

- **status**: `accepted`
- **결정**:
  - 스킬이 판단에 쓰는 개인 맥락을 `fos_career` 의 후보자 맥락 문서로 둔다. 문서 키마다 Markdown 본문과 `version` 을 한 행에 두고, 저장할 때마다 이력 행을 하나 더한다.
  - 문서 키는 `learning-interests`, `position-preferences`, `application-state`, `career-status` 넷으로 고정한다. 연락처와 신원 같은 지원서 공통 프로필은 문서 키에 넣지 않는다.
  - 공부 추천의 후보자 기준 버전은 `learning-interests` 문서의 버전에서 `learning-interests:v{version}` 으로 계산한다. 사람이 따로 올리는 값을 두지 않는다.
  - 후보 조회 응답이 그 문서의 본문과 버전을 함께 돌려준다.
- **대체된 부분**: [ADR-127](ADR-127-공부-추천은-고르지-않은-후보의-판정을-재사용한다.md)의 「관심사가 바뀌면 사람이 `study_recommendation_control.candidate_context_version` 을 올린다」 를 대체한다. 판정을 기준 버전과 유효기간으로 재사용한다는 나머지는 그대로다.
- **맥락**:
  - 학습 관심사가 네 곳에 서로 다르게 적혀 있었다. private brain 의 관심사 페이지는 에이전트 하네스를 최근 강한 관심으로 적었고, 스킬 본문은 백엔드 중심을 목표로 적었다. 제품 문서와 흐름 문서는 분야 없이 「현재 업무, 목표 역할, 엔지니어링 판단 또는 제품·사업 관점」 만 적었다. 모델은 스킬 본문을 먼저 따랐다.
  - 관심사를 고치는 일과 기준 버전을 올리는 일이 서로 다른 곳에서 일어났다. 버전을 올리지 않으면 예전 관심사로 제외한 자료가 30일 동안 다시 나오지 않는다.
  - 공부 추천의 소스, 자료, 추천 이력과 제외 판정은 이미 Backend 가 소유한다. 판단 기준만 스킬 밖의 개인 지식 기반에 있었다.
  - [ADR-123](ADR-123-회사-근거와-개인-제외-정책은-backend가-소유한다.md) 이 같은 이유로 포지션 개인 제외 규칙을 Backend 로 옮겼다. 같은 사실이 두 곳에 있으면 어느 쪽이 최신인지 판정할 수 없다.
- **대안 기각**:
  - 문서 키마다 칸을 나눈 전용 table 은 기각했다. 이 값을 읽는 쪽은 스크립트가 아니라 모델이다. 경험 경계처럼 「여기까지다」 를 문장으로 적는 내용은 칸에 맞지 않고, 항목이 바뀔 때마다 migration 이 필요하다. 스크립트가 계산하는 재지원 간격은 이미 `position_exclusions.expires_at` 에 있다.
  - 문서를 저장할 때 `study_recommendation_control` 행도 같은 transaction 에서 갱신하는 안은 기각했다. 후보자 맥락 module 이 공부 추천 table 에 직접 쓰게 되고, 수동 명령도 남아 두 경로가 같은 값을 바꾼다.
  - 스킬이 문서를 별도 명령으로 조회하는 안은 기각했다. 후보 조회와 문서 조회 사이에 관심사가 바뀌면 추천 저장이 `409` 로 거부된다. 후보 응답에 넣으면 본문과 버전이 한 응답에서 나온다.
  - 지원서 공통 프로필까지 옮기는 안은 기각했다. 지원서를 쓸 때만 필요하고 거의 바뀌지 않는다. 연락처와 신원이 홈서버 MySQL 과 그 backup 에 복제되는 위험이 이득보다 크다.
- **결과**:
  - 얻는 것: 관심사를 저장하면 다음 후보 조회부터 새 기준 버전이 적용되고 예전 판정이 조회에서 빠진다. 스킬 본문과 제품 문서는 분야를 적지 않고 문서 키를 가리킨다. 이력 행으로 어느 추천 실행이 어떤 관심사로 판단했는지 되짚을 수 있다.
  - 감당할 것: `learning-interests` 문서가 없으면 후보 조회가 `409 CANDIDATE_CONTEXT_MISSING` 으로 멈춘다. 배포 뒤 첫 추천 전에 문서를 저장해야 한다. 판정만 초기화하려 해도 본문을 고쳐 저장해야 한다. 관심사를 편집기로 열어 고치던 방식이 CLI 로 바뀐다. 개인 지식 기반의 링크와 출처 관리 기능은 이 문서에 없다.
- **적용 범위**: `services/career-backend/src/candidate-context/`, `services/career-backend/src/study/`, `scripts/candidate-context/`, `scripts/study-topic-recommender/`, `.claude/skills/study-topic-recommender/`, `docs/prd.md`, `docs/flow.md`, `docs/data-schema.md`, `docs/code-architecture.md`. 나머지 세 문서 키를 읽는 스킬의 전환은 별도로 다룬다. [ADR-130](ADR-130-면접-연습의-후보자-맥락은-memory-공급자-경계로-읽는다.md) 의 면접 연습 계약은 이 결정이 바꾸지 않는다.
