# 기술 사용과 운영 깊이를 분리해 검증한다

## 상태

Accepted

## 배경

Kotlin 코드베이스와 후보자의 기능 커밋이 확인된다는 이유로 Kotlin을 주력 기술로 분류하고 전체 백엔드 경력 기간에 적용했다.
코드 기여는 기능 개발 사실을 뒷받침하지만, 언어 고유의 장애 대응, 성능 분석과 운영 노하우까지 자동으로 증명하지 않는다.
기존 근거 원장은 구현, 소유권과 결과만 나눠 이런 차이를 표현하지 못했다.

## 결정

- 기술 관련 주장에는 사용, 기능 개발, 운영 깊이와 사용자 확인을 구분하는 `experienceDepth`를 기록한다.
- 하나의 경력 기간을 여러 기술에 함께 적용하지 않고 기술별 기간을 독립적으로 확인한다.
- 코드와 Git 이력만 있으면 사용 또는 기능 개발까지만 확인한다.
- 운영, 숙련, 주력과 노하우 표현에는 장애, 배포, 성능, 관측, 운영 결정 또는 구체적인 사용자 확인이 필요하다.
- 로컬 근거로 경험 깊이를 확정할 수 없으면 `ask_user`로 판정하고 한 번에 한 질문만 확인한다.
- `soften`, `ask_user`, `remove`가 남은 근거 원장은 최종 평가를 통과하지 못한다.

## 결과

기술 목록이 저장소의 언어 목록을 그대로 복제하지 않는다.
사용자는 애매한 경험만 추가로 확인하며, 확인되지 않은 숙련도는 제출 문장에서 제거된다.
