# career-os 제품 요구사항

career-os는 커리어 탐색부터 지원 준비, 면접 연습, 기술 학습까지 이어지는 개인 운영 도구다.

이 문서는 각 스킬이 **무엇을 약속하고 무엇은 하지 않는지**, 그리고 **무엇을 관측하면 약속이 지켜진 것인지**를 담는다.
어떤 순서로 도는지는 [`flow.md`](flow.md), 무엇을 저장하는지는 [`data-schema.md`](data-schema.md),
코드가 어디 있는지는 [`code-architecture.md`](code-architecture.md)가 담는다.

## 공통

### 사용자 문제

채용 공고, 경력 근거, 지원 문서, 면접 준비 자료가 흩어지면 판단과 개선이 반복되지 않는다.
career-os는 외부 자료를 수집하고 사용자의 실제 이력과 대조해 다음 행동을 정할 수 있게 한다.

### 제품 약속

- 실제로 열린 개별 공고만 추천 후보로 다룬다.
- 추천과 이력서의 주장은 확인 가능한 경력과 작업 근거에 연결한다.
- 동기, 본인 판단, 기각한 대안과 설명 가능성처럼 사람만 확정할 수 있는 내용은 사용자에게 돌려주고 답변 준비까지 연결한다.
- 마감 여부, 중복, 명시적 제외처럼 결정적으로 판정할 수 있는 조건은 코드로 처리한다.
- 공고 적합도와 읽을거리의 최종 선별은 모델이 맥락을 보고 판단한다.
- 사용자가 보는 분석 결과는 공개 범위를 점검한 HTML 리포트로 제공한다.
- 여러 실행 환경에서 만든 비공개 지원 자료는 다음 실행이 같은 현재 revision으로 이어받는다.
- 지원서 제출, 로그인, 메시지 전송, 공개 게시처럼 외부 상태를 바꾸는 작업은 사용자 승인 뒤에 수행한다.

### 성공 기준

- 게시 리포트에는 공개 가능한 정보만 포함되며 URL이 실제로 열린다.
- 비공개 지원 자료를 쓰는 스킬은 홈서버 revision과 로컬 변경 상태를 확인한 뒤 실행한다.
- 다른 환경이 먼저 새 revision을 반영했으면 로컬 결과를 보존하고 덮어쓰지 않는다.

### 제품 경계

- 채용 플랫폼 계정과 지원서 제출을 자동으로 조작하지 않는다.
- 개인 경력과 지원 전략을 공개 리포트에 그대로 싣지 않는다.
- 외부 자료 없이 학습 주제나 채용 공고를 만들어내지 않는다.
- 기능 사용법만 나열한 문서와 전이할 판단이 없는 발표·홍보 자료를 최신성만으로 추천하지 않는다.
- 지원 문서와 면접 자료는 파일 기반 운영을 유지한다.
  포지션과 학습자료의 수집·분석·추천 상태는 예외로 HTTP API와 MySQL을 사용한다.
- 캐시, 임시 공개 리포트, token과 개인키를 실행 환경 사이의 작업 원본으로 동기화하지 않는다.
- 실행 이력과 완료 작업을 제품 문서에 계속 쌓지 않는다.

## application-package-writer

### 약속

공고가 찾는 사람과 후보자의 경험, 이력과 방향성이 부합하는지 판정하는 일을 첫 목표로 삼는다.
공고 항목을 컴포넌트 단위로 쪼개 판정하고 가중 점수로 적합도를 표시하며,
**부합하지 않는다는 판정도 결론으로 남긴다.**

그 판정 위에서 후보자 인터뷰, 지원 전략과 면접 검증 포인트를 준비한다.
전체 지원 요청에서는 이 결과를 `resume-preparer`로 이어 사용자가 실행 순서를 다시 판단하지 않게 한다.

사용자는 하나의 로컬 `application-package.html`에서 승부처, 공백, 지원동기와 다음 행동을 확인한다.

### 성공 기준

- 지원 브리프는 회사·포지션 기준, 후보자 근거, 준비 상태와 다음 행동을 함께 제공한다.
- 공고의 모든 항목이 적합도 표에 오르고, 각 항목에 근거와 판정이 있다.
- 적합도 총점과 구분별 소계를 한 화면에서 색으로 구분해 확인할 수 있다.
- 총점을 합격 확률로 표시하지 않는다.

## interview-practice

### 약속

기술·인성·포지션별 질문을 준비하고 사용자가 먼저 답한 내용을 채점해 복습 상태에 반영한다.
등록된 기술 블로그, 공개 영상과 GitHub 가이드에서 질문 후보를 수집하고,
공식 원문으로 기술 사실을 검증해 부족한 영역을 보강한다.

회사 서열이 아니라 문제 규모와 책임 수준으로 질문 난도와 꼬리질문 깊이를 정한다.

대표 경험 설명과 꼬리질문 연습이 이 스킬의 몫이다. 이력서 문구는 `resume-preparer`가 소유한다.

### 성공 기준

- 면접 답변 연습은 복습 대상을 누적하고 다음 실행에서 활용한다.
- 면접 질문은 포지션 질문과 공통 기반을 함께 포함한다.
- 답변에 따라 판단, 반례, 운영과 근거 경계까지 깊어진다.

### 제품 경계

- 공개 가능한 일반 질문 수집은 필요할 때만 내부 유지보수 절차로 실행한다.
- 포지션 질문과 개인 답변을 공개 질문 은행에 넣지 않는다.

## position-recommender

### 약속

등록된 채용 소스에서 공고를 수집하고, 후보자가 해온 일과 선호에 얼마나 맞는지 판단해
재사용 가능한 공고 분석과 대기·수집 경고를 담은 리포트를 만든다.

닫힌 공고와 개인 제외 대상은 모델에 넣기 전에 제거한다.
유효한 과거 분석은 다시 분석하지 않는다.
**아직 분석하지 않은 공고는 억지로 순위를 매기지 않고 분석 대기로 표시한다.**

**회사는 세 축으로 각각 판정한다.** 기술적으로 성장할 수 있는가,
팀이 커지고 있는가, 보상과 복지가 적절한가다.
셋을 한 값으로 합치지 않는다. 배울 것이 많지만 보상이 낮은 회사와 그 반대를 갈라 보여준다.

판정은 공개 자료에서 모은 근거 위에서만 한다.
**근거가 없는 축은 지어내지 않고 「근거 없음」으로 남긴다.**
현재 직장도 같은 방식으로 판정해 비교의 기준으로 쓴다.

현재 지원 대상과 회사별 지원 판단은 private brain에서 확인하고,
공고별 실행 자료는 대응하는 `applications/` 디렉터리에서 관리한다.

### 성공 기준

- 추천 공고에 원문 URL, 활성 상태, 추천 근거가 있다.
- 종료되거나 지원 기한이 지난 공고가 추천 결과에 포함되지 않는다.
- 개인 제외 회사의 공고는 모델 입력과 추천 결과에 포함되지 않는다.
- 같은 공고의 본문, 후보자 기준 버전과 분석 규칙이 같으면 이전 분석을 재사용한다.
- 매일 분석할 공고 수가 비공개 정책의 상한을 넘지 않는다.
- 분석하지 않은 활성 공고와 부분 실패한 수집 소스를 추천 화면에서 구분해 확인할 수 있다.
- 회사마다 세 축의 판정과 각 축의 근거를 추천 화면에서 확인할 수 있다.
- 근거가 없는 축이 낮은 평가가 아니라 「근거 없음」으로 구분돼 보인다.
- 현재 직장의 1인 평균 급여와 평균 근속연수가 후보 회사와 같은 출처에서 나온다.
- skill이 실행 절차 대신 무엇을 판단해야 하는지를 적는다.

## resume-preparer

### 약속

이력서와 경력기술서를 작성하고, 사람 확인, 주장 근거 감사, 인사담당자와 실무담당자 리뷰,
HTML·PDF 렌더링과 제출 묶음 검증을 한 흐름에서 수행한다.

**이미 검증한 주장은 문구와 근거 파일이 모두 같을 때 이전 판정을 재사용한다.**
재사용 판정은 모델에 전체 이력과 근거를 전달하기 전에 코드로 수행하며,
어떤 근거가 바뀌어 다시 읽어야 하는지 출력한다.

모든 제출 문서는 추상적인 표현보다 실제 제품, 문제, 수행한 작업과 확인한 결과를 먼저 보여준다.
초안을 사용자에게 보여주기 전에 외부 문장을 전수 검사하며,
제품 전체의 경험과 한 기능의 사례를 구분하고 같은 경험의 범위를 모든 제출 문서에서 일치시킨다.

경력, 역할 선호와 경험 경계는 brain에서 필요한 시점에 조회하고,
사용자 정정으로 새로 확인한 개인 지식은 기존 brain 환원 절차로 연결한다.
다른 공고에서도 같은 작성 취향을 적용하되, 제출 문구와 수치는 해당 지원의 근거로 확정한다.

### 성공 기준

- 이력서 핵심 주장마다 확인 가능한 근거와 소유권 범위가 있다.
- 이전에 검증한 주장과 근거 파일이 같으면 다시 감사하지 않고, 변경된 항목만 재검증 대상으로 남는다.
- 검증 장부 검색 결과에서 주장 문구, 근거 경로, locator와 현재 근거 상태를 확인할 수 있다.
- 제출 문구를 바꿀 사람 확인 항목이 남으면 준비 완료로 판정하지 않는다.
- 제출 문서, 근거 원장과 검토표의 문구 해시가 모두 같은 버전이다.
- 사실 감사와 설득력 평가가 서로 다른 기준을 유지한다.

## study-topic-recommender

### 약속

회사 기술 블로그, 개발 동향과 공개 영상 소스를 수집한다.
고정 주제를 생성하지 않고, 수집한 외부 글과 영상 중
사용자의 현재 업무와 다음 커리어에 적용할 판단을 얻을 수 있는 자료만 선별한다.

선별한 자료는 공부 주제별로 묶고, 이전에 추천한 같은 글과 영상은 다시 추천하지 않는다.
직전 리포트와 같은 공부 주제도 다음 리포트에서 반복하지 않는다.

**수집한 자료는 누적해 보관하고 이미 모은 것은 다시 모으지 않는다.**
**고르지 않은 자료는 사용자의 관심사 기준이 바뀌기 전까지 다시 판단하지 않는다.**
소스와 자료와 추천 이력은 `fos_career` 에 두고 파일에 두지 않는다.

### 성공 기준

- 읽을거리 리포트가 공부 주제, 커리어에 연결할 질문, 외부 자료의 제목, 출처, 요약과 추천 이유를 제공한다.
- 이전에 추천한 같은 글과 영상이 다음 실행의 선별 결과에 포함되지 않는다.
- 직전 리포트와 같은 공부 주제가 다음 리포트의 선별 결과에 포함되지 않는다.
- 공식 자료나 최신 소식이어도 사용자의 현재 업무, 목표 역할, 엔지니어링 판단 또는
  제품·사업 관점에 구체적으로 연결되지 않으면 추천하지 않는다.
- 전날 고르지 않은 자료가 기준 버전이 같고 유효기간이 남았으면 다음 날 후보에 나오지 않는다.
- 사람이 소스를 끄면 다음 실행부터 그 소스를 수집하지 않는다. 커밋과 배포가 필요 없다.
- Backend 가 응답하지 않으면 실행이 파일로 물러서지 않고 멈춘다.
- 홈서버의 `morning` 작업이 이 경로로 매일 돈다.

### 아직 만들지 않은 것

**PC 와 모바일에서 같은 즐겨찾기, 읽음 상태, 개인 메모로 자료를 다시 찾는다.**
아래는 합의한 요구사항이며 현재 동작을 뜻하지 않는다.
누적 보관과 과거 자료 수집은 이미 있다. 그것을 사람이 찾아보는 화면과 개인 상태가 없다.

| 사용자 행동 | 필요한 동작 |
| --- | --- |
| 오래된 좋은 글 찾기 | 누적 자료를 검색하는 화면 |
| 나중에 다시 보기 | 자료에 별표를 추가·해제하고 즐겨찾기 목록에서 조회한다 |
| 학습 완료 기록 | 읽음 상태를 변경하며, 추천 여부·별표와 독립적으로 유지한다 |
| 내 생각 남기기 | 자료별 개인 메모를 저장하고 다른 기기에서도 조회·수정한다 |
| 기기를 바꿔 사용 | PC와 모바일이 같은 서버 상태를 조회하고 변경한다 |

화면은 전체 자료, 오늘 추천, 즐겨찾기와 읽은 자료를 구분한다.
글과 영상, 주제와 출처를 필터링하고 원문을 열 수 있어야 한다.
재수집으로 자료 정보가 갱신돼도 사용자가 남긴 별표·읽음 상태·메모는 보존한다.

접근 제어는 블로그의 공통 관리자 로그인을 재사용한다.
Better Auth의 GitHub 로그인을 쓰고, 서버에 등록한 본인 GitHub 고유 ID만 허용한다.

## sync-profile

### 약속

원티드, LinkedIn, GitHub 프로필을 이력서 원고 기준으로 갱신한다.

**프로필은 여러 회사가 상시로 본다.** 한 회사에 내는 지원본과 노출 범위가 다르므로,
같은 문장이라도 지원본에서는 맞고 프로필에서는 과할 수 있다.
그래서 대상별 원고를 따로 두고 공개 범위를 조정한 문장만 올린다.

**세 곳은 저장 방식이 서로 달라 확인하는 방법도 다르다.** 이것이 이 스킬이 존재하는 이유다.
화면에 값이 보이는 것으로는 반영됐는지 알 수 없다.

### 성공 기준

- 올린 문장이 이력서 원고에 있는 문장이다. 새로 지어낸 문장이 없다.
- 반영한 내용이 서버에서 다시 조회했을 때 그대로 있다.
- 세 곳 중 고치지 않은 곳도 원본과 어긋난 지점이 보고에 남는다.

### 제품 경계

- 사용자 승인 없이 외부 프로필을 바꾸지 않는다.
- 지원본에만 쓰는 문구와 수치를 프로필에 그대로 올리지 않는다.
