# 영역 고르기

4단계에서 읽는다. 1단계에서는 「사용자 반응」 절만 읽는다.

## 쓰는 값

| 값 | 어디서 |
| --- | --- |
| 지난 살펴보기 시각 | 입력의 변화 신호. `처음` 이면 첫 살펴보기다 |
| 사용자 메시지 수와 Memory 문맥이 같은지 | 입력의 변화 신호 |
| 최근에 알린 발견 | 입력. 영역, 주제 키, 원문 주소, 확인 날짜 |
| 지속적인 선호와 거절 | Memory 문맥 |
| 사용자 반응 | 점검 대화의 앞 내용 |
| 지난번 맥락 읽기의 답 | 점검 대화의 앞 내용에서 `sourceFailures` 가 빈 결과 블록을 남긴 살펴보기 가운데 가장 최근 것의 3단계 위임 답 |
| 네 문서의 본문과 `version` | 이번 3단계 위임의 답 |
| 공부 후보와 `recentStudyTopicKeys` | 이번 3단계 위임의 답 |

「바뀌었다」 는 문서의 `version` 이 지난번 맥락 읽기의 답에 적힌 값보다 크다는 뜻이다.
「새 후보」 는 지난번 맥락 읽기의 답에 없던 공부 후보다.
지난번 맥락 읽기의 답을 찾지 못하면 모든 문서를 바뀐 것으로, 모든 후보를 새 후보로 본다. session 이 바뀌었거나 첫 살펴보기일 때다.

맥락을 읽은 뒤 실패한 살펴보기의 위임 답은 기준으로 삼지 않는다. 결과 블록이 없거나 `sourceFailures` 가 남은 살펴보기가 여기 든다.
그런 살펴보기가 가장 최근이면 건너뛰고, 그 앞에서 `sourceFailures` 가 빈 결과 블록을 남긴 살펴보기의 답까지 거슬러 올라가 견준다.
그 답을 기준으로 삼으면 version 이 이미 같아져 「바뀌었다」 가 거짓이 되고, 실패한 살펴보기가 알리려던 발견을 다시 찾지 않는다.

기준을 지난 살펴보기 시각으로 두지 않는다. 2단계에서 바로 침묵한 살펴보기도 지난 살펴보기가 되므로, 그 사이에 바뀐 문서를 놓친다.

**영역마다 「고르지 않는 조건」 을 먼저 본다.** 하나라도 참이면 고르는 조건이 참이어도 고르지 않는다.
**한 주제는 한 영역에서만 본다.** `study` 로 고른 기술을 `trend` 로 다시 고르지 않는다.

## 사용자 반응

점검 대화의 반응과 Memory 문맥에 적힌 선호에 같은 규칙을 쓴다.
session 이 바뀌어 점검 대화에 근거가 없으면 Memory 문맥만 본다.

| 본 것 | 이번 살펴보기에서 하는 일 |
| --- | --- |
| 지난 발견을 받아들였다. 「읽어 볼게요」, 「할 일로 둘게요」 | 같은 주제 키는 새 원문이고 `changeSinceLast` 를 적을 때만 다시 낸다 |
| 지난 발견을 거절했다. 「관심 없어요」, 「이미 알아요」 | 그 주제 키를 30일 동안 내지 않는다. 사용자가 먼저 다시 꺼내면 예외다 |
| 관심 범위를 줄였다. 「포지션은 당분간 빼 주세요」, 「Kafka 만 봐 주세요」 | 그 말이 가리키는 영역이나 주제 밖은 고르지 않는다. 사용자가 다시 넓히기 전까지 지킨다 |
| 한 영역을 이번에는 원하지 않는다고 했다. 「이번엔 공부거리는 괜찮아요」 | 그 말 뒤 첫 살펴보기에서 그 영역을 고르지 않는다 |
| 무언가를 물었다. 「결제 도메인 공고가 궁금해요」 | 그 물음에 맞는 영역을 먼저 고른다 |
| 답하지 않았다. 메시지 수가 `0개` 다 | 선호나 거절로 읽지 않는다. 같은 발견을 다시 내지 않는 것만 지킨다 |

지속적인 선호로 보이는 말이 Memory 문맥에 없으면 6단계에서 `questions` 로 기억해 둘지 묻는다.

## study

아래 가운데 하나라도 참이면 고른다.

- 새 후보 가운데 `learning-interests` 의 우선 주제에 맞고, 그 주제가 최근에 알린 발견과 `recentStudyTopicKeys` 에 없다
- `learning-interests` 가 바뀌었다
- `career-status` 나 `application-state` 가 가까운 일정에 필요한 기술을 적고 있고 그 기술의 발견을 최근에 알리지 않았다. 새 업무, 면접 예정, 발표 같은 일정이 여기 든다
- 사용자가 점검 대화에서 공부거리를 물었다

아래 가운데 하나라도 참이면 고르지 않는다.

- 사용자가 공부 추천을 빼 달라고 했거나, 이번에는 괜찮다고 한 뒤 첫 살펴보기다
- 고를 이유가 새 후보뿐인데 그 후보의 주제가 모두 최근에 알렸거나 거절한 주제다
- 관심사 문서가 없다(`learning_interests_missing`)

## position

아래 가운데 하나라도 참이면 고른다.

- `application-state` 나 `position-preferences` 가 지금 지원할 곳을 찾고 있다고 적고, 둘 중 하나가 바뀌었다
- 지원할 곳을 찾고 있고, 최근에 알린 `position` 발견이 없거나 가장 최근 것이 7일보다 오래됐다
- 사용자가 점검 대화에서 공고나 회사를 물었다

아래 가운데 하나라도 참이면 고르지 않는다.

- `application-state` 가 이직 보류나 탐색 중단을 적고 있고, 사용자가 점검 대화에서 공고를 묻지 않았다
- 사용자가 포지션 알림을 빼 달라고 했거나, 이번에는 괜찮다고 한 뒤 첫 살펴보기다

## trend

아래 가운데 하나라도 참이면 고른다. 「지켜볼 항목」 은 문서나 대화에 「동향」, 「지켜볼」, 「변화를 알려 달라」 처럼 명시된 기술이나 분야다. 공부 우선 주제는 지켜볼 항목이 아니다.

- 사용자가 점검 대화에서 어떤 기술이나 분야의 변화를 알려 달라고 했고, 그 주제의 `trend` 발견을 7일 안에 알리지 않았다
- `learning-interests` 나 `position-preferences` 가 바뀌었고, 바뀐 부분에 지켜볼 항목이 새로 생겼다
- 첫 살펴보기이고 `learning-interests` 에 지켜볼 항목이 있다

아래 가운데 하나라도 참이면 고르지 않는다.

- 사용자가 동향 알림을 빼 달라고 했거나, 이번에는 괜찮다고 한 뒤 첫 살펴보기다
- 고를 이유가 「새로 공부하기 시작한 기술」 뿐이다. 그것은 `study` 의 이유다
- 이 사용자의 일이나 학습에 미칠 영향을 적을 수 없는 일반적인 업계 소식이다

## 고를 영역이 없을 때

조사하지 않고 `NOTHING_NEW` 로 끝낸다.
3단계에서 커리어 맥락을 읽지 못해 고를 수 없을 때는 `references/result-block.md` 의 「맥락을 읽지 못했을 때」 를 따른다.
