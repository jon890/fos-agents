# RFP 대조 기준

## 구현 범위

다음 항목을 공고 요약이 아닌 원문 기준으로 대조한다.

- 기존 UI와 프런트 호출 제약
- 데이터 모델과 공개 API
- 고객 접수와 개인정보 노출 조건
- 파일 업로드, 다운로드, 삭제, 정리
- 관리자 인증, CRUD, CMS, 동기화
- 알림, 이력, fallback, 운영자 알림
- 보안, 동시성, 성능, 장애 대응
- QA, 산출물, 인계, 하자보수

## 운영 한계

초기 납품을 영구적 성능 보장으로 표현하지 않는다.

다음 성장 신호를 제안서에 기록한다.

- 주문과 관리자 조회가 늘어나는 경우
- 첨부 파일 용량과 업로드 실패가 늘어나는 경우
- 알림 발송 실패율과 메시지 비용이 늘어나는 경우
- 동시 관리자 작업과 고객 접수가 겹치는 경우
- 응답 시간, 오류율, 재시도, 저장소 비용이 임계치에 가까워지는 경우

각 신호에 대해 현재 구현의 보호 장치와 이후 고도화 방향을 구분한다.
예를 들어 초기에는 페이지네이션·지연 로딩·rate limit·로그를 적용하고, 증가 후에는 인덱스·캐시·비동기 큐·보관 정책·모니터링 경보를 추가한다.

## 견적 경계

초기 구축 견적에는 명시된 요구사항과 기본 관측·오류 대응만 포함한다.
새 기능, 예측하지 못한 대규모 트래픽 대응, 상시 장애 대응, 월 유지보수는 별도 계약으로 분리한다.
