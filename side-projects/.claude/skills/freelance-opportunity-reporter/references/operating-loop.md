# 외주 기회 운영 루프

이 문서는 외주 공고 리포트를 한 번 만들고 끝내지 않기 위해 사용한다.
목표는 반복 가능한 작은 루프로 실제 지원, 회신, 수익까지 이어지게 만드는 것이다.

## 기본 주기

초기에는 주 2회 운영한다.

- 1회차: 월요일 또는 화요일에 새 공고를 수집한다.
- 2회차: 목요일 또는 금요일에 새 공고와 회신 상태를 점검한다.
- 바쁜 주에는 주 1회로 줄이되, 기록 형식은 유지한다.

## 루프 단계

| 단계 | 목표 | 산출물 |
| --- | --- | --- |
| 수집 | 위시켓, 프리모아, 원티드 긱스에서 공고 ID를 모은다 | 원자료 JSON, 출처 URL, 수집 건수 |
| 완전성 검사 | 표시된 전체 건수와 고유 공고 ID 수를 비교한다 | 누락 수, 중복 수, 실패 지점 |
| 원격 필터 | 상주, 반상주, 현장 테스트를 제거한다 | `remote_only_pass` 판단 |
| 상세 확인 | 상세 링크와 로그인 필요 여부를 확인한다 | 상세 URL, 근거 메모 |
| 분류 | 첫 수주와 일반 수익성 관점에서 지원, 확인, 거절로 나눈다 | 점수표, 최종 판단 |
| 선택 | 이번 회차에 실제로 할 지원 행동을 고른다 | 지원 후보 1-2개 |
| 자산 작성 | 지원문과 질문을 만든다 | 메시지 초안 |
| 실행 | 사용자가 확인한 뒤 지원한다 | 발송 기록 |
| 회고 | 회신, 미팅, 거절, 가격 반응을 기록한다 | 다음 회차 개선 메모 |

## 중단 기준

아래 조건은 한 가지만 있어도 해당 후보를 멈춘다.

- 완전 원격 진행을 확인할 수 없다.
- 정기 출근, 상주, 반상주, 파견, 현장 테스트가 필요하다.
- 상세 URL을 확보하지 못했고 목록 요약만으로 판단해야 한다.
- 로그인 후 상세 확인이 필요한데 계정 접근이 없다.
- 예산이 낮고 수정 범위가 넓다.
- 결제, 의료, 금융, 신원 인증, 보안 핵심 로직이 중심이다.

## 기록할 지표

매 회차 아래 숫자를 남긴다.

- 수집한 공고 수
- 플랫폼 표시 건수와 수집 누락 수
- 이전 회차 이후 새로 발견한 공고 수
- `remote_only_pass`를 통과한 공고 수
- 상세 링크를 확인한 공고 수
- 첫 수주 후보 수
- 지원 후보 수
- 작성한 지원문 수
- 발송한 지원 수
- 받은 회신 수
- 미팅 전환 수
- 실제 수익 또는 예상 수익
- 투입 시간

## 이번 회차 선택 기준

초기에는 한 번에 많은 일을 벌리지 않는다.
회차마다 하나의 주력 행동만 정한다.

외주 이력이 0회이면 아래 순서로 둔다.

1. 1-14일 안에 끝나고 납품물과 검수 기준이 명확한 첫 수주 후보를 확인한다.
2. 원격과 수정 범위를 고정할 수 있으면 첫 수주 후보에 지원한다.
3. 일반 수익성 후보는 첫 수주 후보와 별도로 유지한다.
4. 경쟁이 높거나 범위가 넓은 공고는 지원하지 않고 사유만 기록한다.
5. 로그인이나 계정이 필요한 상세 검증은 사용자와 접근 가능 여부를 확인한 뒤 진행한다.

## 리포트에 포함할 운영 섹션

리포트 끝에는 아래 세 섹션을 넣는다.

- `운영 루프`: 반복 주기와 단계별 산출물을 적는다.
- `이번 회차 액션`: 이번에 실제로 할 1-3개 작업을 적는다.
- `의논할 결정`: 계정, 우선순위처럼 사용자 판단이 필요한 것을 적는다.
