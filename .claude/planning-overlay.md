# planning 오버레이

공용 `planning` 절차에 fos-agents의 모노레포 경계만 추가한다.

## 설계 경계

- 작업할 워크스페이스의 `AGENTS.md`와 책임 문서를 먼저 읽는다.
- 다른 워크스페이스의 코드와 데이터를 교차 참조하지 않는다.
- 반복 실행은 스크립트, 판단과 안전 경계는 스킬에 둔다.
- 설정에는 사람이 유지할 정책과 입력만 두고 수집 결과나 현재 외부 목록을 고정하지 않는다.
- 스킬 간 연결은 특정 에이전트 CLI 대신 의도와 입력 계약으로 표현한다.

## 문서 책임

| 변경 | 단일 출처 |
|---|---|
| 제품 범위와 성공 기준 | `<workspace>/docs/prd.md` |
| 데이터, 상태와 산출물 | `<workspace>/docs/data-schema.md` |
| 사용자·실행 흐름 | `<workspace>/docs/flow.md` |
| 디렉터리와 구현 책임 | `<workspace>/docs/code-architecture.md` |
| 코드로 자명하지 않은 장기 결정 | `<workspace>/docs/adr/` |

존재하지 않는 문서는 만들 필요가 있을 때만 추가한다. 같은 설명을 여러 문서에 복제하지 않는다.

ADR은 대안 선택의 이유가 이후 변경에도 영향을 줄 때만 만든다. 단순 파일 추가, 필드 변경, 중복 제거와 버그 수정은 책임 문서와 커밋으로 충분하다.

## task 작성

- path는 저장소 루트 기준으로 명확하게 적는다.
- phase마다 수정 책임, 검증 명령, 완료 조건과 외부 상태 변경 경계를 둔다.
- plan과 ADR 번호는 해당 워크스페이스의 실제 파일을 확인해 충돌을 피한다.
- branch, commit, push, 실행 세션과 모델은 계획에 고정하지 않고 현재 저장소 정책과 실행 환경이 결정한다.

공용 task 스키마와 충돌하는 저장소 전용 필드는 만들지 않는다. 기존 task 형식을 바꿔야 할 때는 실제 소비 코드를 먼저 확인한다.
