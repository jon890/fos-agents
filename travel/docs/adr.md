## ADR-001 — travel은 문서 중심의 선택적 구조를 사용한다

- Status: Accepted
- Date: 2026-05-20

### 맥락

travel은 여행별 일정, 예약, 선택 사항을 문서로 관리한다.
상시 자동화가 없는 상태에서 다른 워크스페이스의 전체 구조를 복제하면 빈 디렉터리만 늘어난다.

### 결정

- 여행별 자료는 `trips/<trip-id>/` 아래에 둔다.
- 공통 제품 설명과 데이터 경계는 workspace `README.md`와 `docs/`가 담당한다.
- 자동화가 생길 때만 `scripts/`, `config/`, agent skill을 추가한다.
- 실행 환경 값이 필요할 때만 `.env`를 사용하고 공개 키 목록은 `.env.example`에 둔다.
- 예약 정보와 개인 일정은 공개 문서와 외부 리포트에 자동으로 포함하지 않는다.

### 거절한 대안

- 모든 표준 디렉터리를 미리 만들면 현재 책임을 설명하지 못하는 빈 구조가 생긴다.
- 여행별로 별도 워크스페이스를 만들면 공통 규칙과 인덱스가 반복된다.

### 결과

현재는 문서 중심으로 작게 유지하고 실제 자동화 요구가 생길 때 구조를 확장할 수 있다.
