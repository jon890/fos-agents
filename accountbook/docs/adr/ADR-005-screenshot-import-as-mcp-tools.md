## ADR-005: 화면 가져오기는 MCP 도구로 합치고 파일 상태를 두지 않는다

- Status: Accepted
- Date: 2026-10-01

### 맥락

토스 화면 가져오기는 셸로 실행하는 스크립트와 비공개 상태 파일에 의존했다.
fos-assistant의 가계부 전용 에이전트는 셸과 파일 쓰기 도구 없이 MCP 도구만 쓰므로([ADR-004](ADR-004-mcp-connector-plugin.md)) 그 흐름을 실행할 수 없었다.
주간 자동 등록과 Discord 접수는 같은 스크립트 위에 얹은 별도 입력 경로였고, 1단계에 필요한 것은 스크린샷 한 장이 가계부에 등록되는 흐름 하나다.

### 결정

- 화면 가져오기의 결정적 검증과 등록을 plugin의 MCP 도구 `preview_screenshot_import`, `submit_screenshot_import`로 옮긴다.
- 절차는 단일 `accountbook-api` 스킬의 한 절로 둔다.
- MCP 서버는 파일 상태를 만들지 않는다.
  사용자 확인은 추출 내용의 해시인 묶음 ID로 묶고, 재등록은 등록 직전의 기존 기록 대조로 막는다.
- 셸 기반 화면 가져오기 스킬과 스크립트, 주간 자동 등록, Discord 접수를 제거한다.
  [ADR-002](ADR-002-weekly-safe-policy-auto-submission.md)와 [ADR-003](ADR-003-hermes-discord-image-input.md)을 대체한다.

### 거절한 대안

- 전용 에이전트에 셸과 파일 도구를 여는 방식은 토큰을 가진 profile의 권한을 넓힌다.
- MCP 서버가 이미지 파일을 직접 읽어 해시를 만드는 방식은 토큰을 가진 프로세스에 파일 읽기 경로와 운영 설정을 더한다.
- 상태 파일로 후보별 전송 상태를 남기는 방식은 profile별 비공개 루트를 운영 환경이 다시 나눠야 한다.
- 화면 가져오기를 별도 스킬로 두는 방식은 가족과 카테고리 선택 절차를 중복시키고, 전용 에이전트의 지침에 스킬 하나만 싣는 계약과 맞지 않는다.

### 결과

얻는 것: 가계부 전용 에이전트가 MCP 도구만으로 스크린샷을 등록한다. 이미지와 거래 후보가 디스크에 남지 않는다.

감당할 것:

- 이미지 해시가 없어 같은 화면을 다시 보냈는지는 기존 기록 대조로만 안다.
- 등록 도중 실패하면 자동 복구가 없다. 남은 거래는 내역을 조회한 뒤 단건 도구로 등록한다.
- 무인 등록과 메신저 접수가 사라진다. 다시 필요하면 같은 MCP 도구 위에 입력 경로를 더한다.
- 에이전트가 사진을 보는 수단은 실행 환경이 제공해야 한다.
