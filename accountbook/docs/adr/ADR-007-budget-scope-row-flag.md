# ADR-007: 예산 대상 판정은 플러그인이 행마다 싣고 서버 예산 합계로 대조한다

- Status: Accepted
- 날짜: 2026-11-02

## 배경

2026-11-02 운영 테스트에서 비서는 월 소비 리포트의 총액과 카테고리 합계는 맞혔지만 예산 대상 지출을 틀렸다.
카테고리에 걸린 예산 제외를 플러그인이 넘기지 않았고, 모델이 거래의 `excludeFromBudget`만 보고 「예산 제외가 없다」 고 단정했다.
가계부 서버의 예산 합계는 거래 예산 제외, 카테고리 예산 제외, 반복지출이 만든 지출을 모두 뺀다(fos-accountbook ADR-B26).
사용자는 [ADR-006](ADR-006-list-output-file.md)대로 합계 도구를 두지 않고 모델이 파일을 계산하는 방식을 유지하기로 했다(2026-11-02).

## 결정

- `list_expenses`의 파일 출력에 `categoryExcludeFromBudget`과 `countsTowardBudget`을 싣는다. 판정 규칙은 서버 예산 합계 규칙과 같다.
- 모델은 판정 규칙을 다시 만들지 않고 이 칸으로 필터링해 더한다.
- `get_budget_summary`가 가계부 서버의 예산 합계, 생활비, 예산 항목별 사용액과 한도를 그대로 넘긴다.
- 모델은 파일로 계산한 예산 합계, 생활비, 항목별 사용액을 `get_budget_summary`의 값과 대조한다. 다르면 두 값을 함께 보이고 어느 쪽도 고르지 않는다.
- 커넥터는 여전히 월 합계나 카테고리 합계를 계산하는 도구를 제공하지 않는다.

## 대안 기각

- 플러그인 월 요약 도구: `execute_code` 없이도 답할 수 있지만 ADR-006을 뒤집고 집계 방식이 늘 때마다 도구가 바뀐다.
- 가계부 지출 응답에 판정 칸 추가: 규칙이 백엔드에만 남지만 지출 API 계약이 바뀌고 백엔드 작업이 커진다.
- 거래 행 표시 규칙(거래 OR 카테고리): 내역 화면과 맞지만 예산 화면의 합계와 어긋나 서버 합계로 대조할 수 없다.

## 영향

- 같은 예산 대상 규칙이 백엔드 두 곳(QueryDSL과 JPQL)과 플러그인 한 곳에 있다. 서버 규칙이 바뀌면 플러그인도 고친다.
  고치지 않으면 서버 합계 대조가 불일치를 알려 리포트가 조용히 틀리지 않는다.
- 연동 토큰은 예산 읽기 경로 두 개(`dashboard/budget-summary`, `budget-items`)를 허용받아야 한다. 허용 전에는 `ACCOUNTBOOK_FORBIDDEN`이고 스킬은 한도 없이 답한다.
- 목록 파일의 보관 규칙은 ADR-006과 같다.
