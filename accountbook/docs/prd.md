# PRD: accountbook

## 목적

금융 앱 화면에 이미 모인 거래 내역을 다시 손으로 입력하는 비용을 줄인다.
OCR 오류와 중복 등록을 숨기지 않고 사용자가 확인할 수 있는 후보로 만든다.

## 사용자

개인 또는 가족 가계부를 쓰는 사용자다.
가계부 에이전트는 사용자별 연동 토큰으로 MCP 도구를 호출한다.

## 현재 범위

1단계는 토스 소비 내역 스크린샷이 가계부에 등록되는 흐름 하나다.

| 기능 | 목적 |
|---|---|
| 토스 스크린샷 추출 | 날짜별 수입과 지출 후보 생성 |
| 결정적 검증 | 필드 스키마, 일별 합계, 잘린 화면과 기존 기록 검사 |
| 미리보기 | 날짜별 합계와 차단 사유 확인 |
| API 등록 | 확인한 묶음을 사용자가 승인 카드에서 승인하면 수입·지출 API에 순차 등록 |
| 대화형 기록 관리 | MCP 도구로 가족, 카테고리와 수입·지출을 조회하고 등록·수정 후보 준비. 실행은 사용자가 승인 카드에서 승인한 것만 가능 |
| 기간 통계 | 전체 목록을 사용자별 JSONL 파일로 받고 코드 실행 결과로 합계와 통계 제공 |
| plugin 배포 | MCP 서버와 단일 스킬을 설치 없이 실행할 수 있는 배포 단위로 제공 |

화면 가져오기는 2026-10-01에 fos-assistant의 가계부 에이전트에서 실제 화면으로 등록까지 확인했다.
현재 정책에서 등록과 수정은 사용자가 대화 화면의 승인 카드에서 승인한 것만 실행된다.
삭제는 지원하지 않으며 가계부 앱에서 직접 지우도록 안내한다.

## 성공 기준

- 화면의 완전한 날짜에서 상세 거래 합계와 일별 요약 합계가 모두 일치한다.
- 하루 거래가 스크린샷 여러 장에 걸쳐도 합친 합계가 화면 요약과 같으면 등록할 수 있다.
- 합계 불일치, 낮은 필드 신뢰도와 잘린 날짜는 등록 전에 차단된다.
- 같은 화면을 다시 보내거나 일부가 이미 등록돼 있어도 같은 거래가 두 번 등록되지 않는다.
- 사용자가 미리보기를 확인하지 않으면 등록 요청을 보내지 않는다.
- 미리보기와 다른 내용은 같은 묶음 ID로 등록할 수 없다.
- 이미지와 거래 후보를 파일로 저장하지 않는다.
- 인증 값은 환경 변수로 전달하고 파일에 저장하지 않는다. API 응답 원문은 로그와 파일에 저장하지 않는다.
- 목록 파일은 검증한 거래 필드만 사용자별 출력 디렉터리에 저장한다.
- 수정은 현재 기록을 보여 주고 사용자 확인과 승인 카드의 승인을 거친다. 승인하지 않은 수정은 실행하지 않는다.
- 삭제 요청에는 가계부 앱에서 직접 지우도록 안내하고 삭제 도구를 호출하지 않는다.
- 가계부를 조회하고 변경할 때는 MCP 도구를 사용한다. 통계는 `execute_code`로 목록 파일을 계산하며 코드 실행 도구가 없으면 제공하지 않는다.
- 여러 profile의 토큰이 서로 섞이지 않는다.

## 비범위

- 토스 계정이나 앱 UI 자동 조작
- 토스 또는 금융사 비공개 API 탐색
- OCR 모델 학습과 운영
- 거래 시각이 보이지 않는 화면에서 시각 추정
- 일별 합계로 확인할 수 없는 스크린샷 병합. 한 날짜가 여러 장에 걸치면 합친 결과가 화면 요약과 일치할 때만 등록한다
- 토스가 일별 합계에서 뺀 거래(내 계좌 사이 이체, 카드 대금 납부)의 등록
- 사용자 확인 없는 무인 등록과 예약 실행
- 메신저 첨부 이미지 접수

## 다음 단계 후보

결정된 것이 아니라 사용하면서 필요해지면 검토할 항목이다.

- 소액 적립 같은 거래를 등록에서 빼되 일별 합계 검증에는 포함하는 선택 입력
- 수입과 지출로 나뉜 MCP 도구를 `type` 인자로 합쳐 도구 수 줄이기
- 토스 외 금융 앱 화면의 추출 규칙
- 사용자 확인 없는 등록. 다시 필요해지면 같은 MCP 도구 위에 입력 경로를 더한다
