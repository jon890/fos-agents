# PRD: accountbook

## 목적

금융 앱 화면에 이미 모인 거래 내역을 다시 손으로 입력하는 비용을 줄인다.
OCR 오류와 중복 등록을 숨기지 않고 사용자가 확인할 수 있는 후보로 만든다.

## 사용자

본인 1인이다.
홈서버의 이미지 인식 지원 에이전트를 통해 개인 가계부 API에 거래를 등록한다.

## 현재 MVP

| 기능 | 목적 |
|---|---|
| 토스 스크린샷 추출 | 날짜별 수입과 지출 후보 생성 |
| 결정적 검증 | 필드 스키마, 일별 합계와 잘린 화면 검사 |
| 후보 검토 | 원본 근거와 차단 이유 확인 |
| API 등록 | 승인된 후보를 기존 수입·지출 API에 순차 등록 |
| 재실행 복구 | 이미지와 후보 식별자로 성공한 전송을 반복하지 않음 |
| 주간 입력함 처리 | 신규 금융 화면을 모아 안전 조건 통과분만 자동 등록 |
| Discord 이미지 접수 | iPhone에서 Hermes 전용 Discord 채널로 보낸 화면을 즉시 처리 |
| 예외 분리 | 자동 등록할 수 없는 이미지를 검토·실패 상태로 격리 |

## 성공 기준

- 화면의 완전한 날짜에서 상세 거래 합계와 일별 요약 합계가 모두 일치한다.
- 합계 불일치, 낮은 필드 신뢰도, 날짜 누락과 기존 동일 거래는 등록 전에 차단된다.
- 대화형 후보는 사용자가 승인하지 않으면 accountbook API를 호출하지 않는다.
- 주간 후보는 `weekly-safe-v1`을 모두 통과한 경우에만 사용자 확인 없이 등록한다.
- 허용된 Discord 사용자가 전용 채널에 보낸 이미지 한 장은 별도 업로드 절차 없이 같은 안전 정책으로 처리한다.
- Discord에서 받은 이미지의 거래 날짜가 수신일 기준 최근 14일을 벗어나면 연도를 자동 판단하지 않는다.
- 재실행 시 이미 성공한 후보를 다시 전송하지 않는다.
- 실제 금융 데이터와 인증 값은 `private/` 밖에 남지 않는다.

## 비범위

- 토스 계정이나 앱 UI 자동 조작
- 토스 또는 금융사 비공개 API 탐색
- OCR 모델 학습과 운영
- 거래 시각이 보이지 않는 화면에서 시각 추정
- 여러 스크린샷에 걸친 같은 날짜 거래의 자동 병합
- `weekly-safe-v1`을 벗어난 후보의 무인 등록
- LangGraph와 별도 실행 흐름 서버
- Discord 메시지와 첨부 파일의 장기 보관 또는 완전 삭제 보장
