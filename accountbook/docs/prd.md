# PRD: accountbook

## 목적

금융 앱 화면에 이미 모인 거래 내역을 다시 손으로 입력하는 비용을 줄인다.
OCR 오류와 중복 등록을 숨기지 않고 사용자가 확인할 수 있는 후보로 만든다.

## 사용자

개인 또는 가족 가계부를 쓰는 사용자다.
가계부 에이전트는 사용자별 연동 토큰으로 MCP 도구를 호출한다.

## 현재 범위

1단계는 토스 소비 내역 스크린샷이 가계부에 등록되는 흐름 하나다.

| 기능 | 목적 |
|---|---|
| 토스 스크린샷 추출 | 날짜별 수입과 지출 후보 생성 |
| 결정적 검증 | 필드 스키마, 일별 합계, 잘린 화면과 기존 기록 검사 |
| 미리보기 | 날짜별 합계와 차단 사유 확인 |
| API 등록 | 사용자가 확인한 묶음을 수입·지출 API에 순차 등록 |
| 대화형 기록 관리 | MCP 도구로 가족, 카테고리와 수입·지출을 조회하고 등록·수정·삭제 |
| plugin 배포 | MCP 서버와 단일 스킬을 설치 없이 실행할 수 있는 배포 단위로 제공 |

## 성공 기준

- 화면의 완전한 날짜에서 상세 거래 합계와 일별 요약 합계가 모두 일치한다.
- 합계 불일치, 낮은 필드 신뢰도, 잘린 날짜와 기존 동일 거래는 등록 전에 차단된다.
- 사용자가 미리보기를 확인하지 않으면 등록 요청을 보내지 않는다.
- 미리보기와 다른 내용은 같은 묶음 ID로 등록할 수 없다.
- 이미지와 거래 후보를 파일로 저장하지 않는다.
- 인증 값은 환경 변수로 전달하고 파일에 저장하지 않는다. MCP 응답 본문은 로그와 파일에 저장하지 않는다.
- 수정과 삭제는 현재 기록을 보여 주고 사용자 확인을 받은 뒤에만 요청한다.
- 가계부 전용 에이전트는 셸과 파일 쓰기 도구 없이 MCP 도구만 사용한다.
- 여러 profile의 토큰이 서로 섞이지 않는다.

## 비범위

- 토스 계정이나 앱 UI 자동 조작
- 토스 또는 금융사 비공개 API 탐색
- OCR 모델 학습과 운영
- 거래 시각이 보이지 않는 화면에서 시각 추정
- 여러 스크린샷에 걸친 같은 날짜 거래의 자동 병합
- 사용자 확인 없는 무인 등록과 예약 실행
- 메신저 첨부 이미지 접수
