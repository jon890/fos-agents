# 토스 소비 화면 추출 계약

토스 소비 화면을 `accountbook/docs/data-schema.md`의 `extracted.json`으로 변환할 때만 읽는다.

## 화면 판별

다음 요소가 함께 보여야 지원 화면으로 판정한다.

- 월 선택 영역
- `전체`, `카드`, `입·출금` 같은 소비 탭
- 일자별 수입·지출 요약
- `N일 요일` 제목 아래의 거래 행

요소가 부족하거나 거래 상세 화면이면 `UNSUPPORTED_SCREEN`으로 중단한다.

## 여러 번 읽기

한 번의 OCR 결과만 사용하지 않는다.

1. 전체 화면에서 월, 일자 요약, 날짜 제목과 다음 날짜 경계를 읽는다.
2. 왼쪽 아이콘을 제외한 거래 본문에서 금액과 설명을 다시 읽는다.
3. 두 결과가 다르면 해당 행만 확대해 금액과 설명을 다시 읽는다.

각 필드의 최종 근거가 한 번만 읽혔거나 결과가 엇갈리면 `medium` 또는 `low`로 표시한다.
색상은 수입·지출 부호를 보완하는 근거일 뿐 단독 근거로 사용하지 않는다.

## 날짜

- 화면의 `N월`과 `N일 요일`을 조합한다.
- 화면에 연도가 없으면 이미지 생성 시각보다 미래가 되지 않는 가장 가까운 연도를 사용한다.
- 파일 생성 시각으로 연도를 채우면 `dateSource`는 `file-metadata`다.
- 주간 입력함의 보조 정보 파일이 원본 사진 생성 시각을 제공하면 그 값으로 연도만 채운다.
  이때 `dateSource`는 `upload-metadata`이고, `dateEvidence`에는 화면에서 읽은 `screenMonth`, `screenDay`와 `yearSource: upload-metadata`를 넣는다.
  화면에서 읽은 월·일 없이 전체 날짜를 보조 정보 파일의 시각으로 만들지 않는다.
- 사용자가 연도를 직접 확인하면 `user-confirmed`다.
- 상태 표시줄의 현재 시각을 거래 시각으로 사용하지 않는다.

날짜 제목부터 다음 날짜 제목 직전까지를 한 날짜의 거래로 묶는다.
다음 날짜 제목이 보이지 않고 화면이 거래 행에서 끝나면 마지막 날짜는 `partial`로 둔다.
제목만 보이고 거래가 잘린 다음 날짜도 `partial`이며 `selectedForImport`는 `false`다.

## 거래 행

거래 행은 금액 한 줄과 바로 아래 설명 한 줄로 구성한다.

- `-N원`은 `expense`이며 JSON에는 양의 원 단위 금액을 넣는다.
- 파란 양수와 수입 문맥은 `income`이다.
- `가맹점 | 결제수단`이면 왼쪽을 `description`, 오른쪽을 `paymentMethod`로 분리한다.
- `출발지 → 도착지` 형식은 전체 문장을 `description`에 두고 `paymentMethod`는 `null`이다.
- 아이콘 모양만으로 category를 확정하지 않는다.
- category 근거가 없으면 `categoryName`은 `null`이다.

같은 날짜에서 화면 위부터 `rowIndex`를 1부터 부여한다.
금액과 설명의 OCR 원문을 `evidence`에 보존한다.

## 일별 합계

달력 영역에서 대상 날짜 아래의 수입과 지출 요약을 `expectedTotals`에 넣는다.
상세 행의 수입과 지출을 각각 합산해 정확히 일치하는지 검증기가 확인한다.

요약을 읽을 수 없으면 `expectedTotals`는 `null`이다.
합계 차이를 맞추려고 거래를 만들거나 금액을 보정하지 않는다.

## 출력 전 점검

- 실제 이미지에 있는 거래만 기록했는가
- 날짜별 행 순서가 화면과 같은가
- 금액 부호를 JSON type과 양의 금액으로 분리했는가
- 다음 날짜 경계로 화면 잘림을 판정했는가
- 파일 생성 시각에서 추정한 연도를 사실로 표시하지 않았는가
- 절대 경로를 `sourceImage`에 넣지 않았는가
