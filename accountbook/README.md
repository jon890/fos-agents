# accountbook

토스 소비 화면 스크린샷을 가계부 거래 후보로 변환하고 검증한 뒤 등록하는 워크스페이스다.

## 현재 범위

- 이미지 인식을 지원하는 에이전트가 토스 소비 화면을 읽는다.
- MCP 도구가 날짜, 금액, 행 구조와 일별 합계를 검사하고 기존 기록과 대조한다.
- 등록 후보를 미리보기로 보여 준다. 등록은 사용자가 대화 화면의 승인 카드에서 승인한 것만 실행된다.
- 같은 에이전트가 대화로 수입과 지출을 조회하고 수정 후보를 준비한다. 수정도 승인 카드에서 승인한 것만 실행된다.
- 기간 합계와 통계는 목록의 파일 출력과 `execute_code` 계산으로 제공한다.
- 삭제는 지원하지 않으며 가계부 앱에서 직접 지우도록 안내한다.

OCR 엔진 자체를 제공하지 않으며 이미지 입력을 지원하지 않는 실행 환경에서는 실행을 중단한다.
이미지와 거래 후보를 파일로 저장하지 않는다.

## MCP plugin

배포 단위는 `accountbook/plugin/`, plugin 이름은 `fos-accountbook` 0.2.0이다.
에이전트는 단일 `accountbook-api` 스킬을 통해 MCP 도구로 화면 검증과 미리보기, 조회를 한다.
등록과 수정은 사용자가 승인 카드에서 승인한 것만 실행하며 삭제는 지원하지 않는다.
fos-assistant는 [plugin 설치 계약](docs/code-architecture.md#plugin-설치-계약)과 `connector.json`을 읽고 사용자별 profile에 `accountbook` 서버를 설치한다.
사용자는 가계부 설정에서 발급한 연동 토큰을 fos-assistant에 등록한다.
런타임에는 Bun만 필요하며, 패키지 설치는 빌드하는 개발 환경에서만 수행한다.

## 사용 방법

fos-assistant에서는 다음 순서로 쓴다.

1. 가계부 설정에서 연동 토큰을 발급하고 fos-assistant의 연결 화면에 등록한다.
2. 가계부 에이전트와의 대화에 토스 소비 내역 스크린샷을 첨부하고 등록을 요청한다.
3. 에이전트가 보여 주는 미리보기에서 날짜별 합계, 새로 등록할 건수와 건너뛸 건수를 확인한다.
4. 카테고리가 없는 거래는 카테고리를 고르거나 에이전트에게 판단을 맡긴다.
   지출은 `EXPENSE`, 수입은 `INCOME` 목록에서 고른다.
5. 등록을 명시하면 대화 화면에 승인 카드가 뜬다. 카드에서 승인하면 그 내용 그대로 한 번 등록되고 저장된 건수가 대화로 온다.
   여러 건을 건별로 등록하면 카드가 건마다 뜨며, 「승인하고 묻지 않기」(1시간, 오늘, 30일)로 묶어 승인할 수 있다.

처음 응답은 미리보기에서 멈춘다. 등록을 명시하고 카드에서 승인하기 전에는 accountbook API에 쓰지 않는다.

### 스크린샷 찍는 법

- 달력 영역의 일별 수입·지출 요약과 거래 행이 한 화면에 함께 보여야 한다.
- 하루 거래가 한 화면을 넘으면 이어지는 화면을 여러 장 올린다. 두 장에 겹친 행은 한 번만 읽는다.
- 장 사이에 빠진 행이 있으면 합계가 맞지 않아 등록되지 않는다. 에이전트가 빠진 구간을 다시 요청한다.
- 합계가 수입과 지출 모두 화면 요약과 같으면 목록 끝이 보이지 않아도 등록할 수 있다.

### 알아 둘 동작

- 같은 화면을 다시 올려도 같은 거래가 두 번 등록되지 않는다.
- 금액이 회색인 행(내 계좌 사이 이체, 카드 대금 납부)은 토스가 일별 합계에서 뺀 거래라 등록하지 않는다.
- 일별 합계로 검증하므로 그 날짜의 거래 일부만 골라 등록할 수 없다. 소액 적립도 함께 등록된다.
- 가계부에 설명을 다르게 적어 둔 기록은 같은 거래로 알아보지 못한다. 미리보기의 새로 등록할 건수로 확인한다.
- 화면에 연도가 없으면 오늘 날짜를 기준으로 연도를 추정하고 미리보기에 알린다.

2026-10-01에 실제 토스 화면으로 미리보기, 등록과 재전송 시 0건 등록을 확인했다.

### 로컬에서 MCP 서버 실행

로컬에서 MCP 서버를 직접 띄울 때는 `accountbook/.env.example`의 환경 변수를 전달한다.
환경 변수의 의미는 [데이터 계약](docs/data-schema.md#환경-변수)을 따른다.

## 검증

```bash
bun install --frozen-lockfile --cwd accountbook/plugin
bun test ./accountbook/plugin
bun run --cwd accountbook/plugin typecheck
bun run --cwd accountbook/plugin build
claude plugin validate accountbook/plugin
```

위 명령은 `bun`이 PATH에 있어야 한다. 기본 설치 위치는 `~/.bun/bin`이다.
첫 줄의 의존성 설치를 건너뛰면 `@modelcontextprotocol/sdk`를 찾지 못해 서버 테스트와 번들 일치 검사가 실패한다.

plugin 테스트에는 원본과 배포 번들의 일치 검사, 설치 없는 stdio 초기화 검사와 스킬 본문 길이 검사가 포함된다.
실제 운영 API를 호출하지 않으며 모든 HTTP 호출은 fetch 대역으로 검증한다.
