# 가계부 기록 관리

`accountbook` MCP 도구만 호출해 요청을 처리한다.
셸, 파일 도구와 HTTP 직접 호출을 사용하지 않는다.
토큰을 사용자에게 묻거나 대화에 붙여 넣도록 요청하지 않는다.

## 가족과 카테고리

1. `list_families`로 접근할 수 있는 가족과 기본 가족을 확인한다.
   기본 가족이 없고 가족이 하나면 그것을 고른다.
   여럿이면 이름을 보여 주고 사용자에게 하나를 고르게 한다.
   가족이 없으면 가계부에서 가족을 만든 뒤 다시 요청하도록 안내하고 끝낸다.
2. `list_categories`로 선택한 가족의 카테고리를 조회한다.
   사용자가 입력한 이름을 정확히 일치시키며 없는 이름이나 같은 이름이 여럿이면 선택을 요청한다.
   UUID는 조회 결과에 있는 값만 사용한다.

## 등록과 조회

- 지출과 수입의 종류, 금액, 카테고리와 날짜를 확인한다.
  날짜가 없으면 실행 환경의 현재 한국 날짜를 사용하고, 날짜만 있으면 저장 시각은 `12:00:00`으로 한다.
  이는 실제 거래 시각이 아니므로 사용자가 시각을 주면 그 값을 사용한다.
  필수 값이 모호하면 등록 전에 묻는다.
- "점심 12000원 식비"처럼 기록 내용이 확정돼도 날짜와 종류를 포함한 후보를 보여 주고 등록 확인을 받는다.
  확인 뒤 `create_expense` 또는 `create_income`을 한 번 호출한다.
- 최근 내역은 `list_expenses` 또는 `list_incomes`로 기간과 개수(기본 20, 최대 100)를 전달해 조회한다.
  비어 있으면 0건이라고 알린다. 더 오래된 내역은 `page`를 늘려 조회한다.
  날짜, 금액, 설명과 카테고리를 보여 주되 불필요한 개인정보는 가린다.

## 수정과 삭제

1. 목록에서 사용자가 고른 기록의 UUID와 가족, 수입·지출 종류를 확인한다.
   대상을 추정하지 않는다.
2. `get_expense` 또는 `get_income`으로 현재 기록을 다시 읽는다.
3. 수정은 현재 내용과 바꿀 필드, 삭제는 삭제할 기록을 보여 주고 확인을 요청한다.
   사용자가 이 미리보기를 보고 명시적으로 확인한 뒤에만 `update_expense`, `update_income`, `delete_expense`, `delete_income`을 호출한다.
   변경 도구의 `confirmed`는 이 확인을 받은 때에만 `true`로 전달한다.
   수정에서는 사용자가 바꾼 필드만 전달한다.

## 오류와 완료

오류의 `code`와 사용자용 `message`를 전달한다.
401 안내가 나오면 가계부 설정에서 연동 토큰을 다시 발급해 fos-assistant에 등록하도록 안내한다.
403은 가족 선택과 권한을 확인하고, 404는 목록을 다시 조회한다.
네트워크 오류와 서버 오류는 변경 결과가 불명확하므로 자동 재전송하지 않는다.
내역을 다시 조회해 확인하고, 그래도 결과를 확정할 수 없으면 사용자 판단을 기다린다.
토큰, API 응답 전체와 거래 설명을 로그나 파일에 저장하지 않는다.
성공한 변경 결과만 간결히 알리고 요청한 작업이 끝나면 종료한다.
