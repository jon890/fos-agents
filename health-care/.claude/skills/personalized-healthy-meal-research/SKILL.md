# personalized-healthy-meal-research

개인의 건강 조건과 생활 제약을 식사 설계 조건으로 바꾼 뒤, 공신력 있는 건강 자료와 실제 요리 영상을 함께 조사해 반복 가능한 집밥 체계를 만든다.
특정 식재료나 유행 레시피를 정답으로 고정하지 않는다. 먼저 식품의 **역할과 재료군**을 정의하고, 현재 구입 가능성·조리도구·기호에 따라 구체 재료를 선택한다.

## When to use

다음 요청에서 사용한다.

- “내 건강에 맞는 식단을 찾아줘”
- “콜레스테롤·지방간·위염 등을 함께 고려한 집밥을 추천해줘”
- “다음에도 반복해서 먹을 건강식을 조사해줘”
- “유튜브 레시피까지 찾아서 장보기와 주간 식단을 만들어줘”
- “재료 → 요리법 → 효과를 HTML 리포트로 만들어줘”
- 기존 건강식 리포트의 메뉴·영상·대체재를 갱신할 때

다음에는 단독으로 사용하지 않는다.

- 검사 결과나 증상을 진단하는 요청
- 의료진의 처방을 바꾸는 요청
- 급성 복통·황달·출혈·반복 구토 등 즉시 진료 판단이 우선인 상황
- 한 끼 메뉴만 빠르게 고르는 요청에는 전체 심층 조사 과정을 강제하지 않는다

## 핵심 원칙

1. **조건 우선:** 인기 요리보다 건강 조건·증상·의료진 지시를 먼저 적용한다.
2. **재료군 우선:** 특정 재료를 고정하지 않고 단백질원·통곡물·채소·지방·양념의 역할로 설계한다.
3. **반복 가능성:** 한 번의 이상적인 식사보다 장보기·보관·남은 재료 연결이 쉬운 체계를 우선한다.
4. **효과 절제:** 음식이 질병을 치료하거나 단기간에 수치를 정상화한다고 표현하지 않는다.
5. **영상 분리:** 유튜브는 조리법 자료다. 건강 효과의 근거는 의료기관·공공기관·학술 출처에서 가져온다.
6. **개인정보 분리:** 개인 건강 기록은 private 입력으로만 사용하고 공개 skill·config·HTML에는 비식별 기준만 남긴다.

## 입력과 개인정보 경계

### 가능한 입력

- 사용자가 현재 대화에서 밝힌 건강 목표와 증상
- `health-care/private/conditions/*/current-context.md`
- 의료진이 안내한 식사 제한 또는 추적 계획
- 알레르기·종교·윤리적 제한
- 싫어하는 음식, 조리도구, 조리 가능 시간, 예산
- 냉장고 재료와 자주 이용하는 마트

### 경계

- private 파일의 검사 수치·병원명·복약·정확한 날짜를 공개 리포트에 복사하지 않는다.
- 공개 HTML에는 “콜레스테롤 관리 고려”처럼 일반화된 조건만 적는다.
- 개인화된 산출물은 기본적으로 `health-care/private/reports/`에 둔다.
- 완전히 비식별화한 공개용 산출물만 `health-care/data/reports/`에 둘 수 있다.
- Cloudflare Pages 등 외부 게시에는 사용자의 명시적 요청이 필요하다.

## 재료 일반화 체계

항상 `references/ingredient-framework.md`를 먼저 읽고 후보를 역할별로 분류한다.
메뉴는 다음 슬롯 중 필요한 항목을 채우는 방식으로 설계한다.

1. **주 단백질:** 저지방 동물성 / 식물성 / 생선 / 달걀·저지방 유제품
2. **식이섬유 탄수화물:** 통곡·잡곡 / 콩류 / 뿌리·전분 채소
3. **채소:** 익혀 먹기 좋은 채소 / 생채소 / 냉동채소 / 해조류
4. **지방:** 불포화지방을 소량 사용하는 슬롯
5. **맛:** 저염 감칠맛 / 허브 / 산미 / 매운맛
6. **비상 재료:** 냉동·통조림·즉석 통곡 제품

특정 재료가 없으면 같은 슬롯 안에서 교체한다. 예를 들어 “닭가슴살 필수”가 아니라 “저지방 단백질 1종”으로 설계한 뒤 현장에서는 가용한 재료를 고른다.

## 실행 순서

### 1. 요청 범위 확정

다음을 확인하거나 대화·private 컨텍스트에서 찾는다.

- 주요 목표: 콜레스테롤, 체중, 혈당, 지방간, 소화기 증상 등
- 피해야 할 급진적 방식: 단식, 초저열량, 극단적 무지방식 등
- 한 끼 / 7일 / 2주 / 장기 라이브러리 중 범위
- 출력: Discord 요약 / Markdown / HTML / 공개 URL
- 식사 인원, 조리 시간, 도구, 예산

정보가 없고 결과를 크게 바꾸지 않으면 1~2인, 10~25분, 냄비·팬·전자레인지 기준으로 진행한다.

**완료 조건:** 건강 목표, 증상 조정 규칙, 출력 범위가 한 문단으로 요약돼 있어야 한다.

### 2. 건강 조건 충돌표 작성

각 조건을 다음 네 칸으로 나눈다.

- 늘릴 요소
- 줄일 요소
- 완전히 제거하면 안 되는 요소
- 증상에 따라 조절할 요소

예:

- 콜레스테롤: 포화지방 감소, 수용성 식이섬유 증가
- 감량: 포만감과 분량 조절, 급격한 절식 금지
- 담낭 문제: 고지방 폭식과 빠른 감량을 피하고 지방을 무조건 0으로 만들지 않음
- 위장 증상: 산미·매운맛·생채소·카페인을 개인 반응에 따라 조절

이 예시는 고정 진단표가 아니다. 사용자의 실제 조건에 없는 항목은 억지로 넣지 않는다.

**완료 조건:** 서로 충돌하는 목표가 있으면 우선순위와 보수적 절충안이 명시돼 있어야 한다.

### 3. 공신력 있는 건강 근거 조사

우선순위:

1. 보건당국·국립 연구기관·병원 공식 자료
2. 전문학회 가이드라인
3. 체계적 문헌고찰
4. 일반 건강 매체

현재 정보가 필요한 경우 웹에서 원문을 직접 확인한다. 식단 효과를 영상 제목이나 블로그 문구로 근거화하지 않는다.

최소 근거 축:

- 주요 건강 조건별 식사 원칙
- 체중 감량 속도와 극단적 식단 위험
- 포화지방·식이섬유·첨가당·나트륨 원칙
- 증상별 개인 조정과 위험 신호

`grounded-citations`가 있으면 출처 장부를 사용한다.

**완료 조건:** 핵심 건강 주장마다 확인 가능한 원문 URL이 있고, 사실과 해석이 분리돼 있어야 한다.

### 4. 유튜브 레시피 후보 수집

한 번의 검색어로 끝내지 않는다. 최소 6개 축을 사용한다.

- 조리 방식: 찜, 한 팬, 전자레인지, 오븐/에어프라이어, 국·죽
- 단백질 재료군: 식물성, 저지방 육류, 생선, 달걀
- 섬유질 재료군: 귀리·보리·콩·통곡
- 보관 방식: 냉동채소, 통조림, 대량조리
- 식사 상황: 아침, 도시락, 저녁, 비상식
- 건강 조정: 저염, 저포화지방, 순한 양념

먼저 `youtube-video-research` skill을 로드하고 `skill_view` 결과의 `skill_dir`를 확인한다.
그 경로를 환경변수로 지정해 수집기를 실행한다.

```bash
YOUTUBE_RESEARCH_SKILL_DIR='<skill_view 결과의 skill_dir>'
python3 "$YOUTUBE_RESEARCH_SKILL_DIR/scripts/collect_youtube_candidates.py" \
  --query '<검색어 1>' --axis '<축 1>' \
  --query '<검색어 2>' --axis '<축 2>' \
  --limit 10 --out-dir /tmp/<research-name>
```

목표는 고유 후보 50개 이상, 심층 검토 12~20개다. 간단 요청이면 후보 규모를 줄일 수 있지만 이유를 밝힌다.

**완료 조건:** 검색 축이 한 재료에 편중되지 않고, 후보 URL이 중복 제거돼 있어야 한다.

### 5. 영상 검증과 과장 필터링

각 후보에서 확인한다.

- 영상 ID, 제목, 채널, URL
- 설명란의 재료와 분량
- 가능하면 한국어 자막의 실제 조리 순서
- 튀김·버터·치즈·가공육·과도한 기름·설탕·짠 소스
- 고추·산미·마늘 등 증상 유발 가능 양념
- 광고·협찬 여부
- 과장된 치료·급감량 표현

검토 수준을 표시한다.

- `자막 검토`
- `설명란 검토`
- `메타데이터만 확인`

자막이 없다고 검토한 척하지 않는다. 제목의 “살이 빠진다”, “염증 제거”, “콜레스테롤을 낮춘다”는 효능 근거에서 제외한다.

**완료 조건:** 선별 영상마다 원본 조리법의 문제와 개인 조건에 맞춘 수정점이 한 줄 이상 있어야 한다.

### 6. 메뉴 합성

메뉴 개수 기본값은 12~18개다. 다음 축을 고르게 섞는다.

- 아침 / 점심 / 저녁 / 비상식
- 팬 / 냄비 / 전자레인지 / 무조리 / 오븐·에어프라이어
- 식물성 / 생선 / 저지방 육류 / 달걀
- 즉석 조리 / 2~3회분 대량조리

각 메뉴 카드 필수 항목:

1. 메뉴명과 예상 조리시간
2. 재료군과 현재 선택한 구체 재료
3. 3~5단계 조리법
4. 기대효과 — 식단상 기여로만 표현
5. 같은 재료군의 교체재료
6. 개인 증상에 따른 주의점
7. 관련 유튜브 영상과 검토 수준
8. 영상 원본에서 수정한 점

**완료 조건:** 모든 카드가 8개 필드를 갖고, 같은 주 단백질이나 같은 조리법이 전체의 절반을 넘지 않아야 한다.

### 7. 유튜브 썸네일 규칙

HTML 카드에는 관련 영상이 있으면 링크와 썸네일을 함께 둔다.

영상 ID가 `VIDEO_ID`라면 기본 썸네일 후보는 다음과 같다.

```text
https://i.ytimg.com/vi/VIDEO_ID/hqdefault.jpg
```

규칙:

- 썸네일 전체를 `<a>`로 감싸 영상으로 이동하게 한다.
- `alt`에 영상 제목과 채널명을 쓴다.
- 카드마다 가장 가까운 영상 1개를 대표 썸네일로 둔다.
- 추가 영상은 텍스트 링크로 1~2개만 둔다.
- 영상이 메뉴와 정확히 맞지 않으면 `비슷한 조리 방식 참고`라고 표시한다.
- 썸네일 URL이 실제 이미지로 응답하는지 확인한다.
- 적합한 영상이 없으면 억지 링크를 만들지 않고 `검증된 관련 영상 없음`이라고 쓴다.
- 광고성 제목이나 전후 사진을 건강 효과처럼 보이게 사용하지 않는다.

**완료 조건:** 대표 영상이 있는 모든 카드에서 썸네일·제목·채널·링크·검토 수준이 일치해야 한다.

### 8. 반복 운영 설계

최종 메뉴 목록과 별도로 다음을 만든다.

- 7일 회전표
- 일주일 장보기 목록
- 남은 재료 연결표
- 5~10분 비상식 2개 이상
- 대량조리 1~2개
- 1주 후 점검 질문: 포만감, 속쓰림, 우상복부 불편, 조리 부담, 남은 재료

한 주를 완벽하게 지키는 계획보다 재료 폐기와 배달 의존을 줄이는 계획을 우선한다.

**완료 조건:** 같은 재료를 다음 식사로 연결하는 경로와 실패했을 때의 비상식이 포함돼 있어야 한다.

### 9. 출력과 게시

#### Discord 요약

- 오늘 바로 시작할 메뉴 1~3개
- 장보기 핵심
- 중요한 주의점
- 전체 리포트 링크

#### HTML

- 모바일 우선
- 상단 요약과 고정 내비게이션
- 메뉴 카드
- 카드 내부 유튜브 썸네일
- 7일 회전표와 장보기
- 공신력 있는 출처와 영상 출처 분리
- 개인정보·검사 수치·병원 식별자 없음

#### 공개 게시

사용자가 명시적으로 요청한 경우에만 `public-report-publishing` 또는 `report-publisher` 절차를 사용한다.
게시 전 공개 안전검사를 수행하고, 게시 후 HTTP 200·제목·핵심 최신 문구를 확인한다.

**완료 조건:** 로컬 HTML 렌더링, 모바일 레이아웃, 외부 링크, 공개 URL의 최신 내용이 모두 검증돼야 한다.

## 출력 품질 기준

- 단순 음식 목록이 아니라 선택 이유와 대체 규칙이 있다.
- 건강 효과는 “도움을 줄 수 있음”, “포화지방을 줄이기 쉬움”처럼 제한적으로 쓴다.
- 음식별 효과가 같은 문장으로 반복되지 않는다.
- 유튜브 링크는 실제 영상이며 영상 ID를 검증한다.
- 영상과 공신력 있는 건강 근거를 혼동하지 않는다.
- 특정 재료를 구하지 못해도 같은 재료군으로 전체 계획을 유지할 수 있다.
- 사용자가 오늘 무엇을 살지와 다음 주 무엇을 반복할지 모두 알 수 있다.

## Common pitfalls

1. **한 재료 편중:** 양배추·두부·닭가슴살만 반복하지 말고 역할별 재료군을 순환한다.
2. **건강식 제목 신뢰:** 영상 제목의 감량·해독·염증 표현은 근거가 아니다.
3. **원본 양념 복사:** 건강식 영상도 기름·치즈·소스가 많을 수 있으므로 반드시 수정점을 적는다.
4. **모든 지방 제거:** 담낭 문제와 지속 가능성을 고려해 극단적 무지방식으로 만들지 않는다.
5. **무조건 생채소:** 위장 증상이 있으면 익힌 채소를 우선하고 개인 반응을 확인한다.
6. **카드와 영상 불일치:** 조리법이 다른 영상을 같은 메뉴처럼 붙이지 않는다.
7. **썸네일만 장식:** 썸네일은 클릭 가능한 링크여야 하고 검토 수준을 표시한다.
8. **공개 리포트에 개인 수치 노출:** private 자료에서 읽은 정보는 비식별 조건으로만 변환한다.
9. **배포 후 미검증:** 이전 캐시가 보일 수 있으므로 새 쿼리 또는 배포 URL로 핵심 변경을 확인한다.

## Verification checklist

- [ ] 건강 목표·제약·조리 조건이 요약돼 있다.
- [ ] 조건 충돌과 보수적 절충안이 있다.
- [ ] 공신력 있는 건강 근거 URL이 있다.
- [ ] 최소 6개 검색 축에서 유튜브 후보를 수집했다.
- [ ] 선별 영상의 설명란 또는 자막 검토 수준을 표시했다.
- [ ] 메뉴가 재료군과 조리법 면에서 다양하다.
- [ ] 모든 메뉴 카드에 재료·요리법·기대효과·대체재·주의점이 있다.
- [ ] 가능한 모든 카드에 관련 영상과 클릭 가능한 썸네일이 있다.
- [ ] 7일 회전표·장보기·비상식이 있다.
- [ ] 개인 의료 정보가 공개 산출물에 없다.
- [ ] HTML과 공개 URL을 실제로 열어 최신 내용을 확인했다.
