# ji-yoon-blog 실행 흐름

사진에서 네이버 임시저장까지 가는 흐름을 소유한다.
문체와 카테고리 판단은 `references/`가, 객체 계약은 [`data-schema.md`](data-schema.md)가 소유한다.

## 왜 이 경로인가

S3 API는 홈서버 loopback 주소에만 열려 있다.
아이폰도 맥북도 그 포트에 직접 닿지 않는다.

그래서 두 갈래로 나눈다.

| 누가 | 어디로 | 무엇 |
| --- | --- | --- |
| 아이폰 | `storage.fosworld.co.kr` | Cloudflare Access를 지나 Admin UI로 사진을 올린다 |
| 맥북 | SSH | 홈서버 명령을 불러 목록을 받고 사진을 가져온다 |

아이폰 업로드에 별도 서비스를 만들지 않는다.
Admin UI의 파일 화면에 여러 장 동시 업로드와 폴더 생성이 이미 있다.

S3를 외부에 내는 길은 택하지 않았다.
[`../../docs/adr/ADR-022-home-storage-s3-collections.md`](../../docs/adr/ADR-022-home-storage-s3-collections.md)가
S3 API를 로컬 주소에만 열기로 정했고, 이번 요구는 그 결정을 바꾸지 않고도 채울 수 있다.

## 정상 흐름

| 순서 | 누가 | 무엇 |
| --- | --- | --- |
| 1 | 지융 | 어디에 다녀왔는지 말한다 |
| 2 | 스킬 | `<날짜>-<장소>` 폴더를 만들고 아이폰용 주소를 준다 |
| 3 | 지융 | 아이폰에서 그 주소를 열어 사진을 올린다 |
| 4 | 지융 | 올렸다고 알린다 |
| 5 | 스킬 | 사진을 맥북으로 가져와 촬영시각 순으로 번호를 붙인다 |
| 6 | 스킬 | 사진을 보고, 카테고리 모듈이 요구하는 사실 중 빠진 것을 묻는다 |
| 7 | 스킬 | 제목 후보와 본문, 태그를 만들어 `draft.json`에 담는다 |
| 8 | 스킬 | 미리보기를 만들어 보여준다 |
| 9 | 지융 | 확인하거나 고칠 곳을 말한다 |
| 10 | 스킬 | 네이버 글쓰기에 제목, 본문, 사진, 태그를 넣고 임시저장한다 |

발행하지 않는다.
10단계까지 끝나도 글은 임시저장 상태로 남는다.

## 상태 표시

각 단계가 끝날 때 무엇이 확인됐는지 말한다.
확인하지 않은 것을 완료라고 말하지 않는다.

| 표현 | 언제 |
| --- | --- |
| 폴더 준비 완료 | 폴더를 만들고 주소를 준 뒤 |
| 사진 N장 확보 | 맥북에 내려받고 순서를 세운 뒤 |
| 초안 작성 완료 | `draft.json`과 미리보기를 만든 뒤 |
| 미리보기 초안 등록 완료 | 편집기 상태를 읽어 반영을 확인한 뒤 |
| 로그인 필요로 중단 | 네이버 로그인 화면에서 멈춘 뒤 |
| 네이버 보안 확인으로 중단 | 캡차나 기기 인증에서 멈춘 뒤 |

## 실패와 빈 상태

| 상황 | 무엇으로 아나 | 무엇을 하나 |
| --- | --- | --- |
| 홈서버에 닿지 못한다 | SSH 종료 코드 | 멈추고 알린다. 사진을 새로 받지 않는다 |
| bucket이 없다 | `NoSuchBucket` | 생성 절차를 안내하고 멈춘다 |
| 만든 폴더가 없다 | 폴더 목록이 빈 배열 | 먼저 폴더를 만들자고 알린다 |
| 폴더는 있고 사진이 없다 | 이미지 확장자가 0개 | 아이폰에서 올려달라고 알리고 기다린다 |
| 사진 장수가 예상과 다르다 | 지융이 말한 수와 다름 | 몇 장을 받았는지 알리고 계속할지 묻는다 |
| 촬영시각을 읽지 못한다 | 촬영시각 필드가 빈 문자열 | 이름 순서로 세우고 그 사실을 알린다 |
| 초안이 이미 있다 | `draft.json`이 존재 | 덮어쓸지 묻는다 |
| 사진을 찾지 못한 미리보기 | 미리보기 생성이 0이 아닌 코드로 끝남 | 어느 사진이 없는지 알리고 멈춘다 |
| 네이버 로그인이 풀렸다 | 로그인 화면 | 전용 브라우저 프로필에서 로그인해 달라고 요청한다 |
| 보안 확인이 나온다 | 캡차나 기기 인증 화면 | 멈춘다. 우회하지 않는다 |

## 같은 폴더를 다시 쓸 때

사진을 이어서 올리면 기존 사진 뒤에 더해진다.
같은 이름이 오면 덮어쓴다.

이어 올린 뒤에는 사진을 다시 받아 순서를 새로 세운다.
번호는 폴더 전체를 다시 세므로 앞 사진의 번호도 바뀔 수 있다.
`draft.json`의 사진 경로가 어긋나면 미리보기가 그 자리를 표시하고 0이 아닌 코드로 끝난다.

## 사진 전송 부담

전송은 초당 11.3MB로 실측됐다.

| 사진 | 대략 크기 | 시간 |
| --- | --- | --- |
| 28장 | 84MB | 7초 |
| 56장 | 168MB | 15초 |
| 264장 | 792MB | 70초 |

축소판을 따로 만들지 않고 원본을 한 번만 받는다.
네이버에 올릴 때 원본이 필요하고, 축소판을 두면 같은 사진을 두 번 받거나 캐시를 관리해야 한다.

## Admin UI 접근 범위

`storage.fosworld.co.kr`에는 자체 로그인이 없다.
Cloudflare Access가 유일한 보호막이다.

Access를 지난 사람은 `career-os` bucket의 파일도 함께 보고 지울 수 있다.
Access 정책이 본인만 허용한다는 전제로 이 경로를 쓴다.
정책이 넓어지면 사진 경로만 열리는 별도 창구가 필요해진다.
