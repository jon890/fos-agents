# ji-yoon-blog 데이터 스키마

사진 저장소의 객체 계약과 로컬 산출물을 소유한다.
홈서버 저장소의 공통 연결 계약은 [`../../docs/home-server-object-storage.md`](../../docs/home-server-object-storage.md)가 소유한다.

## 사진 저장소

| 항목 | 값 |
| --- | --- |
| collection key | `ji-yoon-blog` |
| bucket | `ji-yoon-blog` |
| endpoint | 홈서버 loopback. 워크스페이스 밖에서 직접 접근하지 않는다 |
| 권한 | `Read`, `Write`, `List` |

### 객체 키

```text
photos/<YYYY-MM-DD>-<장소>/<파일명>
```

`<장소>`는 상호명을 그대로 쓴다.
`<파일명>`은 아이폰이 올린 원본 이름이며 스킬이 바꾸지 않는다.

| 객체 | 뜻 |
| --- | --- |
| `photos/<폴더>/.keep` | 폴더가 있다는 표시. 크기 0 |
| `photos/<폴더>/<원본 이름>` | 사진 원본 |
| `integration-checks/<이름>` | 연결과 권한 확인용. 확인이 끝나면 남기지 않는다 |

S3에는 폴더라는 것이 없고 키 접두사만 있다.
`.keep`이 없으면 사진을 올리기 전의 폴더가 Admin UI 파일 목록에 나타나지 않는다.

### 삭제

`Write` 권한은 PUT과 DELETE를 함께 포함한다.
SeaweedFS에서 둘을 갈라 줄 수 없다.
실측으로 확인했고, 삭제 요청은 HTTP 204로 성공한다.

그래서 삭제 경계를 권한이 아니라 코드에 둔다.
사진을 지우는 명령을 만들지 않는다.
잘못 올린 사진은 사람이 Admin UI에서 지운다.

### 불변 조건

- 같은 폴더에 같은 이름으로 올리면 덮어쓴다. 아이폰의 원본 이름은 기기 안에서 고유하다.
- 사진의 촬영 순서는 객체 이름이나 저장 시각이 아니라 사진 안의 촬영시각이 정한다.
- 사진을 지우거나 옮기지 않는다. 한 번 올린 폴더는 그 글의 근거로 남는다.

## 로컬 산출물

맥북에 내려받은 사진과 초안은 다음 자리에 둔다.
추적하지 않는다.

```text
ji-yoon-blog/drafts/<YYYY-MM-DD>-<장소>/
  photos/001-<원본 이름> ...
  draft.json
  preview.html
```

사진 앞의 세 자리 번호는 촬영시각 순서다.
촬영시각을 읽지 못한 사진은 이름 순서로 뒤에 붙는다.

## 초안

`draft.json`은 본문과 사진 배치를 담는다.

| 필드 | 뜻 |
| --- | --- |
| `title` | 확정한 제목 |
| `titleCandidates` | 지융에게 보여준 제목 후보 배열. 고르고 나면 `title`이 그중 하나다 |
| `category` | `category-style-map.md`에 있는 카테고리 이름 |
| `sponsored` | 지융에게 확인한 협찬 여부. 참이면 협찬, 거짓이면 비협찬 |
| `tags` | 검색어를 반영한 태그 배열. `#` 없이 적는다 |
| `blocks` | 본문 블록 배열. 순서가 곧 글의 순서다 |

`titleCandidates`를 빼도 미리보기는 만들어진다.
후보를 남겨 두면 지융이 다시 고를 때 앞서 만든 것을 다시 만들지 않는다.

블록은 넷이다.

| `type` | 필드 | 뜻 |
| --- | --- | --- |
| `sticker` | `stickerCode` | 네이버 스티커 코드. 아래 네 코드 중 하나 |
| `text` | `lines` | 문단 배열. 한 원소가 한 줄이다 |
| `image` | `path`, `caption`, `role` | `draft.json`이 있는 자리에서 본 상대 경로. 메뉴판 사진은 `role: "menu"` |
| `map` | `name`, `address` | 확인한 상호명과 주소. 둘 다 일치하는 장소 하나만 첨부한다 |

| 스티커 | `stickerCode` | 배치 |
| --- | --- | --- |
| 안녕하세요 | `ogq_5db4314bac2f0-1` | 첫 블록 |
| 가격표 | `ogq_5db4314bac2f0-6` | 메뉴판 사진 바로 앞 |
| 내돈내산 | `ogq_5db4314bac2f0-23` | `sponsored`가 거짓일 때만 한 개 |
| 위치정보 | `ogq_5db4314bac2f0-4` | 마지막 블록 |

맛집로그와 카페로그는 메뉴판 사진 한 장을 `role: "menu"`로 표시한다.
지도 블록에는 지융이 확인한 상호명과 주소를 적는다.
네이버 검색 결과에서 둘 다 맞는 항목이 하나가 아니면 첨부를 멈추고 지융에게 묻는다.
협찬 여부를 확인하지 않았다면 `sponsored`를 추정해 채우지 않는다.

`lines`를 한 문자열로 합치지 않는다.
지융의 글은 문단의 절반이 문장 중간에서 끊기므로, 줄을 나눈 그대로가 정보다.
한 줄짜리 문단도 원소가 하나인 배열로 넣는다.

`build_preview.py`가 미리보기를 만들기 전에 이 계약을 검사한다.
어긋나면 종료 코드 2로 끝나고 어느 블록의 어느 필드가 문제인지 알려준다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 미리보기를 만들었고 사진도 모두 찾았다 |
| 1 | 미리보기는 만들었지만 사진을 찾지 못했다 |
| 2 | 초안이 계약을 지키지 않아 미리보기를 만들지 않았다 |

사진을 아직 받지 않은 채 문체만 먼저 보려면 `--allow-missing-photos`를 준다.
그러면 사진을 찾지 못해도 0으로 끝난다.

## 설정

맥북과 홈서버가 서로 다른 값을 읽는다.

| 어디 | 파일 | 담는 것 |
| --- | --- | --- |
| 맥북 | `ji-yoon-blog/.env` | 홈서버 접속 정보 |
| 홈서버 | 저장소 밖의 mode 600 파일 | S3 endpoint, bucket, access key, secret key |

S3 키는 맥북에 두지 않는다.
맥북은 홈서버 명령을 부르고 결과만 받는다.
