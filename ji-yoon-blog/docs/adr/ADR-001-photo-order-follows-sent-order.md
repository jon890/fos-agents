## ADR-001: 글의 사진 순서는 지융이 보낸 순서를 따른다

- Status: Accepted
- Date: 2026-10-05

### 맥락

지융은 사진을 고른 순서대로 글이 이어지기를 바랐다.
실제 초안은 그 순서를 따르지 않았다. 흐트러지는 곳은 세 군데였다.

| 어디 | 무엇이 순서를 바꿨나 |
| --- | --- |
| `stage_chat_photos.py` | `--file` 로 받은 차례를 버리고 촬영시각으로, 없으면 이름으로 다시 세웠다 |
| 스킬과 카테고리 모듈 | 「사진 순서」 가 외관, 메뉴판, 음식처럼 놓을 순서를 정해 에이전트가 사진을 옮길 근거가 됐다 |
| fos-assistant | 여러 장을 동시에 올려 첨부 번호와 화면 순서가 고른 순서와 어긋날 수 있었다 |

fos-assistant 쪽은 그 저장소가 고친다.
그 뒤로는 입력의 `N번째 사진` 오름차순이 지융이 고른 순서가 된다.

### 결정

- 초안 폴더의 사진 이름 앞 세 자리 번호가 글의 사진 순서다.
- 대화 첨부는 입력의 `N번째 사진` 오름차순으로 `--file` 을 주고, 스크립트는 받은 차례대로 번호를 붙인다.
- `image` 블록은 번호가 커지는 순서로 한 번씩만 놓는다. 초안 계약이 이를 검사해 어기면 미리보기가 종료 코드 2로 멈춘다.
- 카테고리 모듈의 「사진 순서」 는 빠진 사진을 알아차리는 목록으로만 쓴다.
- 홈서버 저장소 경로는 촬영시각 순서를 그대로 쓴다. Admin UI 가 올린 차례를 남기지 않아 보낸 순서를 알 수 없다.
- 지융이 순서를 바꿔 달라고 할 때만 번호를 다시 붙인다.

### 거절한 대안

- 촬영시각 순서: 지융이 일부러 바꾼 순서를 되돌린다. 여러 기기의 사진이 섞이면 시계도 어긋난다.
- 첨부 번호 순서: 동시에 올리면 서버에 도착한 차례라 고른 순서와 다를 수 있다.
- 순서를 문서로만 지시: 실행 중인 에이전트가 카테고리 순서에 맞춰 사진을 옮긴 적이 있어 검사로 막는다.

### 결과

미리보기와 네이버 편집기 조작이 같은 계약을 쓰므로 번호가 어긋난 초안은 어느 쪽으로도 넘어가지 않는다.
홈서버 저장소 경로에서 고른 순서를 지키려면 assistant 대화에 첨부해야 한다.
사진을 카테고리 순서로 옮겨 둔 예전 초안은 편집기 단계에서도 막힌다. 블록을 번호 순서로 되돌리고 미리보기를 다시 확인받는다.
