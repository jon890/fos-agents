# assistant 대화에 올린 사진으로 초안 만들기

이 절은 Hermes 입력에 `[이번 메시지에 올린 사진]`이 있을 때만 쓴다.
`fos-assistant`는 사진을 대화에 붙인 뒤 Hermes가 읽을 수 있는 디렉터리와 파일 이름을 입력에 적는다.
사진이 첨부되지 않은 메시지에서는 그 경로가 다시 주어지지 않으므로,
여러 메시지로 받은 사진은 앞선 입력에 명시된 파일 이름만 이어서 사용한다.
앞선 파일 이름을 대화 기록에서 확인할 수 없으면 다시 첨부해 달라고 요청한다.

**사진은 지융이 보낸 순서대로 쓴다.**
입력의 사진 목록에는 사진마다 `N번째 사진` 이 붙어 있다. 그 N 의 오름차순이 지융이 보낸 순서다.
목록에 적힌 줄의 차례나 파일 이름(첨부 번호), 촬영시각으로 다시 세우지 않는다.
여러 메시지로 받았으면 N 이 메시지를 넘어 이어지므로 그대로 N 의 오름차순이다.
장소별로 나눠도 한 장소 안의 사진은 이 순서를 지킨다.
카테고리 모듈의 「사진 순서」에 맞춰 사진을 옮기지 않는다. 그 목록은 빠진 사진을 알아차리는 데만 쓴다.

1. 입력에 나온 첨부 파일을 N 의 오름차순으로 `vision_analyze`로 모두 본다. 파일 이름이나 EXIF만으로 장소를 확정하지 않는다.
   한 차례에 여덟 장까지 함께 부른다. Hermes 가 `vision_analyze` 를 한 차례에 여덟 개까지 동시에 돌리므로 30장이면 네 차례다.
   한 장씩 차례로 부르면 30장에 몇 분이 걸린다.
   사진마다 아래 질문을 그대로 준다.

```text
이 사진에 무엇이 찍혔는지 적어 줘. 외관, 입구, 내부, 메뉴판, 음식, 음료, 디저트, 풍경, 사람 중 무엇인지 먼저 말해.
간판, 메뉴판, 가격표, 영수증에 보이는 글자는 메뉴 이름과 가격까지 그대로 옮겨 적고, 읽을 수 없는 글자는 ? 로 적어.
음식과 음료는 무엇으로 보이는지, 공간은 분위기와 좌석이 어떤지 적어.
장소를 짐작할 단서가 있으면 따로 적어. 사진에 없는 것은 짐작이라고 밝혀.
```

   답을 받으면 사진마다 `N번째 사진 (파일 이름): 설명` 한 줄로 적어 둔다.
   설명에는 메뉴 이름과 가격, 장소 단서, 분위기 중 사진에 있는 것을 빠뜨리지 않는다.
   이 목록이 장소를 나누는 근거가 되고, 글쓰기 단계에서 사진 순서를 잃지 않게 한다.
   6단계에서 각 설명이 `image` 블록의 `note` 가 된다.
   글자가 작아 `?` 가 많으면 그 부분만 `region` 으로 잘라 다시 본다.
2. 간판과 메뉴판, 음식, 촬영 흐름을 근거로 사진을 장소별로 나누고 지융에게 각 장소 이름과 사진 묶음을 확인받는다.
   장소가 불분명한 사진은 묶음에 넣지 않고 묻는다. 한 대화에서 여러 장소가 확인되면 초안도 장소별로 만든다.
3. 확인된 묶음마다 아래 명령으로 **입력에 명시된 파일만** `drafts/<날짜>-<장소>/photos`에 복사한다.
   `--file` 은 N 의 오름차순으로 준다. 스크립트는 받은 차례 그대로 `001-`, `002-` 번호를 붙인다.
   다른 대화의 첨부 디렉터리나 지금 디렉터리의 나머지 파일을 검색하지 않는다.
   명령은 `ji-yoon-blog` 워크스페이스에서 실행한다.

```bash
python3 .claude/skills/naver-blog-draft/scripts/stage_chat_photos.py \
  --source-dir "$ATTACHMENT_DIR" \
  --file 101.jpg --file 102.jpg \
  --place '가상식당' --date 2026-09-27 \
  --drafts-dir drafts
```

`ATTACHMENT_DIR`에는 이번 대화 입력에 적힌 디렉터리를 넣는다.
`--file`에는 같은 입력에 적힌 저장 파일 이름만 넣고, 장소마다 명령을 따로 실행한다.
스크립트는 원본을 그대로 두고 `--file` 을 받은 차례로 사진 번호를 붙인다.
출력의 `photos[].source` 가 어느 첨부였는지, `photos[].order` 가 그 장소 안에서 몇 번째인지 알려 준다.
초안 폴더가 이미 있으면 덮어쓰지 않고 실패하므로 기존 초안과 사진을 먼저 확인한다.

4. 초안을 쓰기 전에 [SKILL.md의 5단계 「부족한 사실 묻기」](../SKILL.md#5-부족한-사실-묻기)를 장소별로 통과한다.
   필수 사실이 없어 멈춘 뒤 지융이 그 사실을 알려 주면 같은 단계부터 이어 간다. 이미 만든 초안 폴더와 사진을 쓰며 폴더를 지우거나 사진 재첨부를 요청하지 않는다.
   명령이 출력한 `photos[].path`를 해당 장소 `draft.json`의 `image` 블록에 **번호 순서대로** 넣고, 1단계의 설명을 `note` 에 넣는다.
   번호가 거꾸로 놓이면 `build_preview.py` 가 종료 코드 2로 멈춘다.
   스티커, 지도, 카테고리, 태그와 협찬 여부는 기존 초안 계약을 따른다.
5. 장소별로 `build_preview.py`를 실행하고 확인할 제목, 본문, 사진 순서, 스티커, 지도, 카테고리와 태그를 대화에서 보여준다.
   입력에 `[결과물 폴더]` 단락이 있으면 `--out`을 `<결과물 폴더>/<장소>/index.html`로 준다.
   자세한 규칙은 `SKILL.md`의 「미리보기를 둘 자리」 절을 따른다.
   답에 파일 경로를 쓰지 않는다. 미리보기는 답 아래에 자동으로 붙으므로 `아래 미리보기를 열어 확인해 주세요` 처럼 안내한다.
   결과물 폴더와 초안 폴더의 경로는 지융이 열 수 없는 내부 경로다.
   단락이 없어 대화 화면에 HTML을 여는 수단이 없다면 전체 초안을 채팅에 보여주고,
   사용자가 올린 원본 사진과 각 `image` 블록의 연결을 읽을 수 있게 적는다.
6. 지융이 **그 장소의 초안**을 확인한 뒤에만 네이버 임시저장을 실행한다.
   여러 장소라면 승인과 저장 상태를 장소마다 구분한다. 발행은 하지 않는다.

대화의 사진 첨부는 한 메시지에 올릴 수 있는 장수에 상한이 있다. 상한은 fos-assistant 가 정한다.
사진을 여러 메시지로 받더라도 사진마다 출처 메시지와 파일 이름을 잃지 않는다.
