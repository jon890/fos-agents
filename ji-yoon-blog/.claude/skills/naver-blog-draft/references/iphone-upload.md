# 아이폰에서 사진 올리기

## Admin UI 를 쓰는 이유

아이폰 단축어는 S3 가 요구하는 서명을 만들지 못한다.
서명에는 비밀 키로 HMAC 을 계산하는 단계가 있는데 단축어에 그 기능이 없다.

S3 API 는 홈서버 loopback 주소에만 열려 있어서 아이폰이 그 포트에 직접 닿지도 못한다.

`storage.fosworld.co.kr` 의 SeaweedFS Admin UI 는 Cloudflare Access 를 지나 밖에서 열린다.
그 파일 화면에 폴더 만들기와 여러 장 동시 업로드가 이미 있으므로 업로드 페이지를 따로 만들지 않는다.

## 로그인

Admin UI 에는 자체 로그인이 없다.
Cloudflare Access 가 유일한 보호막이다.

주소를 처음 열면 Access 로그인 화면이 나온다.
한 번 로그인하면 쿠키가 남아 다음부터는 바로 열린다.

## 쓰는 순서

1. 글로 쓸 곳에 다녀와서 사진을 찍는다.
2. 지융이 "사진 올릴 주소 줘" 라고 말하면 스킬이 `photos.py new <장소>` 로 폴더를 만들고 주소를 준다.
3. 아이폰 사파리에서 그 주소를 연다. 처음이면 Cloudflare Access 로그인을 한 번 한다.
4. 파일 화면에서 업로드를 누르고 올릴 사진을 고른다. 여러 장을 한 번에 고를 수 있다.
5. 파일 목록에서 몇 장이 올라갔는지 확인한다.
6. 올렸다고 스킬에 알린다.

## 파일 이름과 순서

파일은 아이폰이 보낸 원본 이름 그대로 저장된다.
Admin UI 는 이름을 바꾸지 않는다.

순서는 스킬이 세운다.
`photos.py pull` 이 사진의 촬영시각을 읽어 `001-<원본 이름>` 형태로 번호를 다시 붙인다.
아이폰이 사진을 어떤 순서로 보내든 결과는 같다.

## HEIC 사진

아이폰이 HEIC 으로 찍어도 사파리가 파일을 고를 때 JPEG 로 바꿔 보내는 경우가 많다.
그때는 따로 설정할 것이 없다.

HEIC 이 그대로 올라가면 촬영시각을 읽지 못해 이름 순서로 세운다.
그 경우에는 사진 순서를 지융에게 확인한다.

## 다룰 범위

Access 를 지나면 같은 저장소의 다른 bucket 파일도 보이고 지울 수 있다.
사진 폴더만 다룬다.
다른 bucket 의 파일은 열지 않는다.
