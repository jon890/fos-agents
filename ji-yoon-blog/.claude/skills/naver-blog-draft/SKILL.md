# 지융로그 초안 만들기

사진에서 시작해 네이버 임시저장까지 간다.
발행은 하지 않는다.

## 어디까지 자동이고 어디부터 사람인가

끝까지 자동으로 가지 않는다.
사람이 해야 하는 걸음이 셋 있고, 그 앞에서 멈춰 기다린다.

| 걸음 | 누가 | 왜 |
| --- | --- | --- |
| 사진 폴더 만들기와 주소 주기 | 스킬 | |
| 아이폰에서 사진 올리기 | 지융 | 아이폰을 스킬이 조작하지 못한다 |
| 사진 받아 순서 세우기 | 스킬 | |
| 빠진 사실 묻기 | 스킬이 묻고 지융이 답한다 | 사진에 없는 것은 지어내지 않는다 |
| 초안과 미리보기 만들기 | 스킬 | |
| 초안 확인 | 지융 | |
| 네이버 로그인 | 지융 | 비밀번호와 인증을 스킬이 다루지 않는다 |
| 제목, 본문, 태그 넣기 | 스킬 | |
| 편집기에 사진 올리기 | 지융 | `browser-driver` 에 파일을 고르는 명령이 없다 |
| 임시저장과 확인 | 스킬 | |
| 발행 | 지융 | 스킬은 하지 않는다 |

사람 차례에서 멈출 때는 무엇을 기다리는지 한 줄로 말한다.
기다리는 동안 다음 걸음을 미리 했다고 말하지 않는다.

## 먼저 읽을 것

글을 쓰기 전에 워크스페이스의 두 문서를 읽는다.

| 문서 | 무엇을 정하나 |
| --- | --- |
| `references/ji-yung-persona.md` | 인사, 문단을 끊는 방식, 부호 습관, 마무리, 태그 |
| `references/category-style-map.md` | 그 카테고리에서 반드시 담을 사실과 사진 순서 |

문체를 지어내지 않는다.
두 문서에 없는 판단이 필요하면 지융에게 묻는다.

## 준비

홈서버 접속 정보가 워크스페이스 `.env` 에 있어야 한다.
`.env.example` 이 필요한 항목을 보여준다.

```bash
python3 .claude/skills/naver-blog-draft/scripts/photos.py folders
```

만들어 둔 폴더 목록과 폴더마다 사진이 몇 장 있는지 보여준다.
설정이 없으면 어느 항목이 비었는지 알려준다.
그 상태로는 아래 단계를 진행할 수 없으므로 지융에게 값을 요청하고 멈춘다.

| 나온 것 | 뜻 | 다음에 할 것 |
| --- | --- | --- |
| 폴더 표 | 홈서버까지 닿았다 | 이어간다 |
| `사진 묶음이 없다` | 닿았지만 폴더가 하나도 없다 | 1번으로 간다 |
| `JI_YOON_BLOG_SSH_TARGET 이 비어 있다` | `.env` 가 비었다 | 지융에게 값을 요청하고 멈춘다 |
| `홈서버 명령이 실패했다` | SSH 나 홈서버 쪽 문제다 | 멈추고 알린다. 사진을 새로 받지 않는다 |

## 1. 사진 올릴 자리 만들기

지융이 아직 사진을 올리지 않았으면 폴더를 만들어 준다.

```bash
python3 .claude/skills/naver-blog-draft/scripts/photos.py new 순돌이곱창
```

장소는 상호명을 그대로 쓴다.
날짜는 명령이 오늘 날짜로 붙이므로 따로 넣지 않는다.

명령이 출력하는 주소를 지융에게 준다.
아이폰에서 그 주소를 열면 `storage.fosworld.co.kr` 의 Admin UI 파일 화면이 뜨고,
그 화면에서 사진을 여러 장 한 번에 고를 수 있다.
Cloudflare Access 로그인은 처음 한 번만 하고, 그 뒤에는 쿠키가 남아 바로 열린다.

아이폰에서 무엇을 누르는지는 스킬의 `references/iphone-upload.md` 가 소유한다.

주소를 주고 나면 멈춰서 기다린다.
지융이 올렸다고 알리기 전에 2번으로 가지 않는다.

### 사진이 아직 없을 때

지융이 사진보다 먼저 말로 시작할 때가 있다.
`어제 간 카페 글 써줄래` 라고만 말하면 사진은 아직 아이폰에 있다.

그때도 멈추지 않고 글을 먼저 만든다.
문체와 사실이 맞는지 먼저 보고, 사진은 뒤에 채운다.

1. 폴더를 만들고 주소를 준다. 지융은 틈이 날 때 올린다.
2. 3번의 `반드시 담을 사실` 을 먼저 묻는다. 사진 대신 지융의 말이 근거가 된다.
3. 4번에서 `image` 블록을 자리마다 넣되 `path` 는 `photos/001-<나중에>.jpg` 처럼 비워 둔다.
4. 미리보기를 `--allow-missing-photos` 로 만든다.

```bash
python3 .claude/skills/naver-blog-draft/scripts/build_preview.py \
  drafts/순돌이곱창/draft.json --out drafts/순돌이곱창/preview.html \
  --allow-missing-photos
```

사진 자리가 `사진 없음` 으로 보이고 종료 코드가 0 이 된다.
문체를 먼저 확인받는 용도이며, 네이버에 넣기 전에는 반드시 사진을 채운다.

사진이 올라오면 2번으로 돌아가 받고, `path` 를 실제 파일 이름으로 바꾼 뒤
`--allow-missing-photos` 없이 다시 만든다.

## 2. 사진 읽기

```bash
python3 .claude/skills/naver-blog-draft/scripts/photos.py pull 2026-09-04-순돌이곱창 \
  --out ./drafts/순돌이곱창/photos
```

사진을 맥북으로 받고 촬영시각 순으로 번호를 붙인다.
촬영시각이 없는 사진은 이름 순서로 뒤에 붙는다.
받은 파일 이름은 `001-<원본 이름>` 형태이므로 초안의 `path` 도 그 이름을 가리켜야 한다.

내려받은 사진을 실제로 본다.
무엇이 찍혔는지 보지 않고 본문을 쓰지 않는다.

`사진이 없다: photos/<폴더>/` 로 끝나면 두 가지 중 하나다.
폴더 이름을 잘못 적었거나, 폴더는 있는데 아직 아무것도 올라오지 않은 것이다.
`folders` 로 그 폴더가 목록에 있는지 먼저 본다.

| `folders` 에 | 무엇 | 무엇을 하나 |
| --- | --- | --- |
| 있다 | 아직 올리지 않았다 | 아이폰에서 올려달라고 알리고 기다린다 |
| 없다 | 폴더 이름이 다르다 | 목록에서 맞는 이름을 찾아 다시 부른다 |

## 3. 부족한 사실 묻기

사진만으로는 알 수 없는 것이 있다.
카테고리 모듈의 `반드시 담을 사실`을 보고 빠진 것을 추린 뒤 한 번에 묻는다.

맛집이면 대개 다음이 빠진다.

- 언제 갔는지와 얼마나 기다렸는지
- 주문한 메뉴와 가격
- 맛이 어땠는지, 아쉬웠던 점
- 주차와 정기휴무

지어내지 않는다.
지융이 모른다고 하면 그 대목을 본문에서 뺀다.

협찬이나 제공을 받았는지도 확인한다.
받았으면 형태에 맞는 고지 문구를 인사보다 앞에 둔다.

## 4. 초안 만들기

초안은 JSON으로 만든다.

```json
{
  "title": "불향 가득한 군산 곱창 맛집 순돌이곱창 메뉴, 웨이팅 후기",
  "category": "맛집로그",
  "tags": ["군산맛집", "군산곱창", "순돌이곱창웨이팅", "내돈내산"],
  "blocks": [
    {"type": "sticker", "emoji": "🍖"},
    {"type": "text", "lines": ["안녕하세요 지융입니다 😋", "오늘은 ..."]},
    {"type": "image", "path": "photos/001-001.jpg"},
    {"type": "map", "address": "전북특별자치도 군산시 우체통거리2길 43-9"}
  ]
}
```

블록의 종류와 필드는 `ji-yoon-blog/docs/data-schema.md` 의 초안 절이 소유한다.

블록 순서는 페르소나 문서의 기본 흐름을 따른다.
사진 한 장에 글 묶음 하나가 붙고, 그 묶음은 서너 줄이다.

제목은 후보를 셋 만들어 `titleCandidates` 에 담고 지융에게 고르게 한다.
고른 것을 `title` 에 넣는다.
검색어를 담되 지융이 실제로 쓰는 형태를 벗어나지 않는다.

초안을 저장한 뒤 미리보기를 만들어 계약을 검사받는다.
계약을 어기면 종료 코드 2 로 끝나고 어느 블록이 문제인지 알려준다.
`lines` 에 문자열 하나를 넣는 실수가 가장 잦다. 한 줄짜리 문단도 배열로 넣는다.

## 5. 미리보기

```bash
python3 .claude/skills/naver-blog-draft/scripts/build_preview.py \
  drafts/순돌이곱창/draft.json --out drafts/순돌이곱창/preview.html
```

네이버 모바일 화면 폭으로 그린다.
사진을 찾지 못하면 그 자리를 표시하고 종료 코드 1로 끝난다.

미리보기를 지융에게 보여주고 확인을 받는다.
확인 없이 다음 단계로 가지 않는다.

## 6. 네이버 임시저장

브라우저 조작은 `~/.claude/scripts/browser-driver` 로 한다.
브라우저 도구를 직접 부르면 실패해도 종료 코드가 0 이라 오류가 드러나지 않는다.
명령 목록은 `browser-driver help` 가 소유하므로 첫 명령 전에 읽는다.

네이버 로그인은 전용 브라우저 프로필에 한 번 해 두고 그 세션을 재사용한다.
프로필 준비와 안전 규칙은 워크스페이스의 `references/preview-automation.md` 가 소유한다.

프로필을 스킬이 만들지 못한다.
`browser-driver doctor` 가 쓸 수 있는 프로필 이름을 보여주므로 먼저 그 목록을 본다.
네이버 세션을 담은 프로필이 없으면 지융에게 만들고 로그인해 달라고 요청하고 멈춘다.

1. 네이버 블로그 글쓰기 화면을 연다.
2. `url` 로 지금 주소를 읽어 화면을 판별한다.
   주소가 `nid.naver.com/nidlogin.login` 으로 바뀌었으면 세션이 없는 것이다.
   로그인 화면이나 보안 확인 화면이면 멈추고 지융에게 넘긴다.
3. 지융이 고른 제목 하나를 제목 입력란에 넣는다.
4. 본문을 `draft.json` 의 `blocks` 순서대로 넣는다.
   `text` 블록은 `lines` 를 줄 단위로 넣는다.
   줄을 한 문장으로 합치지 않는다. 지융의 글은 문단의 절반이 문장 중간에서 끊긴다.
   `image` 블록 자리는 비워 두고 표시만 남긴다.
5. 사진 자리를 다 비워 둔 채로, 어느 자리에 어느 파일을 넣을지 순서대로 알려주고 기다린다.
   `browser-driver` 에 파일을 고르는 명령이 없어 스킬이 올리지 못한다.
   지융이 편집기에서 직접 올린다.
6. 태그 입력란에 태그를 넣는다.
7. 임시저장한다.
8. 편집기 상태를 읽어 제목과 본문, 사진 장수가 실제로 들어갔는지 확인한다.

확인한 것만 완료라고 말한다.
멈춘 경우에 쓸 표현은 `ji-yoon-blog/docs/flow.md` 의 상태 표시 표가 소유한다.

## 하지 않는 것

- 발행. 임시저장까지만 한다.
- 지융이 확인하지 않은 상태로 네이버에 넣기.
- 사진을 보지 않고 본문 쓰기.
- 가보지 않은 곳의 세부나 받지 않은 협찬 문구 넣기.
- 네이버 비밀번호, 인증번호, 쿠키를 요청하거나 저장하기.
