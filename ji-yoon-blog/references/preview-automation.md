# 네이버 블로그 미리보기 자동화

네이버 블로그에 미리보기나 임시저장을 준비하는 절차를 담는다.

## 세션을 어디에 두는가

맥북의 ego 전용 프로필에 둔다.
홈서버에 네이버 세션을 두지 않는다.

`code-architecture.md`의 실행 경계가 이미 홈서버와 맥북을 갈라 놓았다.
홈서버는 S3 credential을 보고 네이버 세션을 보지 않는다.
맥북은 그 반대다.
네이버 세션을 홈서버로 옮기면 두 비밀이 한 자리에 모인다.

쓸 수 있는 백엔드 셋 중 남는 것도 ego 하나다.

| 백엔드 | 네이버 세션 | 쓸 수 있나 |
| --- | --- | --- |
| ego | 사용자가 로그인해 둔 프로필을 그대로 쓴다 | 쓴다 |
| agent-browser | 스스로 띄운 브라우저라 세션이 없다 | 로그인 화면에서 멈춘다 |
| orca | 내장 브라우저에 네이버 로그인이 없다 | 로그인 화면에서 멈춘다 |

스킬은 `browser-driver`만 부른다.
백엔드를 직접 고르지 않고 `BROWSER_EGO_PROFILE`로 프로필만 정한다.

홈서버에 더 있어야 하는 것은 없다.
홈서버는 사진만 맡는다.

## 기본은 수동 등록이다

편집기에 넣는 것이 실제로 되는지 아직 확인하지 못했다.
네이버 세션이 있는 프로필이 없어서 글쓰기 화면을 열지 못했다.

확인하지 못한 경로를 기본으로 두지 않는다.
`build_package.py`가 붙여넣을 묶음을 만들고 지융이 편집기에 넣는다.

브라우저 자동화는 지융이 로그인해 준 뒤 한 번 실측하고 나서 기본으로 올린다.
그때 확인할 것은 셋이다.

- 제목 입력란에 글자가 들어가는가
- 본문의 줄 나눔이 그대로 남는가
- 임시저장 버튼을 누른 뒤 편집기가 저장됐다고 알리는가

## 지켜야 할 안전 규칙

네이버 비밀번호, 일회용 인증번호, 복구 코드, 쿠키를 대화창에 붙여 달라고 요청하지 않는다.
브라우저에서 사용자가 직접 로그인하거나, 전용 브라우저 프로필을 쓴다.

## 로그인 방법

### 네이버 전용 브라우저 프로필

이 워크스페이스가 쓰는 방법이다.

네이버 작업용 프로필을 하나 만들고 사용자가 그 브라우저에서 한 번 로그인한다.
다음부터는 그 세션을 그대로 쓴다.

프로필은 `browser-driver`의 기본 백엔드인 ego가 관리한다.
쓸 프로필은 `BROWSER_EGO_PROFILE` 환경 변수가 정하고,
비어 있으면 ego의 기본 프로필을 쓴다.

```bash
~/.claude/scripts/browser-driver doctor
```

이 명령이 쓸 수 있는 프로필 이름을 함께 보여준다.
없는 이름을 주면 `프로필을 찾지 못했다`로 끝나므로, 먼저 이 목록에서 이름을 고른다.

```bash
export BROWSER_EGO_PROFILE=<프로필 이름>
```

프로필을 새로 만드는 것은 스킬이 하지 못한다.
사용자가 ego 브라우저에서 프로필을 만들고 그 안에서 네이버에 로그인한다.

로그인 여부는 글쓰기 화면을 열어 주소를 읽어 판정한다.

```bash
B=~/.claude/scripts/browser-driver
PAGE=$($B open "https://blog.naver.com/PostWriteForm.naver?blogId=mywldbs" 25000)
$B url "$PAGE"
```

주소가 `nid.naver.com/nidlogin.login`으로 바뀌었으면 세션이 없는 것이다.
그때는 멈추고 사용자에게 그 프로필에서 로그인해 달라고 요청한다.

신뢰할 수 있는 기기에서만 쓴다.
쿠키를 내보내거나 붙여넣지 않는다.

세션이 풀리면 로그인 화면이 나온다.
그때는 멈추고 사용자에게 그 브라우저에서 직접 로그인해 달라고 요청한다.

임시저장이나 미리보기까지만 한다.
발행은 명시적인 요청이 있을 때만 한다.

### 수동 등록용 패키지

브라우저 자동화가 막히면 사용자가 직접 붙여넣을 패키지를 만든다.

- 제목 후보
- 본문 전문
- 사진 위치와 순서
- 태그 목록
- 붙여넣는 순서

## 하지 않는 것

- 네이버 아이디와 비밀번호를 대화창이나 메신저로 주고받기
- 세션 쿠키 공유
- 캡차나 보안 확인 우회
- 사용자의 최종 확인 없이 발행

## 자동화 절차

브라우저 조작은 `~/.claude/scripts/browser-driver`로 한다.
브라우저 도구를 직접 부르면 실패해도 종료 코드가 0이라 오류가 드러나지 않는다.
명령 목록은 `browser-driver help`가 소유하므로 첫 명령 전에 읽는다.

1. 네이버 블로그 글쓰기 화면으로 이동한다.
2. 현재 상태를 판별한다.
   - 로그인 화면이면 사용자에게 로그인을 요청한다.
   - 편집기 화면이면 이어간다.
   - 보안 확인 화면이면 멈추고 사용자 조작을 요청한다.
3. 제목을 넣는다.
4. 본문을 문단 단위로 넣는다.
   글자를 먼저 넣고, 이미지 파일이 있고 편집기가 업로드를 허용할 때만 사진을 넣는다.
5. 태그 입력란이 있으면 태그를 넣는다.
6. 미리보기를 열거나 임시저장한다.
7. 편집기 상태나 미리보기의 제목과 본문을 읽어 실제로 반영됐는지 확인한다.

## 결과를 알리는 표현

실제로 확인한 것만 말한다.

| 상황 | 표현 |
| --- | --- |
| 미리보기나 임시저장이 만들어지고 확인까지 끝남 | 미리보기 초안 등록 완료 |
| 로그인이 필요해 멈춤 | 로그인 필요로 중단 |
| 보안 확인에 막힘 | 네이버 보안 확인으로 중단 |
| 제목, 본문, 태그만 준비함 | 수동 등록용 패키지 생성 완료 |

## 사진은 사용자가 올린다

`browser-driver`에는 파일을 고르는 명령이 없다.
`open`, `nav`, `js`, `waitjs`, `ready`, `url`, `snap`, `shot`, `close`가 전부다.

브라우저는 스크립트가 `<input type="file">`에 파일을 넣는 것을 막는다.
그래서 `js`로도 대신할 수 없다.

네이버 편집기에 사진을 올리는 것은 사용자 몫이다.
스킬은 어느 자리에 어느 파일을 넣을지 순서대로 알려주고 기다린다.

```text
photos/001-IMG_9331.jpg  →  첫 문단 다음
photos/002-IMG_9154.jpg  →  웨이팅 문단 다음
```

사용자가 올린 뒤에 편집기 상태를 읽어 장수가 맞는지 확인한다.

## 알려진 제약

세션 없이 `https://blog.naver.com/PostWriteForm.naver?blogId=mywldbs`를 열면
네이버 로그인 화면으로 넘어간다.
사용자가 브라우저에서 직접 로그인한 뒤에야 자동화를 이어갈 수 있다.

## 글 수집은 로그인이 필요 없다

발행된 글을 읽는 것은 로그인 없이 된다.
페르소나 조사에 쓰는 수집기가 이 경로를 쓴다.

| 용도 | 경로 |
| --- | --- |
| 글 목록 | `PostTitleListAsync.naver` |
| 본문 | `PostView.naver` |
| 태그 | `BlogTagListInfo.naver` |

태그 조회는 `Referer` 헤더가 있어야 응답한다.
`logNoList`라는 이름과 달리 여러 건을 콤마로 이어 보내면 빈 목록이 온다.
글마다 따로 요청해야 한다.

요청이 빠르면 429로 거절하므로 간격을 늘려가며 다시 요청한다.
목록과 본문은 `scripts/collect_naver_posts.py`가, 태그는 `scripts/enrich_naver_posts.py`가 다룬다.
