# 네이버 블로그 미리보기 자동화

네이버 블로그에 미리보기나 임시저장을 준비하는 절차를 담는다.

## 세션을 어디에 두는가

홈서버의 상주 Chrome 프로필에 둔다.
2026-09-20 에 사용자가 그렇게 정했다.

앞서는 맥북의 ego 프로필에 두고 홈서버에는 두지 않기로 했었다.
홈서버가 스스로 임시저장까지 하려면 그 브라우저에 세션이 있어야 해서 뒤집었다.

값이 큰 것은 그대로 남는다.
프로필 디렉터리에 네이버 로그인 쿠키가 남고, 그것을 가진 쪽은 그 계정으로 글을 쓰고 지울 수 있다.
그래서 프로필을 mode 700 으로 두고 CDP 포트를 loopback 에만 연다.
맥북은 SSH 포트 포워딩으로만 그 포트에 닿는다.

이 선택으로 S3 credential과 네이버 세션이 홈서버 한 곳에 모인다.
그것이 이 결정이 치르는 값이다.
대신 홈서버가 사람 없이 임시저장까지 간다.

### 홈서버에서는 ego가 돌지 않는다

그래서 ego 대신 홈서버의 Chrome 에 CDP로 붙는다. 실측한 것이다.

| 확인한 것 | 결과 |
| --- | --- |
| `ego-browser` 바이너리 | macOS arm64 Mach-O |
| 홈서버 | Ubuntu 24.04.4, Linux x86_64 |
| 홈서버 화면 | `XDG_SESSION_TYPE=tty`, `DISPLAY` 없음, `xvfb-run` 없음 |
| 홈서버 node | 없음. `agent-browser`가 node CLI라 그대로는 못 쓴다 |
| 홈서버 Chrome | `Google Chrome 150.0.7871.186` 설치되어 있음 |

그래서 `naver_session.py`가 Chrome을 `--remote-debugging-port`로 띄워 상주시킨다.
맥북은 SSH 포트 포워딩으로 그 포트에 붙는다.

## 기본은 브라우저 자동화다

2026-09-20 에 홈서버에서 끝까지 한 번 돌려 확인했다.
제목과 본문이 들어갔고 임시저장까지 됐다.

| 확인한 것 | 결과 |
| --- | --- |
| 제목 입력란에 글자가 들어가는가 | 들어간다 |
| 본문의 줄 나눔이 그대로 남는가 | 남는다. 문단 6개로 들어갔다 |
| 임시저장이 실제로 되는가 | 된다. 임시저장 글이 9개에서 10개로 늘었고 목록에서 제목을 확인했다 |
| 태그가 들어가는가 | 들어가지 않는다. 임시저장 화면에 태그 입력란이 없다 |
| 사진이 올라가는가 | 올라간다. 2026-09-21 에 두 장으로 확인했다 |

태그는 여전히 지융이 넣는다.
`build_package.py` 가 만드는 묶음이 그 목록과 순서를 준다.
자동화가 막히면 그 묶음으로 되돌아간다.

## 지켜야 할 안전 규칙

네이버 비밀번호, 일회용 인증번호, 복구 코드, 쿠키를 대화창에 붙여 달라고 요청하지 않는다.
브라우저에서 사용자가 직접 로그인하거나, 전용 브라우저 프로필을 쓴다.

## 로그인 방법

### 홈서버의 상주 브라우저

이 워크스페이스가 쓰는 방법이다.

홈서버에 Chrome을 하나 상주시키고 사용자가 한 번 로그인한다.
다음부터는 그 프로필의 세션을 그대로 쓴다.

```bash
ssh <홈서버> 'cd ~/fos-agents/ji-yoon-blog && python3 scripts/naver_session.py start'
```

로그인 여부는 이 명령이 판정해 종료 코드로 알린다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 로그인이 살아 있다 |
| 1 | 브라우저는 떴지만 로그인이 없다 |
| 2 | 브라우저를 띄우지 못했거나 판정하지 못했다 |

홈서버에 화면이 없으므로 사람이 로그인할 때도 맥북에서 붙는다.
그 방법은 아래 「알려진 제약」이 적는다.

신뢰할 수 있는 기기에서만 쓴다.
쿠키를 내보내거나 붙여넣지 않는다.

세션이 풀리면 `login-check`가 종료 코드 1로 끝난다.
그때는 멈추고 사용자에게 다시 로그인해 달라고 요청한다.

임시저장까지만 한다.
발행은 명시적인 요청이 있을 때만 한다.

### 수동 등록용 패키지

브라우저 자동화가 막히면 사용자가 직접 붙여넣을 패키지를 만든다.

- 제목 후보
- 본문 전문
- 사진 위치와 순서
- 태그 목록
- 붙여넣는 순서

## 하지 않는 것

- 네이버 아이디와 비밀번호를 대화창이나 메신저로 주고받기
- 세션 쿠키 공유
- 캡차나 보안 확인 우회
- 사용자의 최종 확인 없이 발행

## 자동화 절차

홈서버에서 상주 Chrome 을 띄우고, 맥북에서 포트를 이어 붙여 조작한다.

```bash
ssh <홈서버> 'cd ~/fos-agents/ji-yoon-blog && python3 scripts/naver_session.py start'
ssh -N -L 9222:127.0.0.1:9222 <홈서버> &
python3 scripts/naver_editor.py open
python3 scripts/naver_editor.py fill drafts/순돌이곱창/draft.json
python3 scripts/naver_editor.py save
python3 scripts/naver_editor.py state
```

`naver_session.py` 가 브라우저와 로그인 판정을, `naver_editor.py` 가 편집기 조작을 소유한다.
두 스크립트 모두 `ji-yoon-blog/scripts/` 에 있다.

### Hermes 컨테이너에서 붙는 방법

컨테이너 안에서는 SSH 포트 포워딩을 띄우지 않는다.
컨테이너의 `127.0.0.1` 은 컨테이너 자신이라 호스트 Chrome 에 닿지 않는다.
호스트의 중계가 컨테이너 네트워크의 게이트웨이 주소에서 받아 Chrome 의 CDP 포트로 넘긴다.

`scripts/cdp.py` 는 붙을 주소를 아래 두 환경 변수로 받는다.

| 변수 | 주지 않거나 비었을 때 |
| --- | --- |
| `JI_YOON_BLOG_CDP_HOST` | `127.0.0.1` |
| `JI_YOON_BLOG_CDP_PORT` | `9222` |

컨테이너에는 중계를 띄운 쪽이 두 값을 넣어 준다.
맥북에서는 주지 않고 포트 포워딩으로 붙는다.

`state` 가 내는 것을 읽어 확인한 것만 완료라고 말한다.

### 편집기에 글자를 넣는 방법

**`browser-driver` 의 `js` 로는 넣지 못한다.**
SmartEditor 가 자체 입력 버퍼로 글자를 받아서 `document.execCommand` 가 `false` 로 끝난다.
실측이다.

브라우저의 실제 입력 경로인 CDP 의 `Input.insertText` 로 넣어야 한다.
`browser-driver` 에 그 명령이 없어서 `scripts/cdp.py` 가 WebSocket 으로 직접 부른다.

## 결과를 알리는 표현

실제로 확인한 것만 말한다.

| 상황 | 표현 |
| --- | --- |
| 미리보기나 임시저장이 만들어지고 확인까지 끝남 | 미리보기 초안 등록 완료 |
| 로그인이 필요해 멈춤 | 로그인 필요로 중단 |
| 보안 확인에 막힘 | 네이버 보안 확인으로 중단 |
| 제목, 본문, 태그만 준비함 | 수동 등록용 패키지 생성 완료 |

## 사진은 자동으로 올라간다

2026-09-21 에 실측했다. 두 장을 넣고 임시저장한 뒤 다시 열어 남아 있는 것을 확인했다.

앞서 이 절은 「사용자가 올린다」였고 근거를 `browser-driver` 에 두었다.
그 도구에 파일을 고르는 명령이 없고 브라우저가 페이지 안 스크립트의 파일 입력 조작을 막는다는 것이었다.
**둘 다 페이지 안에서 조작할 때의 제약이다.**
지금은 `cdp.py` 로 브라우저 바깥에서 CDP 를 직접 부르므로 그 제약에 걸리지 않는다.

`DOM.setFileInputFiles` 가 파일 선택 자동화의 표준 경로이고 이 경우에도 통한다.

```bash
python3 scripts/naver_editor.py photos drafts/순돌이곱창/draft.json \
  --remote-base <브라우저가 도는 기계의 사진 디렉터리>
```

파일 경로는 **브라우저가 도는 기계 기준**이다. 홈서버 Chrome 이면 홈서버 경로다.
맥북에서 명령을 부르더라도 사진은 홈서버에 있어야 한다.

### 넣는 과정에서 걸리는 것 셋

| 걸리는 것 | 무엇이 보이나 | 어떻게 지나나 |
| --- | --- | --- |
| 파일 입력이 잠깐만 있다 | `nodeId: 0` 과 `Could not find node with given id` | 누른 뒤 새로 붙으면 늦다. 파일 선택 창을 가로채 그 이벤트의 `backendNodeId` 로 넣는다 |
| 사진이 둘 이상이면 레이아웃을 묻는다 | 본문에 아무것도 안 생긴 채 멈춘다 | `사진 첨부 방식` 창에서 `개별사진` 을 고른다 |
| 저장 버튼이 JS 클릭을 받지 않는다 | `Uncaught` 로 끝나고 저장 수가 그대로다 | 마우스 이벤트로 누른다 |

네이버는 사진 버튼을 누를 때 숨긴 `input[type=file][multiple]` 을 그 자리에서 만들고,
파일 선택 창이 닫히면 그것을 DOM 에서 지운다.
그래서 누르는 것과 넣는 것이 한 연결 안에서 이어져야 한다.

레이아웃 선택지는 `button` 이 아니라 `input[type=button].se-image-type-radio` 다.
`개별사진` 은 `#image-type-list` 이고, 콜라주와 슬라이드가 나머지 둘이다.

### 그래도 사람이 하는 것

태그는 여전히 넣지 못한다. 임시저장 화면에 입력란이 없고 발행 설정 레이어에만 있다.
발행도 하지 않는다.

## 알려진 제약

세션 없이 `https://blog.naver.com/PostWriteForm.naver?blogId=mywldbs`를 열면
네이버 로그인 화면으로 넘어간다.
사용자가 브라우저에서 직접 로그인한 뒤에야 자동화를 이어갈 수 있다.

실측으로 걸린 것들이다. 모두 화면에는 원인이 드러나지 않는다.

| 걸린 것 | 무엇이 보였나 | 무엇이 원인이었나 |
| --- | --- | --- |
| DevTools 가 계속 끊겼다 | `Debugging connection was closed` 한 줄 | Chrome 을 `--remote-allow-origins` 없이 띄워 WebSocket 을 origin 검사로 거절했다. 이유는 브라우저 기록에만 남는다 |
| 글자가 들어가지 않았다 | 아무 오류도 없었다 | `작성 중인 글이 있습니다` 알림이 화면을 덮어 클릭이 닿지 않았다 |
| 로그인 판정이 뒤집혔다 | `로그인이 살아 있다` | 로그인 화면으로 보내는 리다이렉트가 1초에서 11초 사이에 온다. 아직 안 온 것을 로그인으로 읽었다 |
| 저장을 확인하지 못했다 | `저장된 글 수가 늘지 않았다` | 그 숫자가 `저장` 버튼 안이 아니라 옆 버튼의 aria-label 에 있다 |
| 저장이 되지 않는다 | `Uncaught` 한 줄 | JS 의 `.click()` 을 편집기가 받지 않는다. 마우스 이벤트로 눌러야 한다 |
| 본문이 절반 넘게 빠졌다 | `fill` 이 0 으로 끝났다 | 글자를 넣자마자 Enter 를 누르면 새 문단이 생기지 않고 다음 줄이 앞 줄을 덮어쓴다. 글자가 보인 뒤 0.15초 기다린다 |
| 이모지가 든 줄이 이모지만 남았다 | 아무 오류도 없었다 | 글자와 이모지를 한 번에 넣으면 앞의 글자가 사라진다. 나눠 넣는다 |
| 사진을 넣었는데 본문이 그대로다 | 아무 오류도 없다 | `사진 첨부 방식` 창이 떠서 고르기를 기다린다 |
| 파일 주입이 노드를 못 찾는다 | `Could not find node with given id` | 파일 선택 창이 닫히면서 그 input 이 DOM 에서 사라졌다 |

로그인은 사람이 한 번 한다.
홈서버에 화면이 없으므로 맥북에서 포트를 이어 붙인 뒤
`chrome://inspect/#devices` 나 아래 주소로 그 브라우저 화면에 붙어 로그인한다.

```text
http://127.0.0.1:9222/devtools/inspector.html?ws=127.0.0.1:9222/devtools/page/<탭 식별자>
```

## 글 수집은 로그인이 필요 없다

발행된 글을 읽는 것은 로그인 없이 된다.
페르소나 조사에 쓰는 수집기가 이 경로를 쓴다.

| 용도 | 경로 |
| --- | --- |
| 글 목록 | `PostTitleListAsync.naver` |
| 본문 | `PostView.naver` |
| 태그 | `BlogTagListInfo.naver` |

태그 조회는 `Referer` 헤더가 있어야 응답한다.
`logNoList`라는 이름과 달리 여러 건을 콤마로 이어 보내면 빈 목록이 온다.
글마다 따로 요청해야 한다.

요청이 빠르면 429로 거절하므로 간격을 늘려가며 다시 요청한다.
목록과 본문은 `scripts/collect_naver_posts.py`가, 태그는 `scripts/enrich_naver_posts.py`가 다룬다.
