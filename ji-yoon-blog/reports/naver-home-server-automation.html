초안이 네이버 임시저장까지 가는 길

홈서버의 로그인된 Chrome을 그대로 쓰면서, 사진과 지도까지 편집기에서 확인하는 자동화 구조입니다.

Python 표준 라이브러리 · Chrome CDP · 발행 없이 임시저장

연결 구조

현재 구현은 Puppeteer를 사용하지 않습니다. 홈서버에 로그인 상태로 실행 중인 Chrome에 Python 코드가 CDP로 연결합니다.

사진은 별도 경로사진 원본은 홈서버의 S3 API에서 가져옵니다. 편집기 입력 단계에서는 CDP 파일 선택 이벤트에 실제 파일 경로를 전달하고, 네이버가 올린 결과를 화면에서 확인합니다.

Puppeteer와 다른 점

같은 Chrome 프로토콜을 직접 사용합니다

Puppeteer와 마찬가지로 CDP 명령으로 브라우저를 조작합니다. 이 저장소는 Node 패키지 대신 Python 표준 라이브러리로 필요한 HTTP와 WebSocket 통신만 구현했습니다.

Runtime.evaluate로 화면을 읽고, Input.insertText와 Input.dispatchMouseEvent로 실제 입력 경로에 글자와 클릭을 보냅니다. SmartEditor는 단순한 페이지 JavaScript 입력을 정상 편집으로 받아들이지 않아 이 경로가 필요합니다.

Chrome 세션은 따로 관리합니다

naver_session.py가 상주 Chrome과 로그인 상태를 맡습니다. 초안 입력기는 실행 중인 Chrome에 붙어서 새 글쓰기 탭을 열고, 작업 후 그 탭만 닫습니다.

로그인 만료, 캡차, 기기 인증은 자동화가 통과시키지 않습니다. 사람이 네이버 전용 브라우저에서 처리해야 합니다.

라이브러리로 바꾼다면

현재 CDP 통신 구현은 256줄입니다. 라이브러리는 이 연결 코드를 줄일 수 있지만, 네이버 편집기의 전송 완료와 저장 전 대조는 여전히 필요합니다.

방식줄어드는 부분이 저장소에서의 판단
현재 Python CDP추가 패키지 없이 로그인된 Chrome에 직접 연결합니다.실제 임시저장까지 검증됐으므로 현재 운영 경로로 유지합니다.
Playwright PythonCDP 연결, 클릭과 파일 선택 코드를 라이브러리 API로 바꿀 수 있습니다.Python을 유지할 수 있어 첫 비교 대상입니다. 기존 Chrome에 CDP로 붙는 기능은 공식 문서가 일부 동작 제약을 안내합니다.
Puppeteer기존 Chrome에 연결해 브라우저 조작 코드를 줄일 수 있습니다.편집기 실행 코드 전체를 JS로 옮겨야 하므로 지금은 변경 범위가 큽니다.

자동화에서 까다로운 세 곳

화면발생했던 현상현재 확인 방식
사진올리는 동안 data: 미리보기와 원격 URL이 바뀌고, 화면 밖 사진은 늦게 로드됩니다.해당 사진을 화면으로 가져온 뒤 원격 URL, 로드 완료, 문서 너비 적용을 확인합니다.
스티커와 지도자리표시 글이 없어져도 실제 구성요소가 아직 없을 수 있습니다.스티커 코드와 네이버 지도 카드의 이름·주소를 편집기 구성요소에서 읽어 대조합니다.
설정 창열리는 동안 카테고리 버튼이 움직이고, 화면 표시용 innerText가 잠시 비었습니다.위치가 멈추고 클릭 지점이 드러난 뒤 누릅니다. 카테고리는 먼저 채워지는 textContent로 읽습니다.

맥북에서 빠르게 확인할 때

ego-lite 개인 용도 프로필의 글쓰기 화면을 엽니다

네이버 로그인 화면으로 이동하지 않고 제목 입력 영역이 보이면 세션과 편집기 접근은 정상입니다. 확인용 탭만 닫습니다. 이 점검은 사진 업로드나 임시저장을 실행하지 않습니다.

실제 임시저장 성공 여부는 홈서버의 단계 실행 결과와 네이버 임시저장 목록의 제목으로 확인합니다. 로컬 HTML 미리보기에서는 사진과 스티커 로드 여부를 함께 확인할 수 있습니다.
