# ADR-022 홈서버 공용 저장소는 S3 bucket으로 collection을 격리한다

- Status: Accepted
- Date: 2026-09-03

## 맥락

워크스페이스마다 홈서버 파일 저장 코드를 만들면 저장 경로, 접근 제어, 웹 조회와 백업 절차가 반복된다.
사용자는 `career-os`에 한정하지 않고 여러 개인 자동화가 같은 저장 서비스를 사용하되 데이터를 서로 섞지 않기를 원한다.
2026년 9월 기준 MinIO Community 저장소는 보관 상태이며 유지보수가 종료됐으므로 신규 오픈소스 배포 기준으로 삼기 어렵다.

## 결정

홈서버의 공용 저장 서비스로 SeaweedFS 단일 노드를 사용하고 S3 bucket 하나를 collection 하나로 취급한다.
SeaweedFS 배포와 실제 데이터 경로는 이 저장소 밖 홈서버 서비스가 관리한다.
이 저장소는 공통 연결 계약과 워크스페이스별 adapter만 관리한다.
각 워크스페이스는 자기 bucket의 객체 키와 데이터 의미만 관리하며 SeaweedFS 내부 데이터 디렉터리를 직접 읽지 않는다.
S3 API와 관리 UI는 로컬 주소에만 열고 외부 조회가 필요하면 인증된 private tunnel을 통한다.

## 기각한 대안

- MinIO Community는 S3 호환성과 UI가 좋지만 공식 저장소의 유지보수가 종료됐다.
- RustFS는 MinIO와 비슷한 관리 화면을 제공하지만 아직 정식 버전이 없어 첫 영구 저장소로 채택하지 않는다.
- Garage는 경량 분산 저장에 적합하지만 이번 요구에 필요한 내장 파일 탐색 화면이 없다.
- 공유 디렉터리만 제공하면 구현은 단순하지만 bucket별 접근 정책과 범용 S3 client 연결을 제공하지 못한다.

## 결과

새 collection은 별도 저장 프로그램을 추가하지 않고 bucket과 접근 정책으로 분리할 수 있다.
관리 UI는 객체 확인과 운영 상태 점검만 담당하며 워크스페이스별 이력 해석과 중복 거부는 각 도메인 코드가 계속 담당한다.
단일 노드 저장소는 백업을 대신하지 않으므로 원본 저장소 삭제는 별도 복구본을 검증한 뒤에만 수행한다.
SeaweedFS 실행 파일, compose와 데이터 볼륨은 이 저장소의 워크스페이스 구조에 포함하지 않는다.
